## 用户需求

参考《独立站店铺装修搭建器参考系统对比》和《独立站店铺装修可视化画布迁移》两份资料，设计一套可落地的独立站装修管理功能。

## Product Overview

在现有 `站点内容` 页面基础上升级内容编辑能力，不新增独立的店铺装修导航或页面。用户通过可视化画布组合装修区块，编辑区块属性、绑定站点商品、预览不同终端效果，并通过草稿、发布、下线和历史版本完成内容管理。

## Core Features

- 站点内容列表：按站点、栏目、内容类型和内容状态筛选，保留现有四态与历史版本语义。
- 可视化装修画布：采用区块库、画布、属性面板三栏布局，支持添加、删除、移动、嵌套、复制、排序和选中区块。
- 区块属性编辑：由字段定义驱动属性面板，支持默认值、字段校验、动态字段和区块级权限。
- 页面 Schema：以 JSON 区块树作为唯一真相源，保存草稿和发布版本，不将 HTML 作为持久化数据。
- 数据绑定：商品网格等区块引用站点商品主档，不复制商品价格和库存快照。
- 预览与多端适配：支持桌面、移动端视图切换，保留内容结构一致，允许终端差异化配置。
- 编辑辅助：支持撤销、重做、拖拽吸附、对齐辅助线、区块跳转链接和画布校验。
- 发布管理：支持保存草稿、预览、保存并发布、下线、重新发布、失败重试和发布结果反馈。
- 权限控制：复用成员与权限能力，区分查看、编辑、删除、发布和区块级操作权限。

## Tech Stack Selection

- 原型与页面实现：沿用项目现有 Node 原生 ESM、`.mjs` 页面模块和自包含 HTML 原型。
- 页面数据：沿用 `prototypes/site/data/site-content.json`，新增 `pageSchema` 与版本相关演示数据。
- 共享交互能力：复用 `prototypes/shared/ui.mjs` 的组件、样式令牌和交互约定。
- 数据模型：采用 Schema 驱动的 JSON 区块树；画布仅作为 Schema 的编辑与预览视图。
- 不引入 React、Puck、ReactFlow、tldraw 或新的构建链；只借鉴其数据模型、事务、吸附和字段驱动思想。
- 不直接持久化渲染后的 HTML/CSS，避免编辑态与发布态产生两套真相源。

## Implementation Approach

先保留 `site-content` 现有列表、筛选、四态、发布和历史版本能力，再将编辑抽屉升级为装修编辑态。编辑器通过 `pageSchema` 加载页面区块树，左侧区块库负责插入，中间画布负责结构预览，右侧属性面板负责字段编辑；所有操作先更新 Schema，再由渲染器刷新画布和预览。

页面级操作采用事务化历史记录，一次用户操作只产生一个撤销节点。动态数据解析按区块和触发原因去重，避免拖动或字段更新造成重复解析。区块树遍历和渲染复杂度控制在 O(n)，对大页面通过局部更新、事件委托和选中态局部刷新降低重绘成本。

发布前执行 Schema 完整性、区块字段、数据引用、链接目标、终端配置和权限校验；发布失败保留草稿，不改变已发布版本。所有危险动作必须二次确认，并明确下线、覆盖发布和丢弃修改的后果。

## Architecture Design

### 页面结构

`site-content` 列表页 → 内容编辑入口 → 装修编辑态 → 终端预览 → 发布确认 → 发布结果与版本记录。

### 编辑器组件关系

- **区块库**：展示可用区块模板，处理插入和替换。
- **画布**：根据 `pageSchema` 渲染区块树，处理选中、拖拽、排序、嵌套和辅助线。
- **属性面板**：根据区块定义的 `fields` 渲染控件，执行校验和字段更新。
- **预览层**：使用同一份 Schema 渲染桌面和移动端视图，编辑态增加选中标记，发布态隐藏编辑辅助层。
- **历史记录层**：记录事务前后的 Schema 快照或操作补丁，支持撤销与重做。
- **发布层**：复用现有站点内容四态、多端同步和历史版本语义。

### 状态与动作

| 状态 | 编辑 | 保存草稿 | 预览 | 发布 | 下线 | 重新发布 |
| --- | --- | --- | --- | --- | --- | --- |
| 草稿 | 可 | 可 | 可 | 可 | 不可 | 不可 |
| 待发布 | 可 | 可 | 可 | 可 | 不可 | 不可 |
| 已发布 | 可，修改后生成未发布变更 | 可 | 可 | 可 | 可 | 可 |
| 已下线 | 可 | 可 | 可 | 可 | 不可 | 可 |


发布、下线和重新发布必须校验权限与 Schema；发布请求重复提交时复用进行中的请求结果，失败时保留当前草稿并允许重试。

## Key Data Structures

- `pageSchema`：页面版本、根区块、区块实例、终端配置、区块链接和 Schema 版本。
- 区块实例：区块唯一标识、区块类型、显示属性、子区块、数据绑定和可见性配置。
- 区块定义：区块类型、显示名称、`fields`、`defaultProps`、渲染逻辑、嵌套能力和权限配置。
- 数据绑定：绑定类型、引用实体、筛选条件、排序规则和展示字段；商品区块引用 `site-sku` 主档。
- 版本记录：版本号、编辑人、发布时间、发布状态、Schema 快照和回滚来源。

## Implementation Notes

- 不修改 `modules.json` 新增导航段，避免重复建设。
- 先实现六类首期区块：轮播、图文、页面、商品网格、分类导航、优惠券。
- 区块字段必须能映射到数据字典，枚举、必填、默认值、校验和展示格式不得只存在于页面代码。
- 编辑态与发布态共用渲染模型，禁止通过编辑器临时 DOM 反向生成持久化数据。
- 商品绑定采用引用关系，不复制商品价格、库存等主档字段。
- 预览、保存、发布和下线均使用可恢复的错误反馈，不清空用户未保存内容。
- 日志只记录动作、状态、版本和错误原因，不记录完整 Schema、商品明细或敏感数据。
- 改动范围控制在 `site-content`、共享 UI、站点数据和必要的数据字典，不重构无关页面。

## 设计方向

采用面向运营人员的专业编辑器布局，复用项目既有双栏导航外壳；进入 `site-content` 编辑态后使用“区块库 + 画布 + 属性面板”的工作区结构。界面重点突出当前选中区块、未保存状态、预览设备和发布动作，不使用与电商店铺前台混淆的装饰性视觉。

### 编辑工作区

1. **顶部操作栏**：显示内容标题、保存状态、撤销、重做、设备切换、预览、保存草稿和发布。
2. **左侧区块库**：按基础内容、商品与营销、导航与容器分组，展示六类首期区块；点击或拖入画布后生成实例。
3. **中央画布**：按当前设备比例渲染页面，区块支持选中、拖动、排序、嵌套、复制和删除；拖动时显示插入位置与对齐辅助线。
4. **右侧属性面板**：按区块字段分组呈现内容、数据、样式、可见性和链接配置；错误字段就地提示。
5. **底部状态区**：显示 Schema 校验、数据绑定状态、当前版本和发布目标；失败时保留编辑现场。
6. **预览模式**：隐藏编辑边界和辅助线，保留桌面、移动端切换及返回编辑入口。
7. **危险操作确认**：下线、覆盖发布、删除区块和丢弃修改必须明确提示后果。

### 终端一致性

- PC 与移动端共享区块类型、内容字段、状态和发布语义。
- 通过响应式配置表达列数、间距、字号、图片裁切和可见性差异。
- 移动端不复制一套页面 Schema，只有确有业务必要时允许终端覆盖值。
- 预览切换保持当前选中区块、滚动位置和未保存数据。
- 桌面端提供完整编辑能力，移动端优先作为预览与校验场景，不在首期提供完整画布编辑。

## Agent Extensions

### Skill: huoling-proto

- **Purpose**：遵循项目原型规范，核对 `site-content` 的页面归属、共享 UI、数据引用、跨端联动和构建验收约束。
- **Expected outcome**：形成不新增导航段、兼容现有 `.mjs` 与共享层、可通过构建和交付验收的原型实施方案。

### Skill: ui-ux-pro-max

- **Purpose**：补充画布编辑器的交互模式、可用性、无障碍、响应式预览、空态和异常态设计。
- **Expected outcome**：输出可执行的编辑器交互规则和终端一致性验收标准，避免只描述视觉布局。

### Skill: design-system

- **Purpose**：将区块字段、状态、操作反馈和响应式配置整理为可复用的三层设计令牌与组件规范。
- **Expected outcome**：形成属性面板、状态标签、按钮、校验提示、预览容器和画布辅助线的统一规范。

### SubAgent: code-explorer

- **Purpose**：在正式实现前核对 `site-content`、共享 UI、站点数据、模块装配和现有权限字段的实际调用关系。
- **Expected outcome**：确认最终受影响文件、复用入口和跨端影响，减少凭路径修改与遗漏联动。
