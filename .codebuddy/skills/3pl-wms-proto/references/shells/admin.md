# 后台外壳视觉法（admin）

适用于 `shell = "admin"` 的三端：货主端、仓网管理端、单仓端。三端同壳同法，差异只在侧栏条目、页头页签内容、登录身份与货主端的两套演示数据。

## 1. 设计意图

工具型界面。使用者是每天开八小时的仓内作业与货主运营人员，判据是「一屏能读多少行、误操作有多少」，不是「第一眼多惊艳」。由此定四条取向：

- **密度优先**：留白服务于分组，不服务于呼吸感。
- **弱装饰**：边框与底色承担分区；阴影只给表格容器与浮层；不用渐变、插画、装饰图形、彩色大色块。
- **状态靠色型**：状态一律由 `StatusTag` / `Tag` 的 tone 表达，不靠图标、描边、字号加粗另造一套。
- **强调有预算**：一屏只允许一处主色强调（主按钮或当前页签），其余分层靠中性灰阶。

## 2. 基准

| 项 | 取值 |
| --- | --- |
| PC 设计基准 | 1440 × 900 |
| 内容区最小宽度 | 1080px；列放不下时横向滚动，不压缩列宽 |
| 顶栏 / 侧栏 / 页头 | 54 / 188（收起 64）/ 54px |
| 最小触控目标 | 44px（`--wx-touch`） |
| 字体 | 系统字体栈，不引外部字体文件 |

## 3. 骨架

```
.wx-app（height:100vh，overflow:hidden）
├ .wx-top（fixed，54px）：品牌（产品名 + 端名副标题） / 全局搜索 / 工具与用户
├ .wx-shell（margin-top 顶栏高度，height:calc(100vh - 顶栏高度)）
│   ├ .wx-side（fixed，188px，可收起 64px）：模块分组 + 本端页面 + 折叠按钮
│   └ .wx-main（margin-left 跟随侧栏）
│       ├ .wx-page-header（flex-shrink:0，钉住）：本模块页面页签 + 货主作用域
│       └ .wx-page-body（唯一滚动容器）：一屏一个 .page
└ .wx-toast / 抽屉与弹层挂 body 末尾
```

- 顶栏只放产品名、端名、全局搜索、工具与当前用户。不放部署形态、运营主体说明、「当前端：」这类装配元信息，也不放主体切换器。
- 侧栏按模块分组：一级 `data-nav` 只做展开 / 收起，不跳页；二级 `data-target` 直接切到本端页面。侧栏不列别的端页面，条目文案取 `pages[].name`。
- 页头页签按模块成组，只显示当前模块那组，是同模块内换页的入口；页面名逐字取 `pages[].name`。
- 页面归属只由注册表的 `pages[].app` 决定，不在页面名里加端前缀。
- 货主维度只用列表筛选：需要按货主收窄的页，在筛选区给一个「货主」下拉，取值域来自注册表 `owners`，首项「全部」。端不设顶栏货主下拉，页头右侧只放页签。货主端按登录身份限定数据范围，不摆货主筛选。
- 页头钉住靠布局层级：`.wx-app` 固定高度、`.wx-page-body` 是唯一滚动容器，不用 `position:sticky`。
- `.page` 默认 `display:none`，靠 `.page:not([hidden])` 显示。**任何写了 `display` 的组件都要补 `[hidden]{display:none}`**，否则 `display:flex` 会压过浏览器默认隐藏规则。
- 会话面板挂 `.wx-app` 之后，是弹层，不属于任何 `.page`，由共享外壳统一生成。登录层在这里是 `gate` 模式：登录前全屏覆盖，令牌到期或退出回到登录层。货主端登录层多一个「演示身份」选择，进入后锁定。

## 4. 页面类型

本外壳使用 `list` / `detail` / `report` 三类，**不出现** `scan`（归 PDA）与 `shop`（归商城）。类型由注册表 `pages[].type` 声明，判据是「这页属于哪一类」，不是「组件能不能用」。

| 类型 | 组件 | 结构 | 硬约束 |
| --- | --- | --- | --- |
| `list` | `ListPage` | 状态页签 → 筛选条 → 工具条 → 表格 → 分页 | 一页一张表；**不加** `StatRow`、`ReportHero`、页内大标题、自绘筛选栏 |
| `detail` | `DetailPage` | 抬头字段网格 → 明细表 → 操作轨迹 → 底部操作条 | 抬头字段只读；明细用 `BaseTable`；不套状态页签与分页 |
| `report` | `ReportHero` + `StatRow` + `Block` | 页头 → 指标卡 → 分节卡片 | 唯一允许摆 KPI 的类型；指标值由数据算，不写死数字 |

报表页用了 `ReportHero` 或 `Block` 即豁免列表页禁令；列表页用了 `ListPage` 就不得出现 `StatRow` / `PageHeader`。

### 4.1 列表页细则

- `statusTabs` 第一项是「全部」，不带 `field`；其余每项**必须**带 `field` + `value`，点了要真筛数据。行数据放在 `<tr data-row="转义后的行 JSON">` 里，脚本按 `row[field] === value` 比。
- 计数写 `statusTabs[].count` 或 `scopeNote`，不另做统计卡片。
- `filters` 由 `filters` 数组传，`type` 仅 `text` / `select` / `date` / `daterange`；`select` 的选项从行数据 `uniq()` 派生，不手抄枚举；`extra: true` 的收进「展开全部条件」。
- 数字列加 `align:'right'`，自动带 `tabular-nums`；列头口径说明用 `tipKey` 写进 `title`，**不许在 `<th>` 里塞按钮**。
- 全量 `<tr>` 都写进产物并带 `data-row-idx`，分页只做显隐，`unit` 随页面取（条 / 单 / 行 / 个 / 件）。
- 派生列写成纯函数，不往 `data/*.json` 里加展示字段，避免产生第二份真相。

## 5. 层级与节奏

- **三级层级**：页级（页签、工具条）→ 块级（表格容器、分区卡片标题）→ 行级（单元格、字段值）。每级只能靠「字号 + 字重 + 留白」三者中的一种拉开，混用两种以上会显脏。
- **表格**：`<th>` 只用中性灰底与弱化字色，不加重、不加彩色；主键列加粗；长文本列截断，横向溢出交给容器滚动。
- **留白**：只用 4 / 8 / 12 / 16 / 24 / 32 六档；同页同层级间距必须同档，不许 10、14、18 这类插值。
- **空态**：一页一处，标题说状态，一句说原因；空态里不放统计、不放引导流程、不放插画。
- **一屏一主体**：列表页的主体是表；报表页的主体是指标卡；详情页的主体是抬头 + 明细。主体之外不并列第二个视觉重心。

## 6. 强调色纪律

- 主色（`--wx-primary-*`）只给：主按钮、当前页签、进度条、链接、品牌标记。
- 状态色（success / warn / error / info）只出现在 `StatusTag` / `Tag` / `StatRow` 的 tone 上，不做背景块、不做描边、不做图标着色。
- 中性灰阶承担其余全部分层；一屏出现两种以上强调色即视为超预算。

## 7. 禁区

| 错误做法 | 正确做法 |
| --- | --- |
| 列表页顶部铺一排 KPI 卡、加大标题 | 计数进页签，标题交给侧栏与页签 |
| 自绘筛选栏、把筛选塞进页头 | 用 `ListPage` 的 `filters`，收不住的进「展开全部条件」 |
| 给表格加斑马纹、彩色表头、行悬浮变色成主色 | 中性灰底 + 边框分区；hover 只做底色微调 |
| 用渐变、插画、装饰性图标填补空白 | 空白靠留白与分组解决 |
| 顶栏放部署形态、主体切换器、套餐条 | 单实例单主体，顶栏只放产品名、端名、搜索、工具、用户 |
| 只在字号上做层级，字重与留白齐平 | 三件套至少用两种，见第 5 节 |
| 键盘 Tab 看不到焦点 | 见 `references/implementation.md` 的焦点规则（当前待补齐） |
