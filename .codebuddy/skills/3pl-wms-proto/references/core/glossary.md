# 文案权威源

本文件是 [SKILL.md](../../SKILL.md) 第 2 步「查权威源」的第 2 项，**3PL 云仓原型所有可见文字的唯一出处**。页面上的字，要么在本文件里，要么先登记再写。

## 1. 使用规则

- 端名、模块名、页面名、页签、列名、按钮文案、状态中文名、空态文案、分页单位，逐字取用，含空格与全半角。
- 字段名（JSON 的 key）与显示文案（列 `label`）分开：字段名用小写驼峰，显示文案取本文件。
- 列定义 `tipKey` 写口径说明，但说明本身也是文案，取本文件第 5 节的口径句，不自撰。
- 演示数据里的值也受约束：状态值、优先级、单位取本文件的枚举，不写 `test` / `demo` / `示例数据`。
- 本文件只收「会出现在界面上的字」。实现说明、设计理由、迭代计划一律不进本文件，也不进页面。
- **只放读数，不放读法**：页面只显示数据本身；指标定义、口径边界、设计理由收进 `tipKey` / `title` / `data-tip`。判据一句话：这句话是数据，还是对数据的解释？
- **禁过程文字**：实现注解、设计说明、`TODO`、`lorem`、占位符、「本期不做」「后续迭代」「示意代码」都不许出现。不做真实动作的按钮挂 `data-toast` 给结果提示，不写「暂不支持」。
- **表头是纯文本列**：`<th>` 里不拼按钮、图标或 HTML，标签会被转义成源码。
- 空态、分页单位、日期格式统一按第 5 节，不各页各写一份。

## 6. 新增文案登记流程

1. 在本文件对应表格追加一行，给出值、中文名、色型或列宽口径。
2. 若涉及新端、新模块或新页面，同步 [registry.md](../registry.md) 第 2、4 节与 `prototypes/shared/modules.json`。
3. 若涉及新状态色型或新组件取值，先改 [implementation.md](../implementation.md) 第 3 节与 `prototypes/shared/ui.mjs`。
4. 再改页面模块并重建所有端产物。

顺序不能反：**先有文案，再画页面**。

商城端允许多货主店铺、店铺评分与入驻入口：供货方是本部署内的货主，店铺是业务展示维度，不是独立租户，商城卖的也是货主的货。入驻指货主在本部署内开通店铺，不写订阅、套餐、充值、续费、试用到期、升级专业版，不画平台运营后台与主体切换器。上表一个词都不放宽：多店铺是业务维度，不是架构分层。
