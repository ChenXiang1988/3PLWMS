# 逐节判据

填每一节前读对应小节。每节四段：写什么、不写什么、合格线、常见错误（含改法）。文末是八节自检清单。

每节写完后按 `chart-guide.md` 第 2 节判断该配什么图、第 8 节对号入座；能画就在本节内直接画，文字只留判断、来源与口径，不另起图表附录。结构从 `chart-snippets.md` 取，不自己发明画法。

## 0. 封面与元信息

**写什么**：报告标题、日期、状态、版本、作者、报告对象、一句话结论；`<head>` 里的 `topic`、`survey-window`、`survey-objects` 三个 meta。

**不写什么**：致谢、目录（侧栏自动生成）、「如有疑问请联系」、封面插图。

**合格线**：六项齐全；一句话结论是判断句，含方向，能被单独摘出来引用而不失真；三个 meta 与文件名、封面对应。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 一句话结论：本文对 A 与 B 进行了深入调研 | 没有判断，读完不知道结论 | 中台缺计费闭环，bms 四段链可补 5 页 |
| 日期：今天 | 无法复核时效 | 2026-11-08 |
| 状态：完成 | 「完成」不是状态枚举 | 草案 / 评审中 / 已定稿 |
| meta 的 window 写成「11-08 上午」 | 脚本无法判定窗口是否超过 24 小时 | 2026-11-08T09:20 / 2026-11-08T18:40 |

## 1. 口径与证据

**写什么**：对象表（对象 / 简称 / 访问时刻 / 账号条件 / 覆盖端 / 证据级范围 / 未验证项）、A/B/C 证据级别定义、未执行写操作的声明。

**不写什么**：「据了解」「业内普遍」；把同一对象的多次访问拆成多行；用 C 级推断冒充实见。

**合格线**：每个对象都有精确到分钟的访问时刻；未验证项写到具体页面或字段；只读声明必须有。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 访问日期：2026-11 | 无法判断是否在 24 小时窗口内 | 2026-11-08 09:20 ~ 18:40 |
| 账号条件：正常 | 不知道是否有数据、能否操作 | 未授权任何店铺，订单与库存为空，未执行写操作 |
| 证据级别：A | 全篇都标 A，等于没分 | A 级只给实见页面与字段，源码原文记 B，搜索摘要记 C |
| 未验证项：部分功能 | 无法核对 | 促销价与会员价两块未开通，未验证 |

## 2. 覆盖清单

**写什么**：菜单树全量（一级 › 二级 › 三级）、一行一页的逐页覆盖表（菜单路径 / 页面类型 / 角色 / 状态 / 记录节号）、非页面能力（规则引擎、导入导出、批量工具、通知、定时任务、开放接口、权限点）、覆盖端与角色差异、未覆盖项。

**不写什么**：功能简介；把「有这个功能」当成覆盖；只列菜单名不给状态。

**合格线**：覆盖表里每个「已看」都能在第 3 节找到对应小节号；未覆盖项给了原因；覆盖端与角色差异分别记。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 覆盖了订单模块 | 不知道看了哪几页 | 订单模块 14 页中逐页看 6 页，其余见缺项 |
| 未看：没时间 | 不可复核 | 未看：计费规则需企业版授权，账号无权限 |
| 只记管理员视角 | 受限角色菜单与按钮常不同 | 管理员与仓库主管各记一套可见动作 |

## 3. 逐页记录

**写什么**：一页一节，节标题写 `对象 › 菜单路径`；节内依次记入口（页面类型、进入条件、可跳转去向）、结构分区、列表列与筛选、行与批量操作（动作名、可用条件、二次确认）、状态 × 动作矩阵、交互与异常（空态、失败、部分失败、重复提交）。

**不写什么**：大段原文摘录；把没点到的写成默认行为；把两页合并成一段。

**合格线**：状态 × 动作矩阵能直接判定每个动作是否可执行；每个「未验证」都写了为什么；同一对象的不同页用同一套记录顺序。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 列表支持筛选和导出 | 不知道筛什么、导什么 | 筛选含状态、货主、创建时间区间；导出当前筛选结果为 xlsx |
| 状态：正常 / 异常 | 不是原生枚举 | 待处理 / 拣货中 / 已复核 / 已发货 / 已取消 |
| 动作都可点 | 没有条件 | 批量取消仅在「待处理」可用，已发货不可取消 |

## 4. 术语对照

**写什么**：对象 / 原生叫法 / 该对象下的判定口径 / 我方叫法，四列；同名不同义分行。

**不写什么**：只列词不写差异；把竞品词直接搬进我方叫法；把同一对象的近义词凑数。

**合格线**：读者看完不会把两个对象的同名状态混为一谈；我方叫法能在项目术语表里找到。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 待处理 = 待处理 | 没有对照价值 | 甲系统「待处理」含未付款；我方「待处理」不含，未付款单在「待确认」 |
| 组合 SKU / 组套 | 两个词混用 | 原生「组合 SKU」对应我方「组套商品」，差异在拆解时机 |

## 5. 横向对比

**写什么**：行是对象、列是能力维度，格填 有 / 无 / 未验证；矩阵后写差异原因（为什么一方有另一方没有）。

**不写什么**：把「有这功能」当差异；差异不指到页面或字段；单对象时留空本节。

**合格线**：每个「有」都能回指第 3 节的记录；「未验证」进第 7 节；单对象时写「本轮单对象，无横向对比」。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| A 更强，B 较弱 | 没有维度也没有依据 | 计费链路：A 覆盖规则→账单→结算四段，B 只有规则与账单两段 |
| 表格里填「部分」 | 三值之外无法判定 | 拆成两行，分别填 有 / 无 |

## 6. 结论与落点

**写什么**：结论表（编号 / 判定 / 结论 / 落点），判定只用 可借鉴 / 不跟随 / 待定；落点写到端、模块、页面 key、字段或决策人；建议表（编号 / 动作 / 前置 / 判据）。

**不写什么**：「建议加强协同」「持续优化」；把发现换个说法当结论；落点写「相关模块」。

**合格线**：每条结论能被反驳；每条建议能被验收；待定项写清卡在谁那里、定了影响哪几页。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 建议补齐仓储能力 | 无法验收 | 补 3 页：库位图、波次下发、装车复核，落 `wms/warehouse` 模块 |
| 落点：订单相关页面 | 落不到具体位置 | `erp-app` 的 `order-center`，字段 `fulfillmentType` |
| 待定 | 没写卡点 | 待定：计费对象是货主还是合同需财务确认，定了影响 2 页 |

## 7. 缺项

**写什么**：一行一项，给原因（无权限 / 需付费 / 入口未找到 / 材料不存在）与影响（影响哪条结论）。

**不写什么**：「部分内容未覆盖」这类无法核对的话；把正文该说的塞进本节的。

**合格线**：每条缺项都说清为什么拿不到、影响哪条结论；确实没有缺项时写一句「本轮无缺项」。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 部分页面未看 | 不知道是哪些、为什么 | 3 页未看：付费墙后 2 页、无入口 1 页，影响 C2 的落点判断 |

## 8. 截图索引

**写什么**：一行一张图，图号 / 文件 / 对象 / 菜单路径 / 证明什么 / 数据状态；正文用相对路径 `<img>` 引用，图注写图号、菜单路径、拍摄时刻、证明什么。

**不写什么**：内联 base64；引外部链接；拍付费墙后、越权页与他人数据；用第三方文章配图充 A 级。

**合格线**：正文每个 `<img src>` 都能在本表找到对应行；图片路径真实存在；缺图写「无截图：原因」并把证据级降到 B/C。

**常见错误**

| 错误写法 | 问题 | 改法 |
| --- | --- | --- |
| 图 1：订单页 | 不知道证明什么 | 简称-01 ｜ 订单 › 订单处理 ｜ 证明：默认列与状态页签计数 |
| 截图缩放后贴进报告 | 字段看不清，等于没证据 | 整窗、宽度 ≥1440、不缩放 |
| 缺图不写 | 读者以为没有这块 | 无截图：账号无权限，字段口径来自帮助中心 B 级 |
