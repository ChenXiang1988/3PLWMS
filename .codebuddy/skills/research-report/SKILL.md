# 调研报告产出

## 目标

把散落的调研材料压成一份能被人直接拿去决策的报告：八节固定、每条结论有来源、每个建议有落点和判据。解决的问题是报告结构各写一套、结论落不了地、评审时无法判断哪句有依据。

## 适用场景

| 会触发的情况 | 典型话术 |
| --- | --- |
| 调研结论要成文 | 「把这次调研整理成报告」「写一份对标分析」 |
| 竞品 / 参考系统对标 | 「对比 A 与 B，给结论」「参考系统调研报告」 |
| 技术选型 | 「三个方案选一个，出报告」 |
| 项目复盘 | 「这次上线复盘写成文档」 |
| 报告整改 | 「这份报告太空」「结论没法验收」 |

## 不做什么

- **不采集材料**。怎么访谈、怎么翻源码、看到什么颗粒度，由调研环节或项目调研规则负责。本 skill 从「材料已经在手上」开始。
- **不定义字段颗粒度**。字段表列几列、证据分几级，随调研对象定；本 skill 只要求报告把已有证据标清楚。
- **不替代项目规则**。项目若有自己的存放位置、时效、截图与索引登记要求，以项目规则为准。

## 五步流程

1. **取模板**：把 `assets/report-template.html` 复制到目标路径，改文件名与 `<title>`。
2. **逐节填**：填到某一节前先读 `references/chapter-guide.md` 对应小节，按「写什么 / 不写什么 / 合格线」写。
3. **清指引**：删掉全部 `<!-- GUIDE ... -->` 注释块与 `{{占位符}}`，解除截图位注释。
4. **跑校验**：`node .codebuddy/skills/research-report/scripts/check-report.mjs <报告.html>`，有错加 `--fix` 取补齐建议。
5. **自查交付**：对照 `references/example-good.md` 的厚度，不合规处参照 `references/example-bad.md` 的点评改。

## 八节骨架

| 序号 | 节 | 写什么 |
| --- | --- | --- |
| 1 | 口径与证据 | 对象表（对象 / 简称 / 访问时刻 / 账号条件 / 覆盖端 / 证据级 / 未验证项）、证据级别定义、未执行写操作声明 |
| 2 | 覆盖清单 | 菜单树、逐页覆盖表、非页面能力、覆盖端与角色、未覆盖项 |
| 3 | 逐页记录 | 一页一节，节标题写 `对象 › 菜单路径`，记录段见 `references/chapter-guide.md` 第 3 节 |
| 4 | 术语对照 | 对象 / 原生叫法 / 该对象下的判定口径 / 我方叫法，同名项分行 |
| 5 | 横向对比 | 行是对象、列是能力维度，格填 有 / 无 / 未验证，矩阵后写差异原因；单对象写「本轮单对象，无横向对比」 |
| 6 | 结论与落点 | 每条结论标 可借鉴 / 不跟随 / 待定，落到端 / 模块 / 页面 key / 字段 |
| 7 | 缺项 | 缺哪些、为什么缺、影响哪条结论 |
| 8 | 截图索引 | 图号 / 文件 / 对象 / 菜单路径 / 证明什么 / 数据状态 |

## 硬规则

1. **先数据后判断**：每节先给事实、数字、原文或路径，再给判断。只剩判断没有来源的，降级为「待定」。
2. **结论三选一**：每条结论只能标 `可借鉴` / `不跟随` / `待定`，并写明落点。「建议加强协同」这类无法验收的表述不算结论。
3. **来源可复核**：口径与证据里每个对象给访问时刻与证据级别；拿不到地址的写「未验证」，不写「据了解」「业内普遍」。
4. **不写空话**：禁用「综上所述」「具有重要意义」「为后续奠定基础」「赋能」「抓手」「全面提升」。句子要能被追问「依据是哪个」。
5. **过脚本才算完**：`check-report.mjs` 退出码为 0 才可交付；警告项要么改掉，要么在「缺项」里写明为什么不改。

## 资源索引

| 文件 | 内容 | 什么时候读 |
| --- | --- | --- |
| `assets/report-template.html` | 八节骨架，含三个 head meta、封面对象表、截图位、填写指引与占位符；样式内联、可打印 | 开工第一步，复制出去用 |

| `references/example-good.md` | 正面范例：真实参考系统调研，含来源表、数据表、带落点的结论 | 不确定某节该写多厚时 |
| `references/example-bad.md` | 反面示例：结构混乱、论据不足、结论空泛、来源不明，附四列点评 | 报告被打回、或自查时 |

范例文件是 Markdown 摘要，只用来判断厚度与论据写法；实际交付一律用 HTML 模板。

## 报告厚度参考

| 报告类型 | 核心发现 | 结论条数 | 适用 |
| --- | --- | --- | --- |
| 轻量调研 | 1~2 节，含 1 张表 | 3~5 条 | 单点问题、当天可结论 |
| 标准调研 | 3~5 节，含 2~3 张表 | 6~12 条 | 参考系统对标、选型 |
| 深度调研 | 5 节以上，含数据表与逐项记录 | 12 条以上 | 多系统横向对比、影响面大 |

低于轻量的，不写报告，写一页备忘录；超过深度的，按主题拆成多份，别堆成一份读不完的文件。
