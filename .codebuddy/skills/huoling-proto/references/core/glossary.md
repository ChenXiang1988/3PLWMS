# 文案权威源

本文件是 [SKILL.md](../../SKILL.md) 第 2 步「查权威源」的第 2 项，**货灵供应链运营平台原型所有可见文字的唯一出处**。页面上的字，要么在本文件里，要么先登记再写。

## 1. 使用规则

文案取舍的权威在工作区「界面文案纪律」规则；本节只给落地判据，冲突以规则为准。

- 端名、模块名、页面名、页签、列名、按钮文案、状态中文名、空态文案、分页单位，逐字取用，含空格与全半角。
- 字段名（JSON 的 key）与显示文案（列 `label`）分开：字段名用小写驼峰，显示文案取本文件。
- 列定义 `tipKey` 写口径说明，但说明本身也是文案，取本文件第 5 节的口径句，不自撰。
- 演示数据里的值也受约束：状态值、优先级、单位取本文件的枚举，不写 `test` / `demo` / `示例数据`。
- 本文件只收「会出现在界面上的字」。实现说明、设计理由、迭代计划一律不进本文件，也不进页面。
- **只放读数，不放读法**：页面只显示数据本身；指标定义、口径边界、设计理由收进 `tipKey` / `title` / `data-tip`。判据一句话：这句话是数据，还是对数据的解释？
- **辅助文案可删尽删**：不加 slogan、页面副标题、区块引导句、字段旁常显提示、按钮补注。判据：删掉这句，布局、层级、主操作还能读懂吗？能就删。必须保留的补充信息走 info 图标 + hover 提示（当前落到 `tipKey` / `title`，载体缺口见 [implementation.md](../implementation.md) 2.1），不做常显；PDA 端无 hover，只能删减或并入主标签。
- **禁过程文字**：实现注解、设计说明、`TODO`、`lorem`、占位符、「本期不做」「后续迭代」「示意代码」都不许出现。不做真实动作的按钮挂 `data-toast` 给结果提示，不写「暂不支持」。
- **删减不删可访问名称**：表单控件保留可见标签且与控件关联（`FormField` 的 `label` 必填，控件被 `label` 包裹），纯图标按钮给 `aria-label`。不用 `placeholder` 顶替标签，不因版面清爽删掉列头文本、按钮文本或语义标签。
- **危险动作留后果提示**：删除、支付、提交永久性变更这类动作，必须在动作旁或同层写清「做什么、影响什么、能否撤销」，用 `FormDrawer` 的 `note`、`ListPage` 的 `scopeNote` 或按钮文案承载。这是必留文字，不按辅助文案删。
- **先删后调版**：重写已有界面先删冗余标签与说明，清晰度下降再改布局与按钮文案，仍不够才补 info 图标 + hover 提示，不先写说明补丁。删减后过三问：下一步点哪里、点了会发生什么、出错怎么回退；答不上就是删过头，先改结构不改文案。
- **表头是纯文本列**：`<th>` 里不拼按钮、图标或 HTML，标签会被转义成源码。
- 空态、分页单位、日期格式统一按第 5 节，不各页各写一份。

### 商城 `mall`

货灵商城展示本部署货主开设的店铺与在仓现货，采购方下单后由出库订单履约。六页都走 `shop` 骨架。

同一个货主在商城有两个业务角色：店主经营本货主的店铺、卖本货主的货；买家在别人的店铺下单、买别人的货。两个角色属于同一套部署内的同一主体，不是两套账号体系，也不是切换主体。店主侧自助维护页归货灵ERP，买家侧六页仍归货灵商城；运营审核与全局视图归货灵运营中台管理端。角色口径见 `docs/产品需求/商城双身份设计方案.md`，店主侧页面名为拟名，确认后才登记进本文件。

| key | 页面名 | 类型 | 主要内容 |
| --- | --- | --- | --- |
| `home` | 商城首页 | shop | 类目导航、货源楼层、店铺推荐 |
| `search` | 商品搜索 | shop | 搜索条、类目与货主筛选、商品卡片 |
| `product-detail` | 商品详情 | shop | 商品信息、货主店铺、阶梯价、批次效期、加购 |
| `cart` | 进货单 | shop | 商品、单价、起批量、数量、小计、合计 |
| `checkout` | 确认订单 | shop | 收货信息、商品清单、金额合计、提交 |
| `orders` | 我的订单 | shop | 订单编号、下单时间、订单状态、金额、履约单号 |

### 商城店铺 `mall-shop`

店主侧独立一级菜单，模块名即菜单名「商城店铺」。一个货主当前只能开一个店铺，不做店铺列表与切换。

| key | 页面名 | 类型 | 主要内容 |
| --- | --- | --- | --- |
| `my-shop` | 我的店铺 | report | 单店铺信息；未开通时显示招商页与申请开店 |
| `shop-sku` | 店铺商品 | list | 商品编码、商品名称、商品类目、在售状态、在仓现货、上架时间 |
| `shop-price` | 店铺价格 | list | 商品编码、商品名称、单价、阶梯价、访客可见、登录可见 |
| `shop-order` | 店铺订单 | list | 订单编号、买家货主、订单金额、履约出库单号、订单状态、下单时间 |
| `shop-cert` | 企业资质认证 | list | 认证单号、货主、企业名称、统一社会信用代码、营业执照、认证状态、提交时间、审核人、审核时间、审批意见；单行认证单 + 表单抽屉 |

### 独立站 `site`

货主侧统一管理本人名下多个独立站，与货灵商城「商城店铺」并列，互不复用。一个货主可建多个站点，每个站点选一种类型：品牌站或采销站。站点归属登录货主，货灵ERP不设货主下拉与货主筛选。

| key | 页面名 | 类型 | 主要列名 |
| --- | --- | --- | --- |
| `site-overview` | 独立站总览 | report | 站点数、营业中、今日访客、待发布端 |
| `site-list` | 独立站列表 | list | 站点名称、站点类型、主域名、承载端、站点状态、商品数、订单数、更新时间、操作 |
| `site-config` | 站点配置 | list | 站点、配置项、当前值、生效范围、更新时间、操作 |
| `site-domain` | 域名与证书 | list | 域名、绑定站点、绑定端、解析状态、证书状态、到期时间、操作 |
| `site-content` | 站点内容 | list | 内容标题、所属站点、栏目、内容类型、内容状态、发布人、发布时间、操作 |
| `site-sku` | 站点商品 | list | 商品编码、商品名称、所属站点、售价、可售库存、上架状态、更新时间、操作 |
| `site-order` | 站点订单 | list | 订单编号、站点、买家、订单金额、支付状态、履约状态、下单时间、操作 |
| `site-channel` | 多端发布 | list | 站点、端、发布版本、发布状态、功能覆盖、同步状态、最近同步、操作 |
| `site-member` | 成员与权限 | list | 成员、账号、角色、数据范围、成员状态、最近登录、操作 |

| `sf-m-home` | 站点首页 | shop | 纵向品牌首屏、两列商品、门店入口 |
| `sf-m-products` | 站点商品 | shop | 两列商品卡、公开零售价 |

## 6. 新增文案登记流程

1. 在本文件对应表格追加一行，给出值、中文名、色型或列宽口径。
2. 若涉及新端、新模块或新页面，同步 [registry.md](../registry.md) 第 2、4 节与 `prototypes/shared/modules.json`。
3. 若涉及新状态色型或新组件取值，先改 [implementation.md](../implementation.md) 第 3 节与 `prototypes/shared/ui.mjs`。
4. 再改页面模块并重建所有端产物。

顺序不能反：**先有文案，再画页面**。

## 7. 禁语表

下列文字不得出现在页面或产物中（验收脚本 S5 / 构建期 `[文案]` 与 `[非SaaS]` 会拦）：

| 类别 | 词 |
| --- | --- |
| 过程文字 | `TODO`、`lorem`、占位符、`示意代码`、实现说明、设计注解、操作指引 |
| 迭代话术 | 本期不做、后续迭代、暂不支持、待开发 |
| SaaS 红线 | 租户、账号空间、按租户分库、订阅、套餐、充值、续费、试用到期、升级专业版、平台运营后台、主体切换器 |

货灵商城允许多货主店铺、店铺评分与入驻入口：供货方是本部署内的货主，店铺是业务展示维度，不是独立租户，商城卖的也是货主的货。入驻指货主在本部署内开通店铺，不写订阅、套餐、充值、续费、试用到期、升级专业版，不画平台运营后台与主体切换器。上表一个词都不放宽：多店铺是业务维度，不是架构分层。

### 8.5 口径句（`tipKey` / `title`）

| 口径 | 文案 |
| --- | --- |
| 库存六段 | 按安全库存、在途、未发占用、已占用、可用与总量分别统计 |

| 质检合格率 | 合格数除以验收数量 |
| 盘点差异 | 实盘数减账面数 |
| 履约风险 | 按最晚发货时间与当前时间比对 |
| 商品生命周期 | 按近 30 天销量与上架时间派生 |
