# 入库计划单（数据字典）

> 实体：入库计划单｜对应原型页面：货灵ERP「入库计划单」、货灵运营中台管理端「入库计划单确认」
> 字段名（key）用小写驼峰；中文显示名按 货灵供应链运营平台习惯。
> 本文件是字段真值源；原型列名与取值逐字取自本文件，并在 `glossary.md` 登记。

约定：必填 是＝创建时不可为空；枚举在原型以下拉呈现，首项「全部」。
入库计划单是货主对一批入库货的预约，**一票一仓**。确认生效后按目标仓分发到单仓，形成沿用同一 `planNo` 的执行单，仓库据此执行收货与上架；委托层与单仓执行层字段分表，执行层见 [入库通知单.md](入库通知单.md)。

## 1. 基础标识

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `planNo` | 计划单号 | String | 24 | 是 | 全局唯一，业务引用主键 | `IP` + 日期 + 4 位流水；不可改 |
| `bizType` | 入库类型 | Enum | — | 是 | 采购入库 / 调拨入库 / 退货入库 / 加工入库 / 售后入库 | 决定默认工序编排；售后入库只由售后申请单生成 |
| `ownerName` | 货主 | String | 100 | 是 | 关联货主主档 `ownerName` | |
| `targetWarehouse` | 目标仓库 | String | 20 | 是 | 关联仓库主档 `warehouseCode` | 一票一仓，定在单头；提交后不可改，改仓只能驳回重提 |
| `planStatus` | 计划单状态 | Enum | — | 是 | 草稿 / 待确认 / 已生效 / 已分发 / 已关闭 | 见状态枚举 |
| `confirmMode` | 确认方式 | Enum | — | 是 | 自动确认 / 人工确认 | 自动确认时提交即生效 |
| `sourceDocType` | 来源单据类型 | Enum | — | 否 | 采购单 / 调拨单 / 退货单 / 加工单 / 售后申请单 / 平台售后单 | 外部下发或逆向生成时填写 |
| `sourceDocNo` | 来源单号 | String | 40 | 否 | 上游单据号 | 与 `sourceDocType` 成对出现；售后入库填售后申请单号或平台售后单号 |

### 状态枚举

| 值 | 中文 | 建议色型 tone |
| --- | --- | --- |
| `draft` | 草稿 | `disabled` |
| `pending` | 待确认 | `pending` |
| `confirmed` | 已生效 | `enabled` |
| `dispatched` | 已分发 | `info` |
| `closed` | 已关闭 | `disabled` |

## 2. 计划与分发

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |

| `expectedDate` | 计划到货日期 | Date | — | 是 | 货主期望到仓日期 | 列表列 |
| `skuCount` | 品类数 | Int | — | 是 | 明细行去重商品数 | 由明细派生 |
| `planQty` | 计划数量 | Int | — | 是 | 明细计划数量之和 | 列表列 |
| `processCount` | 已生成工序单 | Int | — | 否 | 本票在仓内已生成的工序单数，初始 0 | 由工序单派生，货灵ERP不展示 |
| `confirmTime` | 确认时间 | Datetime | — | 否 | 确认生效时刻 | 自动确认由系统写入 |

## 3. 明细行

一张计划单至少一行。行上不带目标仓：一票一仓，仓定在单头。

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `lineNo` | 行号 | Int | — | 是 | 单内唯一，从 1 开始 | |
| `skuCode` | 商品编码 | String | 20 | 是 | 关联商品主档 `skuCode` | 只允许本单货主商品 |
| `skuName` | 商品名称 | String | 200 | 是 | 取商品主档 | 展示用 |
| `batchNo` | 批次号 | String | 40 | 否 | 按商品主档批次编码规则生成 | 效期或批次管理商品填 |
| `planQty` | 计划数量 | Int | — | 是 | 行级计划数量 | |

## 4. 与其它主档的关系

- 货主主档：`ownerName` 外键，计划单归属货主。
- 商品主档：`skuCode` 外键，批次与效期策略取主档。
- 仓库主档：`targetWarehouse` 单头外键；确认前按该仓校验能力——商品牌要求质检而该仓 `qcMode=无` 时阻断，温区不含该商品温区时阻断，增值作业不在 `valueAddedServices` 内时提示改仓。校验不通过则不能确认。
- 工序单：确认推送后由单仓基于本票生成收货单、上架单等工序单，计划单与工序单 1:N；工序单回写 `sourcePlans`，计划单派生 `processCount`。计划单本身不在仓内被改写，已收与上架进度从工序单汇总。
- 时效协议：生成通知单时按「仓 × 货主 × 入库」取当刻生效的协议，快照 `slaCode`、`slaDueTime`、`slaStatus`。
- 库存台账：计划单不写账，账在通知单收货上架后产生。
- 售后申请单：`bizType=售后入库` 时 `sourceDocType` 固定为售后申请单、`sourceDocNo` 取售后单号，由系统按原出库行生成，货主不能手工新建；`targetWarehouse` 取原出库计划单的发货仓且不可改，行数量按原出库行可退量校验，累计不得超退；原商城订单与原出库单不因退货改写状态。
- 平台售后单：平台售后的仓发货退货同样落 `bizType=售后入库`，`sourceDocType=平台售后单`、`sourceDocNo=afterSaleNo`；固定原发货仓，处置结果回写平台售后单 `disposalResult`，原平台订单与原履约单不改写状态。
- 退货申请单：`bizType=退货入库` 时 `sourceDocNo` 取退货单号，退仓仓库取原发货仓或协议指定退货仓，验收结果回写退货申请单 `receivedQty` 与冲正流水号。

## 5. 原型衔接建议

- `inbound/plan-owner-list`（货灵ERP，list）：计划单号、计划单状态、入库类型、目标仓库、计划到货日期、品类数、计划数量、创建时间。
- 状态页签：全部 / 草稿 / 待确认 / 已生效 / 已分发 / 已关闭；筛选：入库类型、目标仓库、计划到货日期。
- `inbound/plan-confirm-list`（货灵运营中台管理端，list）：计划单号、货主、入库类型、目标仓库、计划到货日期、品类数、计划数量、计划单状态、确认方式、确认时间。
- 工具条：确认、驳回、查看执行单、导出。改仓只在待确认态可做，确认后执行单已生成，不再允许改仓。
