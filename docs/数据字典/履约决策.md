# 履约决策（数据字典）

> 实体：履约决策｜对应原型页面：货灵ERP「订单中心」的 360 抽屉｜字段真值源

约定：履约决策是一次发货选择的事件记录，不是第四种执行单据。它记录「为什么这样发、拆成几张履约单、承诺何时发」，执行仍由履约单、出库计划单、自发货单、平台备货单承载。决策只追加，不改写历史；改派仓或承运商追加新决策。

## 1. 决策标识

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `decisionNo` | 决策编号 | String | 24 | 是 | 全局唯一 | `FD` + 日期 + 4 位流水 |
| `orderNo` | 订单编号 | String | 24 | 是 | 关联平台订单/订单中心 | 一次订单可多次决策 |
| `fulfillmentNo` | 履约单号 | String | 24 | 否 | 关联履约单 | 一次决策可生成多张 |
| `fulfillMode` | 履约方式 | Enum | 20 | 是 | 仓发货 / 自发货 / 平台备货 | 决定执行单类型 |
| `targetWarehouse` | 目标仓库 | String | 40 | 否 | 仓发货必填 | 关联仓库主档 |
| `carrierName` | 承运商 | String | 40 | 否 | 仓发货/自发货填写 | 关联承运商主档 |
| `promiseShipTime` | 承诺发货时间 | Datetime | — | 是 | 平台要求或货主承诺 | 用于承诺时钟 |
| `splitReason` | 拆分原因 | String | 300 | 否 | 多履约单时必填 | 如库存不足、多包裹、多仓 |
| `ruleVersion` | 规则版本 | String | 20 | 否 | 自动决策时写入 | 人工决策为空 |
| `decisionBy` | 决策人 | String | 30 | 是 | 取登录账号 | 操作日志 |
| `decisionTime` | 决策时间 | Datetime | — | 是 | 系统写入 | 只追加 |

## 2. 规则与关系

- **平台订单**：一个订单可有多条决策；决策不改写平台订单状态，只写履约状态。
- **履约单**：决策与履约单是一对多；部分发货、补发、多包裹各自一张履约单。
- **ATP**：决策前做 ATP 检查；缺口时拆单、改仓或转异常，缺口原因写进 `splitReason`。
- **操作日志**：决策、改派仓、改派承运商、取消决策都写日志；已下发后改派标记异常。
- **状态**：决策本身不设状态；是否执行看履约单状态。取消决策追加一条反向记录，不物理删除。

## 3. 原型衔接建议

- `owner/order-center`（list）：行操作「处理」打开决策表单；「360」打开只读抽屉。
- 360 的「履约决策」块展示最近一条决策，历史决策进时间线。
- 表单字段：履约方式、目标仓库、承运商、承诺发货时间、拆分原因；规则版本与决策人/时间只读。
- 保存后只改列表状态与行字段，不回写已打开的 360 面板；跨页状态不联动。
