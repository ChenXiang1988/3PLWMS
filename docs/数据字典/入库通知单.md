# 入库通知单（数据字典）

> **单仓执行层**：本文描述 L0 入库计划单确认生效、分发到目标仓后形成的执行单。货灵WMS沿用计划单号 `planNo`，不再另开 `ASN` 号；L0 委托层字段见 [入库计划单.md](入库计划单.md)，收货、上架等作业单据见 [工序单.md](工序单.md)。

> 实体：入库通知单｜对应原型页面：入库管理 / 入库计划单及其行详情抽屉（`inbound` 模块，货灵WMS）
> 字段名（key）用小写驼峰；中文显示名按 货灵供应链运营平台习惯；类型以 PostgreSQL 风格标注。
> 本文件是字段真值源；原型列名与取值逐字取自本文件，并在 `glossary.md` 登记。

约定：必填 是＝创建时不可为空；枚举在原型以下拉呈现，首项「全部」；关联字段列展示名称。
入库计划单分发到仓后形成执行单，一票一仓，可分批到货。收货验收与上架任务由它派生，单据状态按数量口径派生，与任务状态无关。

## 4. 收货单、任务拆分与上架单

收货与上架都经过工序单这一层：收货按到货事件聚成收货单，上架按库区聚成上架单，两张单再向下拆任务。

### 收货单与收货任务

一次到货生成一张收货单（工序单 `RC`），按到货批次分组。同一次到货含多张计划单的货时合并为一张收货单，明细行各自回指来源 `planNo`，收货单本身不改变任何一张通知单的数量口径。

一票到货量大时，一张收货单的收货要拆给多个人同时做，任务回指本单 `processNo`。

| 拆分方式 | 适用场景 | 说明 |
| --- | --- | --- |
| 按品类 | 品类多、分属不同收货区 | 按商品品类段切，任务不跨品类 |
| 按库区 | 目标上架区不同 | 按 `targetBin` 所在库区切，收货后直接分流入区 |
| 按托盘 / 容器 | 整托到货、整托上架 | 按托盘号或容器号切，卸货即分任务 |

约束：一个任务只归一个执行主体——人员或设备，不混派；可含多行但不跨库区；任务独立编号，`processNo` 必填回指收货单，汇总数量回写本单 `receivedQty`；不拆时整单视为一个任务由单主体完成。

### 上架单

多张计划单的货常常要进同一个库区，按单一张张上架会让人来回跑。所以收货完成后，系统把待上架明细按目标库区汇总成上架单，一张上架单可以跨多张 `planNo`。

| 字段 | 口径 |
| --- | --- |
| 上架单号 | `PA` + 日期 + 4 位流水，不可改 |
| 目标库区 | 一个上架单只对一个库区 |
| 来源计划单 | 多张 `planNo`，按行汇总，详情可回溯到原单行 |
| 行数 / 计划上架量 | 由汇总行派生 |
| 执行单元 / 班组 | 承接本库区上架的单元与人 |
| 上架单状态 | 待作业 / 作业中 / 异常待处理 / 已完成 / 已取消 |

上架单再拆上架任务：按人、按设备或按货位段切，一段一主体，不跨库区。执行主体为人员时走手持终端扫码确认；为设备时（AGV、叉车）由设备回传完成状态，人只在异常时介入核对。

上架单不改变计划单的数量口径：`receivedQty` 在收货完成时已定，上架是货从暂存区到库位的位置变化，不重复计数。

### 与波次同构

上架单按**库区**分组，波次按**时段**分组，两者都是「多张上游单据合到一个作业单元」的编排层，只是分组维度不同。收货不做这层编排，因为它按到货事件组织，一次到货就是一个批次。

## 5. 与其它主档的关系

- 货主主档：`ownerName` 外键，单据归属货主；收货扫码只在「本单货主 + 条码」范围内匹配，命中 0 条或多条判差异，不借用其它货主商品主档。
- 商品主档：`skuCode` 外键，批次、效期、质检要求取商品主档的效期与批次策略。
- 仓库主档与库区库位：`warehouseCode` 确定落仓，`targetBin` 指向上架库位；单据只落一座实体仓。
- 出库计划单与库存台账：入库记账后写批次库存与流水，`planNo` 作为流水业务单据号留痕；错收走退仓逆向单据，不删原行。

## 6. 原型衔接建议

- 任务区（行详情抽屉）：任务编号、任务类型、执行人、目标库区、计划数量、已收数量、任务状态。一票拆多任务时按子表列出，单头只显示「已拆 N 个、完成 M 个」。
- `receiving-scan` 的上下文取任务，不取整单：扫码屏抬头是任务号与 `planNo` 两个号，后者只用于核对。
- `inbound/in-plan-list`（货灵WMS，list，页面名「入库通知单」）：计划单号、单据状态、货主、计划到货日期、品类数、计划数量、已收数量、已生成工序单、创建时间、操作。
- 状态页签取 `docStatus` 五值：全部 / 待处理 / 进行中 / 异常待处理 / 已完成 / 已取消；筛选：货主、计划单号、计划到货日期。货灵WMS即一座仓，不提供仓库筛选，目标仓库只作详情抬头字段。
- `inbound/in-plan-list` 行详情抽屉：抬头取计划单号、货主、目标仓库、计划到货日期、单据状态、已生成工序单；明细行取商品编码、商品名称、批次号、计划数量；附操作轨迹。
- `inbound/receiving-order`（货灵WMS，list）：工序单号、工序单状态、来源计划单、货主、目标库区、行数、计划数量、已收数量、作业进度、操作；行详情抽屉列出任务子表。
- `inbound/receiving-scan`（货灵WMS，scan）：任务上下文取计划单号、货主、操作员、设备、库位；对象摘要取行号、商品编码、批次号；数量区取应收数量、实收数量。
- 行按 `warehouseCode` 归属本仓，行上带货主维度供列表「货主」筛选。
