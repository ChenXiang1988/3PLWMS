# 入库通知单（数据字典）

> **已并入其它实体**：单仓端 L1 统一为「入库计划单」，计划单确认后原单推送到仓，不再另开入库通知单；收货、上架等作业数据归「工序单」。本文保留作字段历史参考，新页面的列名请取 [入库计划单.md](入库计划单.md) 与 [工序单.md](工序单.md)。

> 实体：入库通知单｜对应原型页面：入库管理 / 入库通知单、入库通知单详情（`inbound` 模块，单仓端）
> 字段名（key）用小写驼峰；中文显示名按 3PL 云仓习惯；类型以 PostgreSQL 风格标注。
> 本文件是字段真值源；原型列名与取值逐字取自本文件，并在 `glossary.md` 登记。

约定：必填 是＝创建时不可为空；枚举在原型以下拉呈现，首项「全部」；关联字段列展示名称。
入库通知单是货主委托入库的 L1 单据，一张通知单对应一次到货承诺，可分批到货。收货验收与上架任务由它派生，单据状态按数量口径派生，与任务状态无关。

## 1. 基础标识

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `asnNo` | 通知单号 | String | 24 | 是 | 仓内唯一，业务引用主键 | `ASN` + 日期 + 4 位流水；不可改 |
| `bizType` | 入库类型 | Enum | — | 是 | 采购入库 / 调拨入库 / 退货入库 / 加工入库 | 决定默认工序编排 |
| `docStatus` | 单据状态 | Enum | — | 是 | 待处理 / 进行中 / 异常待处理 / 已完成 / 已取消 | 见状态枚举，按数量口径派生 |
| `ownerName` | 货主 | String | 100 | 是 | 关联货主主档 `ownerName` | 扫码按本单货主限定商品集合 |
| `warehouseCode` | 仓库 | String | 20 | 是 | 关联仓库主档 `warehouseCode` | 一张通知单只落一座实体仓 |
| `sourceDocType` | 来源单据类型 | Enum | — | 否 | 采购单 / 调拨单 / 退货单 / 加工单 | 外部下发时填写 |
| `sourceDocNo` | 来源单号 | String | 40 | 否 | 上游单据号 | 与 `sourceDocType` 成对出现 |

### 状态枚举

| 值 | 中文 | 建议色型 tone |

| `pending` | 待处理 | `pending` |
| `doing` | 进行中 | `enabled` |

## 3. 明细行

一张通知单至少一行；批次与效期按商品主档策略决定是否必填。

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `lineNo` | 行号 | Int | — | 是 | 单内唯一，从 1 开始 | 与任务分配行 `lineNo` 对应 |
| `skuCode` | 商品编码 | String | 20 | 是 | 关联商品主档 `skuCode` | 只允许本单货主已发布商品 |
| `skuName` | 商品名称 | String | 200 | 是 | 取商品主档 | 展示用 |
| `batchNo` | 批次号 | String | 40 | 否 | 按商品主档批次编码规则生成 | 效期或批次管理商品必填 |
| `productionDate` | 生产日期 | Date | — | 否 | 不得晚于到货日期 | 效期管理商品必填 |
| `expiryDate` | 失效日期 | Date | — | 否 | 生产日期推算或供应商给定 | 取商品主档策略 |
| `planQty` | 计划数量 | Int | — | 是 | 行级计划数量 | 列表与详情展示 |
| `receivedQty` | 实收数量 | Int | — | 是 | 本次到货实收，初始 0 | 收货验收写入 |
| `targetBin` | 目标库位 | String | 20 | 否 | 关联库区库位 `binCode` | 上架推荐结果 |

## 4. 任务拆分与上架单

收货按到货事件组织，单据直接拆任务；上架按库区组织，中间多一层上架单。

### 收货任务

一票到货量大时，一张通知单的收货要拆给多个人同时做。拆分不另开单据，是在通知单下生成任务，任务回指本单 `asnNo`。

| 拆分方式 | 适用场景 | 说明 |
| --- | --- | --- |
| 按品类 | 品类多、分属不同收货区 | 按商品品类段切，任务不跨品类 |
| 按库区 | 目标上架区不同 | 按 `targetBin` 所在库区切，收货后直接分流入区 |
| 按托盘 / 容器 | 整托到货、整托上架 | 按托盘号或容器号切，卸货即分任务 |

约束：一个任务只归一个执行主体——人员或设备，不混派；可含多行但不跨库区；任务独立编号，`asnNo` 必填回指，汇总数量回写本单 `receivedQty`；不拆时整单视为一个任务由单主体完成。

### 上架单

多张通知单的货常常要进同一个库区，按单一张张上架会让人来回跑。所以收货完成后，系统把待上架明细按目标库区汇总成上架单，一张上架单可以跨多张 `asnNo`。

| 字段 | 口径 |
| --- | --- |
| 上架单号 | `PA` + 日期 + 4 位流水，不可改 |
| 目标库区 | 一个上架单只对一个库区 |
| 来源通知单 | 多张 `asnNo`，按行汇总，详情可回溯到原单行 |
| 行数 / 计划上架量 | 由汇总行派生 |
| 执行单元 / 班组 | 承接本库区上架的单元与人 |
| 上架单状态 | 待作业 / 作业中 / 异常待处理 / 已完成 / 已取消 |

上架单再拆上架任务：按人、按设备或按货位段切，一段一主体，不跨库区。执行主体为人员时走手持终端扫码确认；为设备时（AGV、叉车）由设备回传完成状态，人只在异常时介入核对。

上架单不改变通知单的数量口径：`receivedQty` 在收货完成时已定，上架是货从暂存区到库位的位置变化，不重复计数。

### 与波次同构

上架单按**库区**分组，波次按**时段**分组，两者都是「多张上游单据合到一个作业单元」的编排层，只是分组维度不同。收货不做这层编排，因为它按到货事件组织，一次到货就是一个批次。

## 5. 与其它主档的关系

- 货主主档：`ownerName` 外键，单据归属货主；收货扫码只在「本单货主 + 条码」范围内匹配，命中 0 条或多条判差异，不借用其它货主商品主档。
- 商品主档：`skuCode` 外键，批次、效期、质检要求取商品主档的效期与批次策略。
- 仓库主档与库区库位：`warehouseCode` 确定落仓，`targetBin` 指向上架库位；单据只落一座实体仓。
- 出库订单与库存台账：入库记账后写批次库存与流水，`asnNo` 作为流水业务单据号留痕；错收走退仓逆向单据，不删原行。

## 6. 原型衔接建议

- 任务区（详情页）：任务编号、任务类型、执行人、目标库区、计划数量、已收数量、任务状态。一票拆多任务时按子表列出，单头只显示「已拆 N 个、完成 M 个」。
- `receiving-scan` 的上下文取任务，不取整单：扫码屏抬头是任务号与 `asnNo` 两个号，后者只用于核对。
- `inbound/asn-list`（单仓端，list）：通知单号、单据状态、货主、仓库、入库类型、预计到货时间、品类数、计划数量、已收数量、创建时间。
- 状态页签：全部 / 待处理 / 进行中 / 异常待处理 / 已完成 / 已取消；筛选：通知单号、入库类型、货主、来源单号、预计到货时间。
- `inbound/asn-detail`（单仓端，detail）：基础信息、明细行、实收汇总、任务四段；明细行列为商品编码、商品名称、批次号、生产日期、失效日期、计划数量、实收数量、目标库位。
- `inbound/receiving-scan`（单仓端，scan）：任务上下文取通知单号、货主、操作员、设备、库位；对象摘要取行号、商品编码、批次号；数量区取应收数量、实收数量。
- 行按 `warehouseCode` 归属本仓，行上带货主维度供顶栏货主下拉过滤。
