# 代发采购单（数据字典）

> 实体：代发采购单｜对应原型页面：货灵ERP「代发采购单」（`erp` 模块，卖家侧与货源侧两个视角）
> 字段名（key）用小写驼峰；中文显示名按 货灵供应链运营平台习惯。
> 本文件是字段真值源；原型列名与取值逐字取自本文件，并在 `glossary.md` 登记。

约定：必填 是＝创建时不可为空；枚举在原型以下下拉呈现，首项「全部」。
代发采购单是卖家无货时向货源方采购、由货源方直发终端的交易单据。**同一张单两个视角**：卖家侧是采购单，货源方侧是供货单，按登录货主决定可做动作，不各建一份。它与平台订单、商城订单是上下游关系，不是同一层。

## 1. 基础标识

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `dropshipNo` | 代发单号 | String | 24 | 是 | 全局唯一，业务引用主键 | `DS` + 日期 + 4 位流水；不可改 |
| `sellerOwnerCode` | 卖家货主 | String | 20 | 是 | 关联货主主档 | 下单方，货源方视角的客户 |
| `supplyOwnerCode` | 货源货主 | String | 20 | 是 | 关联货主主档 | 供货方，不得等于卖家 |
| `sourceOrderType` | 来源订单类型 | Enum | — | 是 | 平台订单 / 商城订单 | 与 `sourceOrderNo` 成对 |
| `sourceOrderNo` | 来源订单号 | String | 24 | 是 | 平台订单编号或商城订单编号 | 追溯入口 |
| `dropshipStatus` | 代发状态 | Enum | — | 是 | 草稿 / 待确认 / 已确认 / 已下发 / 已完成 / 已取消 | 见状态枚举 |

### 状态枚举

| 值 | 中文 | 建议色型 tone |
| --- | --- | --- |
| `draft` | 草稿 | `disabled` |
| `pendingConfirm` | 待确认 | `pending` |
| `confirmed` | 已确认 | `enabled` |
| `dispatched` | 已下发 | `info` |
| `finished` | 已完成 | `disabled` |
| `cancelled` | 已取消 | `disabled` |

## 2. 商品与收货

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `skuCode` | 商品编码 | String | 20 | 是 | 货源方的已发布商品 | 只允许货源方本货主商品 |
| `skuName` | 商品名称 | String | 200 | 是 | 取商品主档 | 展示用 |
| `qty` | 采购数量 | Int | — | 是 | 不超过货源方可售量 | 锁库发生在货源方出库计划单 |
| `unitPrice` | 采购单价 | Decimal(12,2) | — | 是 | 货源方报价 | 卖家侧只读 |
| `amount` | 采购金额 | Decimal(12,2) | — | 是 | 数量乘单价 | 销售结算依据 |
| `receiverName` | 收货方 | String | 100 | 是 | 终端收货人 | 从来源订单带入，可改 |
| `receiverPhone` | 联系电话 | String | 30 | 是 | 终端联系电话 | 从来源订单带入 |
| `receiverAddress` | 收货地址 | String | 300 | 是 | 终端收货地址 | 不填本部署仓库地址 |

## 4. 两侧视角与可做动作

| 视角 | 登录身份 | 可见范围 | 可做动作 |
| --- | --- | --- | --- |
| 卖家侧 | `sellerOwnerCode` 对应的货主 | 自己发起的单 | 新建、提交、撤回、取消、查看履约与结算 |
| 货源侧 | `supplyOwnerCode` 对应的货主 | 指给自己的单 | 确认、驳回、生成出库计划单、查看结算 |

约束：卖家不能确认自己的单，货源方不能改数量与收货地址；确认后卖家只能取消未下发的部分，已下发走货源方出库计划单的取消规则。

同一张单在买卖双方各投影一条记录：单号相同，按登录货主取自己一侧的那条，两边的状态变更回写同一业务单。这不是两套业务对象，两侧记录不各自取号、不各自结算。

## 5. 与其它主档的关系

- 货主主档：`sellerOwnerCode` 与 `supplyOwnerCode` 都是外键，两者不得相同，禁止自采自供。
- 商品主档：`skuCode` 只取货源方已发布商品；卖家侧不可指定未发布商品。
- 平台订单与商城订单：`sourceOrderNo` 回指来源单，一张来源单可拆多张代发单（多货源），代发单不合并来源单行。
- 出库计划单：`outPlanNo` 回指货源方的履约单，`sourceDocType=代发采购单`、`sourceDocNo=dropshipNo`；锁库、时效、作业全部落在货源方的计划单与出库订单上。
- 入库计划单：终端退货按售后入库回到货源方，`sourceDocType=售后申请单`，回指原出库计划单。
- 费用账单与 ERP服务费账单：采购金额走卖家与货源方的结算，不并入仓储费用账单。

## 6. 原型衔接建议

- 货灵ERP `owner/dropship-list`（list）：代发单号、对方编码、商品编码、采购数量、采购金额、代发状态、结算状态、创建时间。同一张单买卖两侧各一条记录，按登录货主取自己一侧。
- 状态页签：全部 / 草稿 / 待确认 / 已确认 / 已下发 / 已完成 / 已取消；筛选：来源订单类型、代发状态、结算状态、创建时间。
- 卖家侧工具条：新建、提交、撤回、取消；货源侧工具条：确认、驳回、生成出库计划单。
- 行详情抽屉：抬头取代发单号、卖家货主、货源货主、来源订单号、代发状态、出库计划单号；明细取商品、数量、单价、金额；收货区取终端收货人、电话、地址；附操作轨迹。
- 列表按登录货主限定：卖家看自己发起的，货源方看指给自己的，不提供货主筛选。
