# 组织（数据字典）

> 实体：组织（Organization）｜对应原型页面：账号与权限 / 组织架构（`system` 模块 `org-list`）
> 定位：运营方与仓内的组织树，先用仓库与班组表达，不新建独立组织数据源。

## 1. 组织字段

| 字段 key | 中文名 | 类型 | 长度 | 必填 | 取值 / 口径 | 说明 / 关联 |
| --- | --- | --- | --- | --- | --- | --- |
| `orgCode` | 组织编码 | String | 20 | 是 | 全局唯一 | |
| `orgName` | 组织名称 | String | 60 | 是 | | |
| `orgType` | 组织类型 | Enum | — | 是 | 运营中心 / 仓库 / 部门 / 班组 | |
| `parentCode` | 上级组织 | String | 20 | 否 | 根节点为空 | |
| `warehouseCode` | 所属仓库 | String | 20 | 否 | 仓库与班组必填 | |
| `leader` | 负责人 | String | 50 | 否 | | |
| `staffCount` | 人数 | Int | — | 否 | 派生 | |
| `orgStatus` | 状态 | Enum | — | 是 | 启用 / 停用 | |

## 2. 状态与口径

- 停用组织前必须先迁走人员与账号。
- 树深最多四级；班组挂在仓库下。
- 组织编码不可改。

## 3. 与其它主档的关系

- 仓库主档、班组档案：`warehouseCode` 与组织节点对应。
- 子账号：`orgCode` 决定数据范围。
- 审批流：审批角色按组织节点配置。

## 4. 原型衔接建议

- 页面：`system/org-list`，list 骨架，树形缩进列。
- 表单抽屉：组织编码、名称、类型、上级、所属仓库、负责人。
