# 货灵 WMS P1 原型改造清单

> 本清单把《货灵WMS原型设计方案》的 P1「自动化和接口治理」转换为可执行的原型改造范围。当前只登记改造计划，不修改 `prototypes/`；进入实施前须按跨端联动规则确认。

## 1. P1 目标与边界

P1 解决 P0 已能执行、但跨系统和多厂商接入仍不可治理的问题：

```text
连接器/协议 → 能力矩阵 → 自动化拓扑 → 设备任务
                         ↓
              接口对账 → 回执补发/状态重同步
                         ↓
              故障影响 → 任务重排/人工接管/库存过账拦截
```

### 本批纳入

- 连接器管理：设备服务连接端点、协议、凭证脱敏、心跳、健康状态、版本和测试结果。
- 设备能力矩阵：设备类型/型号支持的作业、动作、方向、负载、替代资源和生效范围。
- 自动化拓扑：库区、工位、设备、执行单元、节点、边和当前可用状态的二维关系视图。
- 协议、状态码、错误码映射：厂商原始值映射到统一任务/设备/异常状态，带版本和生效范围。
- 接口对账：WMS、WES、WCS、厂商之间的业务任务、设备任务、指令、回执和库存结果对账。
- 发运回执与补偿：装车/交接后承运商回执、失败重试、补发、状态重同步、异常转单。
- 故障影响闭环：故障告警关联受影响任务、替代设备、人工接管和库存过账拦截。

### 本批不纳入

- 真实厂商接口、证书/密钥保管、WES 求解器、路径规划和实时数据流。
- 三维孪生、拓扑自动布局、全量协议编辑器和厂商控制台复制。
- ERP 订单主档、PDA 扫码页和商城订单流程重建。
- P2 的产能模拟、吞吐预测、异常聚类、三维孪生；本次 P2 已单独实施，见《货灵WMS原型设计方案》P2 落点。

## 2. 现有基线与复用落点

| P1 能力 | 当前可复用页面/模块 | 处理结论 |
| --- | --- | --- |
| 连接器管理 | `resource/device-driver`、`resource/hardware-list`、`resource/device-monitor` | 改造 `device-driver` 为连接器/协议配置主列表；设备监控抽屉展示健康和版本，不新增独立一级页 |
| 设备能力矩阵 | `resource/agv-strategy`、`resource/exec-unit-list`、`resource/hardware-list` | 新增 `resource/device-capability` 列表；策略页只保留调度参数，设备/执行单元引用能力矩阵 |
| 自动化拓扑 | `resource/device-monitor`、`warehouse/location-list` | 新增 `resource/automation-topology` 报表页；二维节点关系，异常节点可进入设备监控或任务池 |
| 协议/状态码/错误码映射 | `resource/device-driver`、`resource/device-alarm` | 以 `device-driver` 抽屉承载协议版本/映射；告警抽屉显示原始码与统一错误码，不新增编码管理一级页 |
| 接口对账 | `owner/reconciliation-list`、`resource/device-monitor` | WMS 新增 `resource/interface-reconciliation` 列表；ERP 现有对账页维持订单/物流/费用语义，不共用页面 |
| 发运回执与补偿 | `outbound/handover-list`、`outbound/loading-list`、ERP `owner/tracking-list` | WMS 交接单承载回执/补偿动作；ERP 物流跟踪只读展示运单节点和回单，不下发仓内补偿 |
| 故障影响闭环 | `resource/device-alarm`、`task/task-pool`、`inventory/stock-snapshot` | 通过告警详情串联影响任务、替代设备、人工接管和库存过账拦截 |

## 3. 逐页改造清单

### 3.1 连接器与协议 `device-driver`

- **源文件**：`prototypes/resource/pages/device-driver.mjs`
- **数据文件**：`prototypes/resource/data/device-driver.json`
- **注册**：现有 `resource/device-driver`，归 `warehouse-app` 的「设备与容器」段。
- **筛选**：设备类型、协议、连接状态、版本状态、更新时间。
- **列表列**：驱动编码、设备类型、协议、端点、凭证状态、协议版本、心跳秒数、连接状态、最近测试、最近错误。
- **抽屉**：端点与脱敏凭证、协议版本、生效范围、状态码映射、错误码映射、心跳记录、最近测试请求/响应摘要。
- **动作**：测试连接、发布版本、停用连接器、查看映射；停用必须显示受影响设备和任务，支持撤回前确认。
- **演示数据**：HTTP 已连接、MQTT 心跳延迟、TCP 连接失败、版本待发布、映射缺失导致任务拦截。
- **规则**：不展示真实密钥；原始码与统一状态分列；连接状态不覆盖设备状态。

### 3.2 设备能力矩阵 `device-capability`

- **源文件**：新增 `prototypes/resource/pages/device-capability.mjs`
- **数据文件**：新增 `prototypes/resource/data/device-capability.json`
- **注册**：新增 list 页面 `resource/device-capability`，归 `warehouse-app` 的「设备与容器」段。
- **筛选**：设备类型、型号、作业类型、方向、能力状态、生效范围。
- **列表列**：能力编码、设备类型、设备型号、作业类型、动作、方向、负载上限、容器能力、替代能力、生效版本、状态。
- **抽屉**：能力明细、适用设备/执行单元、前置条件、替代资源、版本历史、命中任务。
- **动作**：新增能力、复制版本、停用能力、查看命中任务；停用前提示受影响的设备和待执行任务。
- **演示数据**：AGV 搬运/充电、输送线分流、AS/RS 入库/出库、称重打印组合能力、能力缺失。
- **规则**：能力是资源约束，不把设备型号直接写入任务策略；能力状态、设备状态、任务状态分开。

### 3.3 自动化拓扑 `automation-topology`

- **源文件**：新增 `prototypes/resource/pages/automation-topology.mjs`
- **数据文件**：新增 `prototypes/resource/data/automation-topology.json`
- **注册**：新增 report 页面 `resource/automation-topology`，归 `warehouse-app` 的「设备与容器」段。
- **筛选**：库区、节点类型、连接状态、业务影响、拓扑版本。
- **展示**：二维节点与连线关系；节点显示节点编码、节点类型、设备/执行单元、状态、当前任务数；边显示方向、协议、连接状态和最近回执。
- **详情**：节点能力、上下游节点、当前任务、故障影响、替代路径、最近变更。
- **动作**：切换拓扑版本、隔离节点、恢复节点、查看影响任务；隔离必须保留原因和操作人。
- **演示数据**：输送线分流节点断链、AS/RS 出库节点降级、AGV 充电区不可用、旁路路径可用。
- **规则**：P1 只做二维关系和状态，不承诺三维孪生；节点状态与设备运行状态分列。

### 3.4 接口对账 `interface-reconciliation`

- **源文件**：新增 `prototypes/resource/pages/interface-reconciliation.mjs`
- **数据文件**：新增 `prototypes/resource/data/interface-reconciliation.json`
- **注册**：新增 list 页面 `resource/interface-reconciliation`，归 `warehouse-app` 的「设备与容器」段。
- **筛选**：对账对象、方向、对账状态、时间范围、影响级别、来源系统。
- **列表列**：对账号、业务任务号、设备任务号、指令号、来源系统、目标系统、最近发送、最近回执、WMS 状态、外部状态、对账结果、影响级别。
- **抽屉**：请求、响应、回执时间轴、状态映射、重试/补发记录、库存结果、关联告警和任务。
- **动作**：重新拉取状态、补发回执、重试指令、转异常、标记已核对；不可直接修改业务状态。
- **演示数据**：WCS 已完成但 WMS 未收回执、WMS 已派发但厂商拒绝、重复回执幂等、库存过账拦截、对账一致。
- **规则**：对账结果不等同业务状态；补发保留幂等键、操作者、原因和前后状态。

### 3.5 发运回执与补偿 `handover-list`

- **源文件**：`prototypes/outbound/pages/handover-list.mjs`
- **数据文件**：`prototypes/outbound/data/handover-list.json`
- **注册**：现有 `outbound/handover-list`，归 `warehouse-app` 的「发货作业」段。
- **筛选**：交接状态、回执状态、承运商、发运时间、异常类型、补偿状态。
- **列表列**：交接单号、来源装车单、承运商、包裹数、发运时间、运单号、回执状态、最近回执、重试次数、异常单号。
- **抽屉**：交接明细、承运商请求/响应、回执时间轴、运单节点、失败原因、补偿记录、关联异常。
- **动作**：补发回执、重新同步、转异常、关闭补偿；关闭不可逆，必须展示未完成包裹和异常影响。
- **演示数据**：已回执、回执超时、部分包裹失败、重复回执、承运商接口不可用。
- **规则**：发运后不可回退装车状态；补偿只重试接口/同步，不回写库存事实。

### 3.6 告警/任务/库存闭环

- **改造文件**：`prototypes/resource/pages/device-alarm.mjs`、`prototypes/task/pages/task-pool.mjs`、`prototypes/inventory/pages/stock-snapshot.mjs` 及对应数据。
- **告警增加**：统一错误码、连接器、拓扑节点、接口对账号、替代设备、库存拦截状态。
- **任务增加**：故障来源、替代资源、重排版本、接口对账结果、人工接管结果。
- **快照增加**：设备回执状态、库存过账拦截原因、重同步结果、核验任务号。
- **联动动作**：告警查看影响任务 → 任务重排/转人工 → 对账重试/状态同步 → 快照核验或库存调整任务；每一步保留审计和前后状态。

## 5. 跨端联动评估（实施前确认）

| 端 | 落点 | 联动点 | 结论 |
| --- | --- | --- | --- |
| 货灵 WMS `warehouse-app` | `resource`、`outbound`、`task`、`inventory` 页面与数据 | 新页面注册、连接器/能力/拓扑/对账字段、任务与库存状态、导航段 | 必须同改 |
| PDA 作业端 `pda-app` | 拣货、上架、盘点、设备接入上下文 | 任务号、设备/执行单元、人工接管、异常码；本批不改 PDA 页面但保持字段契约 | 必须同改（字段核对） |
| 货灵 ERP `erp-app` | `owner/tracking-list`、`owner/reconciliation-list`、出库/物流结果 | 发运回执、运单节点、异常单号、对账边界；ERP 不承接 WCS 设备对账页 | 必须同改（链路核对） |
| 运营中台 `network-app` | 设备档案、设备监控汇总、告警与仓网资源 | 跨仓设备/连接器只读汇总、告警级别和仓库范围；本批原则上不新增网络端页面 | 必须同改（口径核对） |
| 货灵商城 `mall-app` | 订单与身份 | P1 不触及商城身份或购物链路 | 无需改 |
| 独立站 Web/APP | 商品、订单、品牌站 | 不引用 WMS 设备和接口状态 | 无需改 |
| 共享层 | `modules.json`、`ui.mjs`、`glossary.md` | 新 page key、页面类型、导航、状态和组件契约 | 必须同改 |
| 数据字典 | 设备、告警、运单、装车及新增正式实体 | 字段、枚举、关联和来源 | 必须同改 |

本批默认重建七个端；不同步会影响 WMS 页面装配、PDA 任务上下文、ERP 发运回执、运营中台告警口径和全量交付验收。若只实施 WMS，必须在交付记录中说明未同步端及后果。
