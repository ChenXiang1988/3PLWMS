# 货灵 WMS P0 原型改造清单

> 本清单把《货灵WMS原型设计方案》和“有限空间资源约束下的仓内作业调度模型”转换为可执行的原型改造范围。当前只登记改造计划，不修改 `prototypes/`；进入实施前须按跨端联动规则确认。

## 1. 改造目标与边界

P0 补齐一条可追溯的仓内执行主链：

```text
出库订单 → 库存分配/锁定 → 波次 → 拣货单 → 作业任务 → 设备任务/人员执行 → 回执与异常 → 库存流水
```

调度员最终应能回答：哪些任务可以释放、哪些被挡住、当前瓶颈在哪里、设备异常影响哪些业务、库存结果是否可追溯。

### 本批纳入

- 任务池：前置依赖、阻塞原因、SLA、执行单元、派工与重派。
- 出库调度：库存分配、锁定、缺货/短拣、波次容量、释放与重排。
- 设备执行：设备任务关联、心跳、回执、重试、故障影响和人工接管入口。
- 容器资源：容器能力、当前位置、占用单据、设备任务和回流状态。
- 库存事实：WMS 侧库存流水入口、来源链路、数量守恒和快照差异。
- 设备任务队列、消息流水/死信补发；优先采用现有页面或详情抽屉承载。

### 本批不纳入

- 真实后端接口、WES 求解器、路径规划和厂商协议实现。
- 三维孪生、完整产能仿真和自动参数校准。
- ERP 订单主档、跨仓库存和 PDA 扫码页面的重复建设。
- 独立的 WES/WCS/集成治理一级导航。
- 驱动协议编辑、协议映射和连接测试，列为 P1；P0 只展示执行影响和接管入口。

## 4. 逐页改造清单

### 4.1 任务池与派工 `task-pool`

| 项目 | 要求 |
|---|---|
| 筛选 | 区域、任务类型、阻塞原因、SLA、执行单元、设备影响、跨层；保留货主、执行人、更新时间 |
| 状态 | `taskStatus` 保持待作业/作业中/阻塞/已完成/已取消；异常单独用 `exceptionFlag` |
| 列 | 任务号、来源单据号、工序单号、类型、区域、计划/完成数量、优先级、SLA、阻塞原因、执行单元、设备任务号、重试次数 |
| 调度字段 | 前置任务、授权状态、准入原因、当前瓶颈、缓冲占用、预计等待、同步窗口、容器需求 |
| 动作 | 批量派工、批量重派、转人工、暂停/恢复释放、查看、派工、登记异常 |
| 抽屉 | 来源链路、前后置依赖、资源组合、准入判断、执行轨迹、异常和动作条 |
| 数据 | 覆盖待派、设备故障影响、容器不足、前置未完成、垂直队列满、已完成 |

### 4.2 出库订单 `out-plan-list`

| 项目 | 要求 |
|---|---|
| 筛选 | 分配状态、锁库状态、缺货原因、波次号、承诺时间、SLA；保留货主、计划单号、计划日期 |
| 列 | 订单号、来源单号、货主、承诺时间、订单行数、计划/已分配/已锁定件数、缺货数、波次号、当前工序、`docStatus` |
| 抽屉 | 分配规则、锁定库存、批次/库位、缺货明细、短拣、波次和任务关联 |
| 动作 | 分配、重新分配、释放锁定、加入波次、取消分配、查看任务；危险动作显示影响和可逆性 |
| 规则 | 分配只增加已分配量，不改变实物总量；库存变化必须进入库存流水 |
| 数据 | 覆盖分配成功、部分缺货、锁库失败、已入波次、部分发货、取消释放库存 |

### 4.3 波次计划 `wave-list`

| 项目 | 要求 |
|---|---|
| 筛选 | 区域、波次类型、瓶颈状态、容量风险、执行单元类型；保留波次号、作业时段 |
| 列 | 波次号、时段、类型、容量上限、订单数、件数、容器数、标准工作量、剩余容量、当前瓶颈、阻塞任务数、状态 |
| 容量 | 同时体现订单数、明细行、件数、容器数和执行单元产能，不能只看任务数 |
| 动作 | 新建、加入/移出订单、释放、暂停、拆分、重排、关闭；释放前展示容量和瓶颈校验 |
| 抽屉 | 订单/任务清单、资源负荷、缓冲水位、库容风险、设备影响、释放记录 |
| 数据 | 覆盖容量正常、接近上限、超限待拆、设备故障、释放后暂停、重排版本 |

### 4.4 拣货单 `picking-order`

| 项目 | 要求 |
|---|---|
| 筛选 | 任务状态、短拣状态、设备影响、执行单元、区域；保留货主、波次、工序单、来源计划单 |
| 列 | 拣货单号、来源订单/行号、波次、区域/路线、行数、计划/已拣/短拣数量、容器数、执行单元、设备任务号、任务状态 |
| 动作 | 生成、拆分、合并、派工、重派、转人工、登记短拣、返仓；结果回写关联链路 |
| 抽屉 | 订单/波次来源、分配库存、批次库位、容器、任务拆分、设备回执、短拣原因和后续库存动作 |
| 规则 | 短拣不伪装成普通异常；未完成任务不得直接删除 |

### 4.5 设备监控 `device-monitor`

| 项目 | 要求 |

| 筛选 | 区域、设备类型、连接状态、业务影响、当前任务、时间范围 |

| 状态 | 设备、任务、连接、异常四套状态独立展示 |

### 4.6 告警与故障工单 `device-alarm`

| 项目 | 要求 |
|---|---|
| 筛选 | 设备类型、区域、影响任务、级别、工单状态、SLA |

| 动作 | 认领、转派、隔离设备、暂停任务、转人工、登记恢复、关闭、查看消息流水 |

### 4.7 容器管理 `container-list`

| 项目 | 要求 |
|---|---|
| 筛选 | 类型、可用状态、当前位置、占用状态、回流状态、任务号；保留货主和容器状态 |
| 列 | 编码、类型、有效容积、载重上限、载具位、装载率、区域/库位、状态、占用单据、设备任务、回流任务 |
| 动作 | 新增、绑定任务、释放占用、登记回流、维修、报废、查看流转；报废必须显示不可逆影响和审批要求 |

### 4.8 库存快照 `stock-snapshot`

| 项目 | 要求 |
|---|---|
| 筛选 | 区域、库位、批次、差异状态、冻结状态、时间范围；保留货主、编号、时间 |
| 列 | 快照编号/时间、货主、商品、批次、库位、容器、快照量、当前量、差异量、可用量、冻结量、差异状态、来源流水数 |
| 动作 | 生成、对比、查看差异、发起核验、查看流水；不提供直接编辑数量 |
| 规则 | 差异降低相关状态可信度并生成核验任务；调整必须审批后进入调整流水 |

| 列 | 流水号、来源单据号、来源任务号、业务类型、商品、批次、库位、容器、变动前/变动/变动后数量、原因、操作人、时间 |

## 5. P0 新增承载方案

### 设备任务队列

优先在 `device-monitor` 增加任务入口和约 920px 详情抽屉；若密度不足，再新增 `resource/device-task-queue.mjs`，同步 `resource/module.json` 与 `shared/modules.json`。

必须显示：业务任务号、设备任务号、指令号、幂等键、设备、目标/路由、执行状态、重试、心跳、失败原因、原始回执、统一状态和回执时间；支持重试、换设备、转人工、取消、重新同步。

### 消息流水与死信补发

优先在设备任务或告警抽屉承载；若必须独立列表，再新增 `resource/message-log.mjs`、`resource/dead-letter.mjs`。必须显示消息号、业务号、方向、事件、来源、状态、重试次数、最后错误、原始请求/响应、死信原因、影响范围和补发前后状态；所有重试、补发、忽略、转异常均留审计。

## 7. 跨端联动评估（改原型前确认）

| 端 | 落点 | 联动点 | 结论 |
|---|---|---|---|
| 货灵WMS `warehouse-app` | `task`、`outbound`、`resource`、`inventory` | 页面字段、状态、动作、来源链路、设备任务、库存流水 | 必须同改 |
| PDA 作业端 `pda-app` | 收货、上架、拣货、盘点上下文 | 任务号、容器码、数量、差异原因、完成回写；本批不改 PDA 页面但需保持字段契约 | 必须同改（字段契约） |

| 运营中台管理端 | 单仓执行单、仓网告警、库存汇总 | 不新增跨仓能力；核对 WMS 状态和告警口径 | 必须同改（口径核对） |

## 8. 实施顺序与确认点

1. **基线确认**：执行构建检查，确认本清单中的页面 key、注册归属和现有产物无漂移。
2. **文案与字段确认**：先确认 glossary、数据字典和页面注册是否需要变更。
3. **先改 P0 主链**：任务池 → 出库订单 → 波次 → 拣货单 → 设备监控/告警 → 库存流水/快照。
4. **再补容器与新增承载**：容器能力、设备任务队列、消息流水/死信；优先抽屉，避免无必要新增导航。
5. **每个模块完成后重建**：共享层一旦变化，默认全量重建五端。
6. **交付验收**：构建、交付验证、文档和数据字典检查；逐项核对 A/B 组与本清单场景。

## 9. P0 验收清单

- [ ] 任务池能区分可执行、授权、阻塞和异常，并能看到阻塞理由链。
- [ ] 波次释放前能看到容量、缓冲、瓶颈和设备影响校验。
- [ ] 出库订单能追溯分配、锁定、缺货、波次和任务。
- [ ] 拣货短拣、设备失败、转人工和返仓有明确状态与逆向路径。
- [ ] 设备状态、任务状态、连接状态、异常状态不互相覆盖。
- [ ] 设备故障能定位影响任务，并可进入暂停、重试、换设备或人工接管。
- [ ] 容器能力、占用、回流、空间占用和货物通过量口径分开。
- [ ] 库存流水能追溯来源单据、任务、设备/人员执行和数量守恒。
- [ ] 快照差异只能进入核验/调整流程，不可直接编辑库存余额。
- [ ] 消息失败、重试、死信、补发、幂等键和审计记录可见。
- [ ] 1440、1024、768 三档无页面级横向溢出；抽屉动作有可访问名称，危险动作显示影响和可逆性。

> 本清单确认后，才进入 `prototypes/` 源文件修改；若实施中发现新的跨端落点，须暂停并补充联动评估后重新确认。
