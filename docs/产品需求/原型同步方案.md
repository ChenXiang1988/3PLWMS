# PC 原型同步方案（proto-next → 3PL 云仓）

**目标读者**：产品、原型维护人。
**核心目的**：把 `D:/productdesgin/newWMS/proto-next/pc` 已实现的页面按本项目端装配规范同步过来，作为原型页面清单与后续开发拆分依据。
**前提**：范围取全部已实现页；新增 `network`、`resource` 两个模块及所需页面。本次不新增端，只动后台三端（货主端、仓网管理端、单仓端）；项目另有商城端由别的会话在建，不碰它。原型规范见 `.codebuddy/skills/3pl-wms-proto/`，字段真值见 `docs/数据字典/`。

文中的注册表数字与产物指纹以 2026-11-06 现场读取为准，每批开工前重跑 `node prototypes/build-app.mjs --check` 并复看 `prototypes/shared/modules.json`。

> **现场口径变更（2026-11-06 收口）**：`prototypes/01 shared/`、`00 dist/` 已更名为 `shared/`、`dist/`，`apps[].id` 统一加 `-app` 后缀，本文表格与段落里的 `network` / `warehouse` / `owner` 均指 `network-app` / `warehouse-app` / `owner-app`。按 `references/modules.md` 第 3.4 节的预留路径规则，`deployed: false` 的模块与未分配 `app` 的页面不落地 `pages/` 与 `data/`，现场已清除这些空壳模板；下文「归位」「重写模板页」「空 `data/*.json` 补演示行」一律读作「分配 `app` 后从 `templates/page-*.mjs` 复制生成页面源与 `data/<页key>.json`」。第 8 节与第 9 节记录的并发状态与产物指纹是当时快照，以现场重跑为准。

## 1. 那边的形态

`proto-next` 的 PC 端不是「总仓端 + 单仓端」两个产物。8 个一级分组、59 页全渲染进一份 `pc.html`，靠 `hidden` 与 hash 切页。「总仓管理」「单仓配置」都挂在「仓储库存」这个一级组下，区别只在页头「仓库」下拉是否生效：`pc/src/menu.mjs` 的 `SCOPED_SECTIONS = {'conf','docs','task'}` 控制显隐，`shell/warehouse-scope.js` 过滤带 `[data-wh]` 的行。总仓段与库存中心看全部 8 个仓、不写 `data-wh`；单仓配置、仓库单据、任务中心按仓切。判据写在 `D:/productdesgin/newWMS/docs/specs/05-PC页面构筑约定.md` 第 7.1 节：数据属不属于某一座具体的仓。

我们这边「端」是交付单元：一个端一个 `dist/<端名>.html`，侧栏按模块分组只列本端页面。后台三端产物各约 50~90KB，商城端产物由另一会话生成。所以「总仓 → 仓网管理端」是概念映射，同步动作是把 total 段的页面按 `pages[].app` 归到 `network`，不是拷一个端过来。

59 页按 `menu.mjs` 的 `kind` 分：48 页 `data`（有真实数据与列定义）、9 页 `gap`（缺口说明页）、1 页 `embed`（整段嵌入未复制交互）、1 页 `form`（字段表单）。48 页 `data` 里 `order-all`、`out-pick`、`out-ship` 只有 skeleton，`wm-transfer` 是 `renderPageDef` 通用渲染，折算工作量时要扣掉。

`proto-next/dist/pc.html` 目前不存在，要看效果得先跑 `node pc/src/build.mjs`。构建把 34.78MB 的 `bins.json` 整个塞进 `#whmData`，产物约 40MB，只适合当对照物。

## 5. 文案与数据口径

动页面的顺序不能反：先在 `glossary.md` 第 6 节登记 26 个新页面名、列名、状态中文名与色型，同步 `references/registry.md` 第 4 节与 `prototypes/shared/modules.json`，再写页面。状态色型只用 `disabled` / `enabled` / `info` / `pending` / `rejected` 五种；那边的 `ok` / `out` / `low` 未定义，不能直接带过来。

`resource` 涉及设备、容器、执行单元、班组、人员、排班六类新实体，`docs/数据字典/` 目前只有货主、商品、仓库、库区库位四份字典。按本项目「原型须基于数据字典、列名逐字取字典」的规矩，先各写一份字典文档，登记分类 `index.md` / `log.md`，再画这 12 页。仓库档案、库区库位、商品档案、货主档案四页一律以现有字典为准，不用那边的列。

演示数据从 `shared/data/*.json` 按页裁几十行，字段按我们的字典重造，一页一个 `data/<页key>.json`。不整库搬：`bins.json` 34.78MB、`page-defs.json` 3.8MB、`out-orders.json` 1.09MB 都不入库，那 8 个 `verify-*.mjs`、`doc-status.mjs`、`wave-progress.mjs` 等构建期派生也一并丢掉。

业务口径要改：那边是「西之月」电商自营仓，8 个实体仓，带采购单、订单列表、拍单账号、货主组；我们是「华运」3PL 单主体多货主，货主是业务实体。采购、订单、账号类页面按功能清单的「委托单据中心」「入库委托」「出库委托」重造，状态枚举取 `glossary.md`。不做租户、主体切换器一类界面。

## 6. 从零生成目录与构建

新模块目录不要手建，按这个顺序：

1. 定文案与装配清单：改 `.codebuddy/skills/3pl-wms-proto/references/core/glossary.md`、`references/registry.md`，再把新增模块、页面、`pages[].app` 写进 `prototypes/shared/modules.json`。空工作区第一次用才需要动 `templates/modules.json`。

## 8. 开工前的阻塞与风险

`node prototypes/build-app.mjs --check` 现在报 drift：货主端产物 `65fec384`，当前源 `d1330729`。查了现场，`git status` 里 `shared/ui.mjs`、`tokens.css.mjs`、`modules.json`、`build-app.mjs` 和整套 `.codebuddy/skills/3pl-wms-proto/` 都在改动中，`prototypes/mall/` 与 `templates/page-shop.mjs` 还是未跟踪的新文件：另一个会话正在把商城端接进来，注册表已改成四端五类骨架，`dist` 也刚多出商城端。共享层一改，所有端指纹都会变，这就是 drift 的来源。按原型规范要先等那边收口、确认没有并发改动，再重建基线；不能现在就全量重建，会把别人没做完的东西一起写进产物。

外部没有现成 `pc.html`，第 0 批要先构建出对照物；那份产物约 40MB，和我们 50~90KB 的端产物不是一个量级，只能看，不能并进 `dist/`。

直接拷代码会被 `build-app.mjs` 的断言拦住：色值只能取 `tokens.css.mjs` 里的 hex（那边是紫色 `#6424fe`、`--primary-*` / `--wds-*` 双家族加 229KB `antd.css`）；页面模块出现 `<script>` 即违规（那边 `warehouse-manage.mjs` 内嵌 JS、`hardware.mjs` 有 7 处内联脚本、6 个 `shell/*.js` 构建期内联）；类名必须是 `wx-` 或模块前缀（那边是 `hw-` / `whm-` / `net-` / `tbd-`）；骨架按 `pages[].type` 分派，不能混搭（总仓视图是自绘页）；`gap` 页整页的缺口说明属禁语；产物不得有外链。所以路径是「借内容与演示数据，按我们的规范重建」，不是搬文件。

`glossary.md` 与 `design-spec.md` 已登记商城端和 `shop` 骨架，`build-app.mjs` 也已支持 `apps[].shell`。共享层改动已于 2026-11-06 收口，四端 `--check` 报 `check ok`。
