# 单据工序编排 DAG 设计

**目标读者**：产品、原型维护人、研发。
**核心目的**：定货灵WMS「单据工序编排」的节点模型、分支与合流语义、生效维度、版本规则与界面形态，作为 `resource/workflow-list` 与 `DagGraph` 组件的实现依据。
**前提**：独立部署、单一运营主体；货灵WMS即一座仓，多货主是业务维度。字段真值见 `docs/数据字典/工序单.md`，节点就绪后落单的口径见该文件第 4 节。

## 1. 参照与边界

参照对象是 FlyFlow（https://www.flyflow.cc/）：基于 Flowable 的开源低代码工作流平台，前端 Vue3 + Element Plus，后端 Spring Boot + Flowable。它提供钉钉式树状设计器与 BPMN 自由画布两套，本项目只借鉴前者。

借鉴的三点：

| 借鉴项 | FlyFlow 的做法 | 本项目落点 |
| --- | --- | --- |
| 布局 | 主干纵向，分支以列的形式从左到右展开，分支内可嵌套 | `DagGraph` 按层纵向排布，同层分支横排 |
| 条件分支 | 从左到右逐个匹配，首个命中即执行，只能走一路，都不匹配走默认分支 | 条件分支节点，条件组之间与或关系 |
| 分支嵌套 | 并行分支内可放条件分支，反之亦然 | 节点可嵌套，层数由 `layer` 表达 |

不借鉴的三点：

| 不借鉴项 | FlyFlow | 本项目 | 原因 |
| --- | --- | --- | --- |
| 并行语义 | 只有无条件并行，全部分支必执行 | 三种分支：条件分支、并行分支、包容分支 | 工序里常见「按品类并行收货」，是条件并行 |
| 合流规则 | 固定 AND-Join，全部到齐才流转 | 可配全部到齐或任一完成 | 主货位与备货位并行上架时，任一完成即可 |
| 回环 | 审批流允许驳回回连 | 图内禁止回环，逆向走独立单据 | 反上架、退货、冲正都是新单据，不在编排图上表达 |

## 2. 节点模型

一个节点是一道工序的模板，落单时按节点属性生成工序单。节点字段：

| 字段 key | 中文名 | 取值 / 口径 |
| --- | --- | --- |
| `nodeId` | 节点标识 | 编排内唯一 |
| `nodeType` | 节点类型 | 取 `工序单.md` 的 `processType` 枚举：收货 / 上架 / 拣货 / 复核 / 交接 / 盘点 / 移库 / 补货 / 质检 / 贴标 / 打托 / 拆零 |
| `nodeName` | 节点名称 | 默认取节点类型中文名，可改 |
| `preNodes` | 前置节点 | 多选，空表示起始节点 |
| `branchType` | 分支类型 | 无条件 / 条件分支 / 并行分支 / 包容分支 |
| `conditions` | 条件组 | 见第 3 节 |
| `mergeRule` | 合流规则 | 全部到齐 / 任一完成，只在本节点有多个前置时生效 |
| `genMode` | 生成方式 | 自动 / 人工确认；自动即节点就绪即落单，人工即就绪后等人点确认 |
| `groupBasis` | 分组依据 | 取 `工序单.md` 的 `groupBasis` 枚举，决定一个节点出几张工序单 |
| `splitDim` | 拆分维度 | 按品类 / 按库区 / 按容器 / 按货位段 / 按货主，决定工序单怎么拆任务 |
| `subject` | 执行主体 | 人员 / 设备 / 不限，一个任务只归一个主体 |
| `required` | 是否必过 | 是 / 否；否时节点就绪后可由人工跳过 |
| `timeoutHour` | 超时告警 | 小时数，超过写入作业看板的超期项 |

节点就绪判定：`preNodes` 中所有节点按 `mergeRule` 满足完成条件，且本节点 `conditions` 命中，才算就绪。就绪后按 `genMode` 落单。

## 3. 分支与合流

三种分支，选中哪一种由 `branchType` 决定：

| 分支类型 | 语义 | 适用 |
| --- | --- | --- |
| 条件分支 | 按条件从左到右匹配，首个命中执行，其余不走；都不命中时走默认分支 | 效期商品必过质检、非效期直上架 |
| 并行分支 | 不设条件，所有分支同时激活 | 收货完成后质检与分区上架同时开工 |
| 包容分支 | 所有满足条件的分支同时激活，可零到多条 | 按品类并行收货，命中几个品类走几路 |

条件组结构：一个节点可挂多组条件，组间关系取「且」或「或」；组内条件为「字段 + 操作符 + 值」三元组，同一组内默认「且」。字段来源限定三类，取值逐字取数据字典：

- 单据属性：入库类型、出库类型、来源单据类型、是否紧急
- 商品属性：是否效期管理、品类编码、温层、包装单位
- 货主属性：货主编码、是否要求批批检

字段值为空时判定为不命中，不视为通过。条件不支持远程接口与脚本表达式，避免原型出现不可见的判定逻辑。

合流两种，由下游节点的 `mergeRule` 决定：

| 合流规则 | 语义 | 适用 |
| --- | --- | --- |
| 全部到齐 | 所有进入本节点的分支都完成才就绪 | 质检与上架都完成才记账 |
| 任一完成 | 任一分支完成即就绪，其余分支保留在途 | 主货位与备货位任一路完成即可发货 |

## 4. 生效维度与命中

编排的适用范围由三个字段决定，匹配时按「最具体优先」：

| 字段 | 必填 | 留空含义 |
| --- | --- | --- |
| `docType` | 是 | 不允许留空 |
| `ownerCode` | 否 | 空表示覆盖本仓全部货主 |
| `categoryCode` | 否 | 空表示覆盖全部品类 |

命中顺序：先比具体度，字段都匹配的编排里空字段越少越优先；具体度相同时取最新已发布版本。同一适用范围不允许两条同时处于已发布状态。

兜底：没有命中时使用单据类型级默认编排（货主与品类都留空的那条）；连默认编排也没有的，单据在受理时拦下并提示未配置编排，不落半截流程。

编排数量会随货主与品类增长，列表页必须能按单据类型、货主、品类三个字段筛，并提供从现有编排复制新建的入口。

## 5. 版本与发布

两态三值：

| 状态 | 含义 | 可做的动作 |
| --- | --- | --- |
| 草稿 | 编辑中，可反复改 | 保存、删除、发布 |
| 已发布 | 对新单据生效，只读 | 停用、另存为新版本 |
| 已停用 | 不再被命中，历史单据仍可查 | 重新启用 |

发布时版本号递增，`flowCode` 不变。单据落工时记录 `flowRef`（编排编号 + 版本号），在途单据始终沿用创建时的版本，不因新版本发布而改道。回查一张单据当时走了哪版流程，靠这个字段。

## 6. 无环与逆向

保存草稿时做一次环检测，发布时强制再检一次，有环直接驳回并指出成环的节点链。检测按拓扑排序实现，不靠人工看图。

逆向不进图：

| 逆向场景 | 处理方式 |
| --- | --- |
| 反上架、反收货 | 新开冲销单据，库存与库位占用回退，原单据行保留 |
| 退货、退仓 | 新开入库通知单（退货入库），不改原出库订单 |
| 盘点差异冲正 | 库存调整任务，保留原实盘与原流水 |
| 任务重做 | 任务回到待作业，工序单状态回退，不新增节点 |

图上不画回边、不画「驳回」节点，避免与工序的正向拓扑混在一起。

## 7. 与工序单、任务的关系

- 一个节点按 `groupBasis` 生成零到多张工序单；节点与工序单是一对多，不是一对一。
- 一条工序单拆多张任务，拆分维度取 `splitDim`，任务行上记差异。
- 工序单状态由任务状态聚合；节点状态由该节点下的工序单聚合，用于判断下游节点是否就绪。
- 节点被跳过时，工序单状态置已取消，下游节点的 `preNodes` 视同满足。

## 8. 界面结构

`resource/workflow-list` 保持列表页，行操作打开加宽的编排抽屉。

**列表页**：编排编号、单据类型、货主、品类、版本号、编排状态、工序数、更新时间、更新人。筛选取单据类型、货主、品类、编排状态；工具栏「新增」「从现有复制」「导出」。

**编排抽屉**分三段，从上到下：

1. 抬头：编排编号、单据类型、货主、品类、版本号、编排状态、发布人、发布时间。
2. 拓扑图：`DagGraph` 渲染，节点按层纵向排布，同层分支横排；节点内只放工序名、执行主体、状态点；边上带分支类型与条件摘要。
3. 节点属性表：列出全部节点的完整配置，点图中的节点高亮对应行。

图与属性表的联动用纯 CSS 实现：`DagGraph` 生成一组隐藏 radio，每个节点是 label，属性表每行按 `:checked` 高亮。不写 `<script>`，不碰外壳脚本，页面模块只传配置。

## 9. 落地约束

1. `DagGraph` 属于组件白名单新增项，顺序是：先改 `references/implementation.md` 第 3 节与 `references/shells/admin.md` 的图表约束，再改 `prototypes/shared/ui.mjs`，最后重建五端并跑不带 `--fast` 的全量验收。
2. 只读演示，不做拖拽编辑：增删节点、改依赖、改条件都在列表与表单抽屉里完成，图上不承接编辑动作。
3. 分层由 `layer` 显式给出，组件不做自动布局优化，只做同层排序。
4. 色型只用五种 tone，上色只取 `var(--wx-*)`；边与条件标签用中性灰阶，不用强调色。
5. 分支名、节点类型名、状态名先按 `glossary.md` 第 6 节登记，未登记不得写进页面。
6. 环检测、条件求值、节点就绪判定属演示口径，不写构建期状态机；页面用演示数据与纯函数表达。

## 10. 待确认

1. 编排节点上限：单张编排的节点数上限是否限定（建议 20 个），超过时如何提示。
2. 条件字段清单是否够用：单据属性、商品属性、货主属性三类是否需要补其他来源。
3. 货主下发盘点的差异确认入口放在委托单据中心还是差异与异常协同，两处是否需要互链。
4. 库存账册的分层与库位表达另开专项，不在本设计范围内。
