# 货灵WMS三模块设计方案（参照 proto-next）

**目标读者**：产品、原型维护人、研发。
**核心目的**：参照 `proto-next` PC 原型的「仓库单据 / 单仓配置 / 任务中心」三段，定货灵WMS的功能范围、页面组成、数据流转与界面结构，作为原型落地依据。
**前提**：独立部署、单一运营主体；货主是业务实体，不是租户。端名与端数以 `prototypes/shared/modules.json` 的 `apps[]` 为准，仍是货灵ERP、货灵运营中台管理端、货灵WMS、货灵商城四个端；`humanfile/` 是只读草稿。字段真值见 `docs/数据字典/`，文案见 `.codebuddy/skills/huoling-proto/references/glossary.md`，装配见 `prototypes/shared/modules.json`。

**本文使用规则**：本文只定设计口径，不另起页面清单。逐页映射复用 [原型同步方案.md](原型同步方案.md) 第 3、4 节，分批复用 [端定位补齐方案.md](端定位补齐方案.md) 第 3.2 节与 A~E 批，功能范围以 [三端核心功能清单.md](三端核心功能清单.md) 的货灵WMS条目为准。页面名、列名、状态中文名一律先按 `glossary.md` 第 6 节登记；本文未登记的名称均为拟名，登记前不得写进页面。

## 1. 参照对象与一致性基线

`proto-next` 的 PC 端把 8 个一级分组、59 页全渲染进一份 `dist/pc.html`，靠 hash 切页。「仓储库存」下三个二级段由 `pc/src/menu.mjs` 的 `SCOPED_SECTIONS = {'conf','docs','task'}` 标为按仓切：页头「仓库」下拉只在这三段生效，`shell/warehouse-scope.js` 过滤带 `[data-wh]` 的行；判据是「这行数据属不属于某一座具体的仓」。三段共用 `shared/data/` 的 47 份 JSON 与 `shared/doc-status.mjs` 状态机。

| 段 key | 名称 | 页数 | 定位 |
| --- | --- | --- | --- |
| `conf` | 单仓配置 | 9 | 本仓作业资源台账与作业规则，决定「谁能做、在哪做、按什么顺序做」 |
| `docs` | 仓库单据 | 8 | 本仓 L1 单据主档、承诺交付与工序卡点 |
| `task` | 任务中心 | 7 | L3 作业任务台账、负载看板与派工执行反馈 |

保持一致的三个层次：

| 层次 | 一致的内容 | 本项目落点 |
| --- | --- | --- |
| 能力域 | 单据受理与跟踪、本仓配置、任务派工三段分立，互不替代 | 第 2 节 |
| 页面职责 | 一页一事；列表=状态页签＋筛选＋工具条＋表格，看板=汇总与卡点，扫码=单据/任务上下文 | 第 6 节 |
| 数据链 | L1 计划单 → L2 工序单（收货 / 上架 / 拣货 / 复核 / 交接…）→ L3 任务 → 库存账；工序单由单仓生成，波次是拣货的排程容器；状态由任务聚合 | 第 4 节 |
| 分层口径 | 这里的 L1 指单仓执行层视图；L0 委托层在货灵ERP与运营中台，字段见 `入库计划单.md` / `出库计划单.md`。分发到仓后沿用同一 `planNo`，执行层字段见 `入库通知单.md` / `出库订单.md`。两层是同一票单据的字段分表，不是两张单据 | 第 4 节、数据字典 |

不一致的部分集中在装配形态、业务口径与技术实现，逐条列在第 8 节，不改动上述业务结构。

## 2. 模块划分

**模块＝源组织单元，端＝交付单元**（`references/registry.md` 第 1 节）。三段在外部是菜单段，在本项目是**能力域**，不新建三个同名模块：页面仍放在既有模块目录，由注册表 `pages[].app = "warehouse-app"` 决定进货灵WMS产物，`deployed` 决定整块是否装配。端 id 统一带 `-app` 后缀（`owner-app` / `network-app` / `warehouse-app` / `mall-app`），不与模块 ID 同名。

| 能力域 | 承载模块 | 边界 |
| --- | --- | --- |
| 仓库单据 | `inbound`、`outbound`、`warehouse`，聚合视图归 `task` | 本仓入库通知单、出库订单、移库/补货/盘点/上架单的受理、执行跟踪、差异与逆向闭环；不做采购单、电商订单、结算，跨仓单据归货灵运营中台管理端 |
| 单仓配置 | `resource`，库区库位归 `warehouse`，账实参数归 `inventory` | 本仓容器、设备、执行单元、班组、人员、排班台账与策略、工序编排、派工规则；档案主档与仓库级配置由货灵运营中台管理端建档下发，货灵WMS只做本仓实例、绑定、启停与排班 |
| 任务中心 | `task`（聚合视图）＋ `inbound` / `outbound` / `warehouse`（各链任务源） | L3 任务的聚合、派工、执行反馈与负载看板；`task` 只作视图，不持有业务源、不复制其它模块的任务数据 |

三段之外，`inventory` 的本仓明细（仓位库存、批次效期、日清检查、初始库存、库存调整任务、库存快照）是货灵WMS的账实层，作为数据链的终点与库存真相，不并入三段。按 [端定位补齐方案.md](端定位补齐方案.md) 第 3.2 节，任务派工层／单据执行层／账实层／设备执行层是功能分层描述，不是四套页面清单。

**侧栏呈现**：按 `references/shells/admin.md` 第 3 节，货灵WMS是双栏导航：注册表 `apps[].nav` 配十一段作业动线，`apps[].rail` 把段归并为六个业务域，首栏放域、面板按段分组列页。段名取 `glossary.md` 第 2 节的货灵WMS导航段名，条目文案仍取 `pages[].name`；页面源仍按模块目录存放，页面归属不改。面板同一时刻只显示当前域，段在面板内全部展开。三段仍用于功能划分与验收分组，不改写页面归属。

**现状基线**：2026-11-07 货灵WMS产物已含 31 页——本仓商品查询与批次效期 2 页、任务中心 3 页（作业任务、作业看板、单据总览）、入库 3 页（入库计划单、收货单、上架单；计划单详情与工序单详情为列表行抽屉）、出库 5 页（出库计划单、拣货单、复核单、交接单、波次计划）、仓储 4 页（库区库位、移库任务、盘点任务、补货任务）、库存本仓 6 页（批次效期、仓位库存、日清检查、初始库存、库存调整任务、库存快照）、作业资源 9 页（容器管理、设备、执行单元、班组、人员、排班、策略管理、单据工序编排、任务中心策略）。收货验收、拣货作业、盘点作业三个扫码屏归 `pda-app`（PDA 作业端 14 页），货灵WMS不渲染手机屏。14 个模块全部参与装配，仍为预留的只有 `system` 账号管理与角色权限 2 页。

## 4. 数据流转

### 4.1 三层数据链

主链是 **L0 计划单 → L1 执行单 → L2 工序单 → L3 任务 → 库存账**。L0 由货主建、运营中台确认后分发进仓，原单不改编号；L1 是入库通知单与出库订单，沿用 `planNo`，一票一仓，货灵WMS只接已分发单据，看不到草稿与待确认；L2 由单仓按单据工序编排生成，一道工序一张，分组依据按工序不同（收货按到货批次、上架按目标库区、拣货按波次、盘点按盘点计划与库位段）；波次是拣货的排程容器，不是工序单。库内链从内部计划单据起步，不经 L0：盘点由仓网下发、货主下发、单仓自建或日常盘点发起，移库与补货由策略触发或人工建。配置链从旁决定走哪些工序、节点何时就绪、怎么派工。

波次不是「把订单合并」，是作业时段的产能切片：一个波次 = 一个时间窗口 + 该窗口能消化的作业量上限（订单数、明细行数或件数）。订单是排进波次，排得进的前提是该波次还有余量；容量由当班可用执行单元的处理能力与班组出勤人数派生，超限则拆波或顺延。

| 关联 | 外部字段 | 本项目落地 |
| --- | --- | --- |
| 单据 → 编排 | `flowRef.flowId` / `version` → `task-flows` | 单据行带 `sourceDocNo`，编排与工步落在 `resource/data/*.json` |
| 单据 → 工序/波次 | `waveNo` / `arrivalWindowNo` ↔ `batchNo`、`processOrderNo` | `wave-list` 的波次号、任务行的 `sourceDocNo` |
| 任务 → 单据明细行 | `taskId × docNo × lineNo × allocQty` | 任务页保留「来源单据号、商品编码、计划数量、已做数量」，由页面派生列算进度 |
| 任务 → 库位/容器/执行单元 | `targetLocation` / `containerCode` / `execUnitLabel` / `unitId` | 字段取 `库区库位.md`、`容器档案.md`、`执行单元档案.md`；容器占用由 `bizNo` 指向单据，作业完成释放 |
| 任务 → 策略 | `matchedStrategy` | 策略页的编码/名称与任务行的命中策略字段对应 |
| 库存账 | `inventory-stock` / `inventory-flows` | `inventory` 本仓明细与库存台账，是任务完成后的账实终点 |

数据落地方式：一页一个 `data/<页key>.json`，行字段小写驼峰、与 `columns[].key` 同名；货主、商品、仓库、批次等外键取 `shared/data/` 共享主档，构建期做一致性断言；派生列（进度、剩余天数、差异）写成页面内纯函数，不往 JSON 加展示字段。**不搬** `page-defs.json`（3.8 MB）、`bins.json`（34.78 MB）、`doc-status.mjs` 与 `verify-*.mjs` 派生脚本，也不整库复制演示数据。

### 4.2 状态流转与聚合

状态中文名与色型逐字取 `glossary.md` 第 3 节：单据状态 `pending` 待处理 / `doing` 进行中 / `exception` 异常待处理 / `completed` 已完成 / `cancelled` 已取消；作业状态 `wait` 待作业 / `busy` 作业中 / `blocked` 异常 / `done` 已完成 / `closed` 已取消。`StatusTag` 只用 `disabled` / `enabled` / `info` / `pending` / `rejected` 五种 tone。

保留三条聚合规则，补一条盘点差异规则，用演示数据与派生列表达，不做构建期状态机：

1. **工序单据状态 = 其下任务状态聚合**：任务全 `done` 才已完成，出现 `blocked` 即异常待处理。
2. **出库单据状态 = 任务聚合**：拣货、复核、交接任务全部完成才置已完成；取消请求未闭环停在「进行中」并展示返仓中。
3. **入库单据状态 = 数量口径**：按 `qtyExpected` / `qtyReceived` / 到货次数派生，与任务状态无关；差异输出短收、待收、拒收。
4. **盘点差异 = 任务行差异汇总**：任务行记账面数与实盘数，盘点单汇总差异行；仓内主管复核后交货主确认，确认才生成库存调整任务。

**差异只有一条回流路径**：任务行登记差异（商品 × 批次：账面数、实盘数、差异数、差异原因），向上汇总到工序单、执行单与计划单；货主与仓网在计划单上看结论。货灵WMS不建独立差异页面，差异异常单降级为由任务派生的协同台账。盘点的计划单据在仓内自建，货主看不到，因此盘点差异走委托单据中心回报并由货主确认。

外部的入库 6 态、出库 7 态、工序 4 态、SLA 三态统一收敛到上述两组 5 值，不另立枚举；SLA 临期与超期以列值展示，不占状态页签。

### 4.3 配置驱动作业

单据工序编排 → 工序库与工步 → 任务拆分维度、尾差归集、缓冲节点、数量守恒 → 派工权重（负荷／区域／连续性／排队／班次）→ 执行单元承接任务类型与人员资质。配置层对象不带仓维度：外部用 `config-scope.mjs` 在构建期从引用链派生适用仓，本项目按「货灵WMS即一座仓」直接落在本仓配置页，行带 `data-owner` 表达货主维度，不搬派生链。

### 4.4 单仓数据范围

外部：页头「仓库」下拉切换 8 个实体仓，`[data-wh]` 行过滤。本项目：货灵WMS产物就是一座仓，不提供仓库下拉、不提供主体切换器；顶栏「货主」下拉 + 行上 `data-owner` 表达多货主业务维度（仅货灵运营中台管理端、货灵WMS允许），跨仓数据归货灵运营中台管理端，货灵ERP按登录身份限定数据。

## 5. 关键流程

三条链共用「单据 → 任务 → 库存账」骨架，逐步骤列出异常分支与逆向回路；状态名取 `glossary.md` 第 3 节。

| 链 | 步骤 | 输入 | 产出／状态 | 异常分支（触发 → 动作 → 归宿） | 逆向 |
| --- | --- | --- | --- | --- | --- |
| 入库 | 1 委托受理 | 货主入库委托 | 入库通知单 `pending` | 必填缺失／商品未发布／仓库不支持该作业类型 → 驳回并留痕 → 退回委托 | 未收货前可取消至 `cancelled` |
| 入库 | 2 到货登记 | 通知单、到货月台 | 到货次数、预计到货时间 | 无单到货／重复登记 → 挂起并登记异常 → 待人工确认 | 撤销登记，通知单回 `pending` |
| 入库 | 3 收货验收 | 通知单明细、扫码 | 批次、实收／拒收、差异 | 短收、超量、批次或效期不符、跨货主串货、扫码故障 → 拒收或挂起、登记差异、告警 → `exception`；零条或多条条码命中判异常，不取其它货主主档 | 错收冲销入库台账，走退仓逆向单据 |
| 入库 | 4 上架 | 上架任务、推荐库位 | 目标库位、上架数量 | 库位占用／容器冲突／执行单元不匹配 → 改派或改库位 → 任务回 `wait` | 反上架回退库存与库位占用，留原单据行 |
| 入库 | 5 记账 | 实收、上架结果 | 库存台账、批次效期 | 数量不守恒 → 拦截并登记差异 | 已记账用调整任务冲正，不删原流水 |
| 出库 | 1 受理 | 货主出库委托、商城订单 | 出库订单 `pending` | 库存不足／禁售过期批次／货主资质不符 → 驳回 → 退回委托 | 未释放前可取消 |
| 出库 | 2 波次与分配 | 订单、截单时间 | 波次计划、锁库 | 波次容量超限／并发占用 → 拆波或转人工 → 回待分配 | 释放波次、解锁库存 |
| 出库 | 3 拣货复核 | 拣货任务、扫码 | 已拣数量、包裹 | 拣货差异、错拣跨货主、设备与扫码故障 → 登记异常、挂起 → `blocked` | 部分完成后发起取消，走返仓回上架 |
| 出库 | 4 发货交接 | 包裹、承运商 | 交接单、运单 | 交接数量不符／运单失败 → 挂起并重试 → 回 `busy` | 逆向交接：退货、退仓入库，原出库单不删 |
| 出库 | 5 完成 | 交接回单 | 单据 `completed`、库存扣减 | 回单缺失 → 保持 `doing` 并告警 | 已完成为不可逆终态，只能走退货逆向单 |
| 盘点 | 1 计划发起 | 仓网下发 / 货主下发 / 单仓自建 / 日常盘点 | 盘点计划 `pending` | 范围为空、同仓同范围已有在办计划、货主对非自有商品发起 → 驳回并告知 → 回发起方 | 未受理前可撤回 |
| 盘点 | 2 受理排期 | 计划、当班人力、库区占用 | 计划 `accepted` → `effective` | 无可用执行单元、库区被占用、货主期望日期不可行 → 改期或驳回 → 计划回 `pending` | 已生效不可撤回，只能取消并留痕 |
| 盘点 | 3 执行与差异 | 盘点单、盘点任务、实盘 | 任务行差异、盘点单汇总 | 盲盘差异超阈值、重复盘同一库位、账实不符 → 挂起复核 → 盘点单 `exception` | 二次盘点回初盘，原实盘与原任务行保留 |
| 盘点 | 4 确认与调账 | 差异、仓内复核、货主确认 | 库存调整任务、台账冲正 | 货主申诉未闭环、复核驳回 → 挂起不调账 → 差异 `handling` | 调账后冲正走调整任务，不删原流水 |
| 库内 | 1 生成单据 | 策略触发／人工 | 移库单、补货单 | 触发条件不满足／重复生成 → 拦截并留痕 | 未审核前撤回 |
| 库内 | 2 拆任务与执行 | 编排、拆分维度、派工权重 | 移库／补货任务、实移数量 | 无可用执行单元、人员无资质、班次缺员 → 转人工派工；目标库位冲突、容器占用超时 → 挂起登记异常 | 差异复盘，撤销派工回 `wait` |
| 库内 | 3 记账 | 执行结果 | 库存调整、台账流水 | 数量不守恒 → 拦截并登记差异 | 调整任务冲正，保留原流水 |

**不可逆与留痕**：已完成且已记账的单据、已交接的出库单、已确认并记账的盘点差异为不可逆终态，只能新建逆向单据（退货、退仓、冲销、调整任务）处理；取消、撤回、反审核、返仓、退货都保留原单据行、任务行、扫码原值、货主、批次与时间戳，不物理删除。异常处置一律写明触发条件、处理动作与归宿状态，不留悬空分支。

## 6. 界面结构说明

### 6.1 外壳与导航

货灵WMS用 `admin` 外壳（`wx-app`）：双栏导航，首栏为品牌字标、六个业务域、帮助、通知与账号会话，面板为端名、产品名、本域搜索与段内页面，条目文案取 `pages[].name`；不生成跨端或跨模块链接。不出现顶栏、页头页签、仓库下拉、货主下拉、主体切换器、租户相关控件；货主维度只在列表筛选区收窄。

### 6.2 五类骨架分工

| 骨架 | 三段里的页面 | 结构 |
| --- | --- | --- |
| `list` | 全部单据台账、任务台账、9 页配置、波次计划、库区库位 | `statusTabs → filters → toolbar → table → pager`；计数放 `statusTabs` 的 count，不加统计卡片与页内大标题，不写自绘筛选栏 |
| `detail`（仅抽屉内容） | 入库通知单详情、工序单详情、盘点计划详情、单据工序编排 | `DrawerDetail` → `DetailPage`，按抬头字段、明细行、操作轨迹组织；不注册独立页面。编排抽屉额外嵌入 `DagGraph` 与节点属性表，图与表用纯 CSS 联动 |
| `report` | 单据总览、作业看板 | `ReportHero + StatRow + Block`，展示在办合计、异常与超期、工序节点负载、窗口告警 |
| `scan` | 收货验收、拣货作业、盘点作业 | `ScanPage`；先有单据或任务上下文（单号、货主、操作员、设备、库位），再扫商品与批次 |
| `shop` | 不用于货灵WMS | 只给 `shell = "mall"` 的货灵商城 |

### 6.3 页内结构

- **单据／任务列表页**：状态页签取第 3 节枚举，首个为「全部」，其余页签必须带 `field` + `value` 真筛；筛选项的 select 选项从行数据派生；数字列右对齐；工具条按状态显隐主操作（提交审核、审核通过、批量确认、批量异常登记、取消）；行上挂 `data-owner` 与状态字段。单据与任务合页的页面以任务执行为主视角，来源单据号作为一列。入库通知单、收货单、出库订单的操作列都放「查看详情」，详情以 `DrawerDetail` 抽屉呈现，明细与轨迹按行主键取列表页 `details`。
- **配置页**：一页一表，状态页签取 `作业资源状态` 枚举；外部「左栏清单＋右栏详情」「页内多视图」一律收敛为列表页加关键字段列，不引入 `data-view-panel`。
- **报表页**：允许 `ReportHero` 与 `StatRow`，口径说明用 `tipKey` 进 `title`，不把解释性长句摆到版面上。
- **扫码页**：对象摘要含第 N 行、货主、商品编码、批次；PDA 次操作「下一件」、主操作「确认」。

### 6.4 交互驱动对照

| 外部 | 本项目 | 说明 |
| --- | --- | --- |
| hash 路由 + `[data-ctx]` 三级页签 | 页头页签切页 + `data-*` 属性 | 端产物仍是一份 HTML，按页显隐 |
| `[data-wh]` + 页头仓库下拉 | `data-owner` + 顶栏货主下拉 | 仓库维度由端本身限定 |
| `[data-doc]` 单据详情抽屉 | 列表操作列 + `DrawerDetail` 面板挂 `.wx-overlay` | 抽屉随列表行下钻，切页自动关闭，不注册独立 `detail` 页 |
| `[data-view-panel]` 页内多视图 | 拆成独立页或一页主表 | 骨架不许混搭 |
| `[data-status-tab]` + `data-<field>` | `statusTabs` 的 `field` + `value` | 页签必须真筛 |
| `[data-toast]` 原型示意 | `data-toast`，文案「动作名（原型示意）」 | 取 `glossary.md` 第 5 节 |

所有可见文字（页面名、页签、列名、按钮、状态、空态、分页单位）逐字取 `glossary.md`；`StatusTag` 与 `StatRow` 的取值不超出第 3 节枚举；页面模块只写 `columns` / `rows` / `filters` / `toolbar`，只 import `../../shared/ui.mjs`，不写 `<script>`、不写死 hex、不跨模块 import。

## 9. 落地约束与待确认项
