# 计划单与时效协议方案（3PL 云仓）

> 状态：草案｜日期：2026-11-06
> 字段真值源：[入库计划单](../数据字典/入库计划单.md)、[出库计划单](../数据字典/出库计划单.md)、[时效协议](../数据字典/时效协议.md)
> 关联：[原型同步方案.md](原型同步方案.md) 第 4 节逐页映射、[端定位补齐方案.md](端定位补齐方案.md) 第 3 节拟名清单

## 1. 要解决的问题

现状的单据链是「货主建单 → 仓直接执行」：货主端的入库委托、出库委托直接就是入库通知单与出库订单，中间没有确认环节。三个缺口：

1. 货主提交的计划直接变仓的作业单据，仓网端没有确认入口，无法拒单、改期、改量。
2. 各仓对同一货主的时效承诺不同（华东次日、华南隔日），系统里没有落点，单据也没有时效约束。
3. 出库从下单到分配之间库存是敞开的，别的单可以抢先占用，货主承诺出去的货锁不住。

## 2. 单据层级

```
L1 计划单（货主建，一票一仓）── 仓网端确认 ── 推送目标仓
        ↓  单仓生成，1:N
L2 工序单：收货单 / 上架单 / 拣货单 / 复核单 / 交接单 ……
        ↓  拆分
L3 任务：派给人员或设备
```

**三道层的分工是：谁要货、货怎么组织、谁来做。**

- L1 计划单回答「货主要什么、仓网确认了没有」，一票一仓，确认后原单推送进目标仓，**编号不变，不再另开一张通知单**。
- L2 工序单回答「这批货在仓内怎么组织」，由**单仓自己生成**，一道工序一张。分组依据按工序不同：收货按到货批次合、上架按目标库区合、拣货按作业时段（波次）合。一张工序单可跨多张计划单。
- L3 任务回答「这一份活谁做、在哪做、做多少」，由工序单拆分，一份任务只归一个执行主体——人员或设备。

工序类型可扩：质检、贴标、打托、拆零等只要加枚举与一张页，模型不动。见 [工序单.md](../数据字典/工序单.md) 第 5 节。

波次不是工序单，是拣货工序的排程容器：一个波次 = 一个时间窗口 + 该窗口能消化的作业量上限，容量由当班执行单元处理能力与班组出勤人数派生。订单是被排进波次，排得进的前提是那个波次还有余量；拣货单是波次内实际执行的工序单据。

数量口径：工序单的已完成数量由任务汇总，计划单的已收与已上架进度由工序单汇总——三层各算各的，不互相改写。

计划单与作业单据字段不同，所以是两张表而不是一张：计划单管「预约了什么、确认了没有、锁没锁住」，作业单据管「收了多少、差多少、作业到哪一步」。一批计划可能分批到货、有短溢，作业数据不该回写货主的计划单。

## 3. 计划单状态机

| 值 | 中文 | tone | 进入条件 | 可做动作 |
| --- | --- | --- | --- | --- |
| `draft` | 草稿 | `disabled` | 货主保存未提交 | 编辑、提交、删除 |
| `pending` | 待确认 | `pending` | 货主提交，等仓网端确认；自动确认模式下直接进 `confirmed` | 确认、驳回、改期改量、改仓 |
| `confirmed` | 已生效 | `enabled` | 仓网端确认（人工或系统） | 查看通知单、关闭 |
| `dispatched` | 已分发 | `info` | 系统已把本票落成作业单据 | 查看通知单 |
| `closed` | 已关闭 | `disabled` | 货主或仓网端关闭 | — |

`confirmed` 与 `dispatched` 在一次操作内连续发生：确认通过就下发，下发成功即转已分发。`confirmed` 只在人工确认后下发失败时停留，属异常态。

## 4. 下发规则

1. 确认即下发，1:1 落一张作业单据。自动确认＝提交即确认即下发；人工确认＝仓网端点确认后下发。没有第三个对象，也没有单独的「分发」按钮。
2. 下发时按「仓 × 货主 × 业务类型」取当刻生效的时效协议，快照 `slaCode`、`slaDueTime`、`slaStatus` 到作业单据。之后协议改版不影响在途单据。
3. 目标仓能力校验放在**确认时**，不放下发时：一票一仓，一次校验就够。要质检而该仓 `qcMode=无`、温区不匹配时不能确认；增值作业不在 `valueAddedServices` 内时提示，需二次确认。
4. 确认后不允许改仓，作业单据已生成。要改仓只能驳回退回 `pending` 后重提；出库单改仓需先释放锁定再按新仓重锁。
5. 作业单据取消不回滚计划单状态，计划单保持 `dispatched`，取消原因记在作业单据上，货主另行提交新的计划单。

## 5. 出库锁库

出库计划单**提交即锁库**，不等出库订单分配。理由：货主已经承诺出去的货，不能让别的单先占。

| 时机 | 动作 |
| --- | --- |
| 提交 | 按「商品 × 批次 × 仓」全量校验可用量并冻结，`lockStatus` 转已锁 |
| 可用量不足 | 不允许提交，提示可锁量与缺口，货主改量或补货后重提；系统不保存部分锁定 |
| 改量 | 差额补锁或释放 |
| 确认 | 锁定延续，不重复锁 |
| 下发为订单 | 锁定量随订单拣货出库扣减 |
| 关闭、驳回、删草稿 | 释放全部锁定，转已释放 |

锁库不写台账，台账只记变动；冻结体现在库存查询与仓位库存的冻结数量列，与盘点冻结同一口径。

## 6. 时效协议

按「仓 × 货主 × 业务类型」一行一条，**入库与出库分开签**，互不覆盖。属于仓网端对货主的作业承诺。

与承运商主档的 SLA 不合并：承运商侧考核准点率与破损率，属运输成本侧；本协议约束仓内作业时效，属服务水平侧。

| 口径 | 入库 | 出库 |
| --- | --- | --- |
| 作业时效 | 到货签收后 N 小时上架完成 | 截单后 N 小时发货交接完成 |
| 截单时间 | 不适用 | 每日截单时刻，按仓作业时段取 |
| 准确率目标 | 不适用 | 拣货准确率百分比 |
| 异常响应 | 异常登记后 N 小时首次响应 | 同左 |

作业单据侧落三个字段：`slaCode` 协议编号、`slaDueTime` 应完成时间、`slaStatus` 正常 / 临期 / 超期（按当前时间比对派生）。`slaStatus` 只作列值与行样式，不占状态页签，不与单据 5 态混用。
