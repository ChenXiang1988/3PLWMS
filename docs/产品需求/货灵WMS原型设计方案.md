# 货灵 WMS 产品原型设计方案

**状态**：草案｜**版本**：V1.0｜**编制日期**：2026-11-11  
**适用范围**：`prototypes/` 的货灵 WMS（`warehouse-app`）原型设计、评审与后续迭代。  
**目标读者**：产品经理、原型维护人、仓库运营负责人、WES/WCS 方案设计人、设备集成人员、研发评审人。

> 本方案只定义货灵 WMS 的产品边界、信息架构、页面职责、数据对象、交互骨架与分批实施口径，不改后端接口、数据库或真实前端工程。后续改动 `prototypes/` 前，仍须按 `.codebuddy/skills/huoling-proto/SKILL.md` 与「跨端联动确认」规则执行。

## 1. 方案目标与设计结论

### 1.1 产品定位

货灵 WMS 是货灵供应链运营平台的仓内执行端，覆盖三类能力：

- **WMS**：管理仓内业务单据、货物、库位、库存和作业结果，形成可追溯的业务事实。
- **WES**：管理作业需求如何拆分、排序、组批、派工、重排和协同，形成可执行的任务网络。
- **WCS**：管理自动化设备如何接收任务、执行动作、回传状态、处理故障和恢复，形成设备执行闭环。
- **集成治理**：管理 ERP、OMS、TMS、承运商、WCS 与外部设备厂商之间的连接、映射、消息可靠性和对账。

四类能力在产品上不是四个互相割裂的系统菜单，而是同一条仓内执行链的四层：

```text
业务单据与库存事实（WMS）
        ↓ 生成作业需求
任务拆分、波次、派工、重排（WES）
        ↓ 生成设备执行任务
指令、路由、回执、设备状态（WCS）
        ↓ 回写执行结果
单据、任务、库存、异常与审计（WMS + 集成治理）
```

### 1.2 总体设计结论

1. **不把 WMS、WES、WCS 直接拆成三个一级菜单。** 仓库人员按入库、出库、任务、库存和设备工作；理论分层通过页面职责、对象边界和状态字段体现。
2. **保留现有六个首栏业务域**：任务中心、入库、出库与发货、库内作业、库存与资源、人员与配置。它们符合当前 `warehouse-app` 的双栏后台外壳和仓内动线。
3. **保留现有十一段导航作为 V1 页面组织基础**，通过页面扩充、抽屉和任务/设备详情补齐 WES、WCS 和集成治理能力；不在本方案阶段直接修改注册表。
4. **WMS 负责业务事实，WES 负责执行编排，WCS 负责设备执行，集成治理负责边界可靠性。** 业务页面不得直接依赖厂商私有字段。
5. **状态必须分离**：单据状态、工序状态、任务状态、设备状态、接口状态和异常状态不能复用一个通用 `status`。
6. **库存变化只有一个账务入口**：收货、上架、拣货、移库、盘点、调整、加工和逆向动作都必须携带来源单据、来源任务、变动类型、操作人和时间。
7. **所有危险动作可追溯、可解释、可逆性明确**：取消、强制完成、手工确认设备结果、库存调整、冻结解冻和人工补偿都要记录原因与影响范围。

### 1.3 本方案不解决的问题

- 不设计后端 API、数据库表、消息中间件的具体技术实现。
- 不替代货灵 ERP 的订单、采购、售后和利润核算设计。
- 不替代货灵运营中台管理端的跨仓调度、仓网档案、货主服务关系和结算设计。
- 不把设备厂商的 PLC、机器人控制器、AGV 云平台私有页面完整搬入货灵 WMS；WMS 只呈现业务所需的设备状态、任务结果和运维入口。
- 不在 WMS 内建设租户、订阅、套餐或平台运营后台。

#### 库内作业与盘点异常：11 页

`warehouse/location-list` 库区库位、`warehouse/location-capacity` 库位容量与 ABC、`warehouse/move-task` 移库任务、`warehouse/replenish-task` 补货任务、`warehouse/kitting-task` 组套与库内加工、`warehouse/freeze-list` 冻结与解冻、`warehouse/count-plan` 盘点计划、`warehouse/count-task` 盘点单、`inventory/count-diff-audit` 盘点差异审批、`inventory/adjust-task` 库存调整任务、`warehouse/wh-exception-list` 异常登记与处置。

这组页面已覆盖库内账实和异常闭环的基础形态。后续重点不是再建一个“差异主档”，而是把差异来源、审批、调整任务和台账流水串成单一入口。

#### 库存中心：6 页

`inventory/batch-list` 批次效期、`inventory/stock-by-location` 仓位库存、`inventory/daily-check` 日清检查、`inventory/opening-stock` 初始库存、`inventory/stock-snapshot` 库存快照、`inventory/serial-list` 序列号追踪。

库存中心需要补齐可用量、分配量、冻结量、待检量、锁定来源、流水来源、货主、批次、效期和序列号的联合追溯；库存查询、库存台账和跨仓库存仍分别属于运营中台或货灵 ERP，不搬到 WMS。

#### 设备与容器：7 页

`resource/container-list` 容器管理、`resource/hardware-list` 设备、`resource/exec-unit-list` 执行单元、`resource/device-monitor` 设备监控、`resource/device-alarm` 告警与故障工单、`resource/device-driver` 驱动与协议、`resource/agv-strategy` AGV 调度策略。

这是 WCS 的基础骨架，但还缺少设备能力模型、仓库拓扑、设备任务队列、指令/回执流水、厂商连接器、消息重试/死信/补发和设备任务与业务任务的关联链路。

#### 人员与作业配置：8 页

`resource/team-list` 班组、`resource/staff-list` 人员、`resource/shift-list` 排班、`task/staff-performance` 人效与准确率、`resource/strategy-list` 策略管理、`resource/workflow-list` 单据工序编排、`resource/task-strategy-list` 任务中心策略、`base/sku-warehouse-list` 本仓商品查询。

这组页面承担 WES 的资源与规则基础，但需要把策略命中、版本、生效范围、人员资质、工作站能力和自动化资源能力连到任务拆分与派工结果。

## 3. 产品边界与对象模型

### 3.1 四层职责边界

| 层 | 负责什么 | 核心对象 | 不负责什么 |
| --- | --- | --- | --- |
| WMS 业务层 | 业务单据、货物、库位、库存、作业结果 | 入库通知单、出库订单、工序单、库存余额、库存流水、容器 | 不直接处理厂商协议，不替代 ERP 订单和跨仓调度 |
| WES 编排层 | 需求拆分、工序依赖、波次、任务、优先级、派工、重排 | 作业需求、任务、任务组、波次、资源、工序 DAG、SLA | 不直接发送 PLC/AGV 私有指令 |
| WCS 执行层 | 设备能力、路由、指令、回执、状态、故障和恢复 | 设备、控制点、设备任务、指令、回执、告警、路由 | 不改变业务单据规则，不直接决定库存可用量 |
| 集成治理层 | 外部连接、协议适配、字段映射、消息可靠性、对账审计 | 连接器、接口、消息、映射、重试、死信、补发、对账 | 不成为业务单据主档，不复制设备业务逻辑 |

### 3.2 WMS/WES/WCS 的对象关系

| 对象 | 产生方 | 消费方 | 原型必须能看到的关联 |
| --- | --- | --- | --- |
| 业务单据 | ERP、运营中台、WMS 内部 | WMS、WES | 单据号、货主、来源单号、承诺时间、单据状态 |
| 工序单 | WMS 按工序编排生成 | WES、PDA、WCS | 工序单号、工序类型、前置工序、数量、状态 |
| 作业任务 | WES 从工序单拆分 | PDA、WCS、调度员 | 任务号、来源单据号、任务类型、数量、执行单元、任务状态 |
| 波次/任务组 | WES 生成 | 作业任务、出库单 | 波次号、时间窗、容量、订单数、任务数、波次状态 |
| 设备任务 | WCS 由作业任务转换 | 设备厂商适配器 | 设备任务号、业务任务号、指令号、设备、路由、执行状态 |
| 设备回执 | 设备或厂商服务 | WCS、WES、WMS | 回执号、指令号、原始状态、统一状态、发生时间、幂等结果 |
| 库存流水 | WMS 过账 | 库存查询、审计、对账 | 来源单号、来源任务号、变动类型、数量、前后余额、操作人 |
| 异常记录 | WMS/WES/WCS/集成层 | 对应责任人、审批人、报表 | 来源、对象、影响范围、处理动作、结论、关闭时间 |

### 3.3 责任划分判据

遇到新需求时按以下问题归类：

1. **是否改变货物归属、数量、库位或业务单据结果？** 是 → WMS。
2. **是否决定任务拆分、先后顺序、批次组合、资源分配或任务重排？** 是 → WES。
3. **是否涉及设备选型、路由、指令、回执、心跳、故障或人工接管？** 是 → WCS。
4. **是否涉及跨系统连接、厂商协议、消息重试、幂等、补发或对账？** 是 → 集成治理。
5. 同一动作命中多个问题时，页面入口放在最接近操作角色的一层，详情中展示上下游链路，不重复建主档。

## 4. 目标信息架构与菜单

### 4.1 外壳与导航原则

货灵 WMS 继续使用 `admin` 双栏后台外壳：

- 首栏保留六个业务域：**任务中心、入库、出库与发货、库内作业、库存与资源、人员与配置**。
- 面板保留当前十一段作为 V1 组织基础：任务中心、入库管理、出库管理、发货作业、库内作业、盘点与异常、库存中心、设备与容器、人员与班次、作业配置、基础资料。
- 后续新增 WES/WCS/集成页面优先归入现有段，不为“WES”“WCS”单独造理论段；只有页面数量和操作角色足以形成独立动线时，才评审新增导航段。
- 端不提供仓库切换器；货灵 WMS 产物即一座仓。多货主只在需要收窄的列表筛选区出现「货主」筛选。
- 不出现顶栏、页内页签、租户切换、主体切换、套餐、订阅或跨端跳转。ERP、运营中台、PDA 的联动以业务对象和字段契约描述，不在 WMS 页面里做跨端链接。

### 4.2 目标菜单总览

| 业务域 | 导航段 | 目标职责 | 主要角色 |
| --- | --- | --- | --- |
| 任务中心 | 任务中心 | 看全仓作业、任务依赖、负荷、阻塞和派工 | 仓库主管、调度员 |
| 入库 | 入库管理 | 从到货预约到收货、质检、理货、越库、上架 | 收货员、质检员、上架员 |
| 出库与发货 | 出库管理 | 从出库订单、分配、波次到拣货和复核 | 调度员、拣货主管、复核员 |
| 出库与发货 | 发货作业 | 打包、分播、称重、装车、交接和发运回执 | 打包员、发运员、承运商交接员 |
| 库内作业 | 库内作业 | 库区库位、移库、补货、加工、冻结 | 库内主管、库位管理员 |
| 库内作业 | 盘点与异常 | 盘点计划、差异审批、调整、异常处置 | 盘点员、仓库主管、货主协同人 |
| 库存与资源 | 库存中心 | 库存余额、批次效期、序列号、台账、快照 | 库存管理员、仓库主管 |
| 库存与资源 | 设备与容器 | 容器、设备、执行单元、监控、告警和厂商适配 | 设备管理员、自动化主管 |
| 人员与配置 | 人员与班次 | 班组、人员、资质、排班、人效 | 人事/仓内主管 |
| 人员与配置 | 作业配置 | 策略、工序 DAG、任务派工规则、SLA | 仓库配置管理员 |
| 人员与配置 | 基础资料 | 本仓商品和后续本仓作业资源主档入口 | 仓库管理员 |

### 4.3 页面增量的归置规则

新增能力先按以下规则放置：

- **任务依赖、动态派工、超时升级、任务重排** → `任务中心`。
- **库存分配、缺货池、短拣、订单拆分** → `出库管理`，不在任务中心复制订单主档。
- **包装规则、称重、面单、分播、装车、发运回执** → `发货作业`。
- **设备能力、设备任务、路由、指令、回执、人工接管** → `设备与容器`。
- **设备厂商连接器、接口健康、消息流水、重试补发、死信、对账** → 优先归 `设备与容器` 的新增分段或页面抽屉；若后续页面超过 5 页，再评审独立“集成治理”导航段。
- **库存分配结果和库存变更** → `库存中心`；WES/WCS 只展示引用，不拥有第二份库存余额。
- **质量规则和异常原因** → `盘点与异常` 的筛选、抽屉和配置入口，不建重复的“异常主档”。

## 5. 各领域页面设计

### 5.1 任务中心：WES 控制台

#### 页面职责

| 页面 | 目标问题 | 必备字段 | 主操作 |
| --- | --- | --- | --- |

| 作业看板 | 今天的作业量、瓶颈和风险在哪里？ | 时间范围、在办任务、异常任务、超时任务、各工序负荷、设备影响时长、窗口告警 | 进入问题列表 |
| 作业任务 | 每个可执行任务现在由谁、在哪、做了多少？ | 任务号、来源单据号、任务类型、商品、数量、库位、容器、执行单元、作业人、任务状态、阻塞原因 | 领取、开始、暂停、完成、登记异常 |
| 任务池与派工 | 哪些任务待派，派给谁最合适？ | 待派任务、优先级、SLA 截止、区域、前置任务、技能要求、资源负荷、推荐执行单元 | 批量派工、重派、转人工、取消 |
| 拟新增：任务依赖与重排 | 某个前置任务阻塞后，后续任务如何调整？ | 任务组、前置/后置关系、阻塞节点、替代资源、重排版本、影响单据 | 重排、暂停后续、恢复、查看版本 |

#### WES 核心规则

- 任务最小粒度应能被一个人、一个设备或一个工作站独立领取和反馈。
- 任务必须保留 `sourceDocNo`、`sourceLineNo`、`processOrderNo`、`taskId` 的链路，不能只显示一个模糊的“来源”。
- 任务派工需要同时判断区域、技能/资质、执行单元能力、当前负荷、班次和优先级。
- 任务状态与异常标记分离：任务可以是“执行中”且 `exceptionFlag = true`，不能用“异常”覆盖执行状态。
- 自动派工失败时转人工派工；设备不可用时转替代设备或人工任务，保留原任务和改派记录。
- 任务重排必须生成重排版本，旧版本只读；已完成任务不可被重排覆盖。

#### 入库交互规则

- 入库通知单详情抽屉按“抬头 → 明细 → 收货汇总 → 工序/任务轨迹 → 差异”组织。
- 收货确认前必须显示货主、商品、批次、效期和容器上下文；跨货主扫码不允许静默匹配。
- 收货数量、拒收数量和短溢差异必须能回指明细行，不只在单据头显示总数。
- 上架推荐库位由策略产生，实际库位是执行结果；推荐值和实际值不能共用一个字段。
- 收货完成不等于库存可用：待检、合格、不合格和隔离状态必须独立表达。

#### 出库分配与波次规则

- 库存分配是出库订单进入拣货前的独立业务步骤，必须可追溯到分配规则、批次、库位和锁定流水。
- 波次是时间窗口和产能切片，不是简单的订单合并；波次容量由订单量、明细行、件数、可用执行单元和班组产能共同约束。
- 同一波次内可以有多个货主，但任务下发必须保留货主隔离校验；不允许因波次合并发生串货。
- 缺货订单进入缺货/短拣协同状态，不伪装成普通异常；补货完成或库存重新分配后才能继续。

### 5.7 库存中心：库存事实与追溯

库存中心必须围绕八个问题设计：

1. 有多少：账面量、可用量、已分配量、锁定量、冻结量、待检量、在途量。
2. 在哪里：仓库、库区、库位、容器。
3. 属于谁：货主、商品、批次、序列号。
4. 为什么不可用：分配、冻结、待检、破损、过期、异常。
5. 被什么单据占用：来源单据、任务、波次、容器。
6. 何时变化：流水时间、操作人、设备/接口时间。
7. 如何追溯：收货 → 上架 → 移库/加工 → 分配 → 拣货 → 发运。
8. 如何纠正：盘点差异 → 审批 → 调整任务 → 库存流水，不直接编辑余额。

| 页面 | 主字段 |

| 仓位库存 | 货主、商品、批次、库位、容器、可用量、占用量、冻结量、总量 |
| 日清检查 | 检查日、库区、账面总量、现场确认量、差异量、检查人、结论 |
| 初始库存 | 导入批次、来源、货主、商品、库位、数量、校验结果、审批状态 |
| 库存快照 | 快照时间、货主、商品、批次、库位、快照数量、当前数量、差异 |
| 序列号追踪 | 序列号、商品、批次、当前状态、当前库位、来源单、最近动作、轨迹 |

## 6. 数据链路、状态模型与库存过账

### 6.1 主数据链

货灵 WMS 采用以下主链：

**L0 计划单 → L1 仓内执行单 → L2 工序单 → L3 作业任务 → L4 设备任务/人员执行 → 库存流水与业务结果**。

- L0 计划单由货灵 ERP 或运营中台产生，跨端责任不在 WMS。
- L1 在仓内落为入库通知单或出库订单，沿用原 `planNo`，一票一仓。
- L2 由 WMS 根据单据工序编排生成，收货、上架、拣货、复核、交接、盘点各自有工序单。
- L3 由 WES 按拆分维度生成，任务可以分给人员、工作站或设备。
- L4 由 WCS 将设备可执行任务转换为厂商指令；人工任务由 PDA 执行。
- 库存变化只有在业务动作完成并满足数量守恒后过账，设备回执不能绕过 WMS 直接修改库存余额。

### 6.2 统一关联字段

每一层都要保留可追溯的关联，不允许只存一个展示用名称：

| 层 | 必备字段 |
| --- | --- |
| 单据 | `docNo`、`docType`、`sourceNo`、`ownerCode`、`warehouseCode`、`docStatus` |
| 明细 | `lineNo`、`skuCode`、`batchNo`、`serialNo`、`qtyExpected`、`qtyActual` |
| 工序 | `processOrderNo`、`processType`、`flowId`、`flowVersion`、`processStatus` |
| 任务 | `taskId`、`sourceDocNo`、`sourceLineNo`、`taskType`、`taskStatus`、`exceptionFlag` |
| 资源 | `execUnitId`、`operatorId`、`workstationCode`、`deviceCode`、`containerCode` |
| 设备 | `deviceTaskNo`、`commandNo`、`idempotencyKey`、`deviceStatus`、`ackAt` |
| 库存 | `inventoryTxnNo`、`sourceNo`、`sourceTaskNo`、`changeType`、`qtyBefore`、`qtyChange`、`qtyAfter` |
| 审计 | `operator`、`actedAt`、`reason`、`traceId` |

### 6.3 状态模型

#### 单据状态 `docStatus`

沿用当前货灵 WMS 的五值口径：

- `pending` 待处理
- `doing` 进行中
- `exception` 异常待处理
- `completed` 已完成
- `cancelled` 已取消

单据状态由业务规则聚合，不由设备状态直接覆盖。入库以计划量/实收量和异常结果为主要口径；出库以拣货、复核、交接和回执闭环为主要口径。

#### 任务状态 `taskStatus`

- 待作业
- 作业中
- 阻塞
- 已完成
- 已取消

建议在数据层使用独立的 `exceptionFlag`、`blockedReason` 和 `blockedAt` 表达异常原因，不把所有阻塞都写成任务状态。

#### 设备状态 `deviceStatus`

- 离线
- 空闲
- 忙碌
- 故障
- 维护中
- 禁用

设备状态来自心跳、厂商回执和人工维护；不从任务状态推导设备状态。设备忙碌但任务失败、设备在线但未分配任务等情况必须允许存在。

#### 接口状态 `integrationStatus`

- 未连接
- 已连接
- 测试中
- 部分失败
- 已停用

接口状态只表达连接和消息通道健康，不代替业务单据状态或设备状态。

#### 异常状态 `exceptionStatus`

- 待登记
- 待分派
- 处理中
- 待复核
- 已关闭
- 已忽略

“已忽略”必须保留忽略原因和审批人，不能作为删除异常的替代。

### 6.4 库存过账规则

库存变化必须带：`sourceNo`、`sourceTaskNo`、`changeType`、`reason`、`operator`、`actedAt`。

| 业务动作 | 允许的库存结果 | 过账前置 |
| --- | --- | --- |
| 收货 | 增加待检/可用库存，或进入拒收/隔离 | 收货数量、批次、容器和验收结果确认 |
| 上架 | 从收货暂存位转入目标库位 | 实际库位、容器和数量确认 |
| 分配 | 增加已分配量，不改变实物总量 | 分配规则命中、库存锁定成功 |
| 拣货 | 可用量转为拣货中/已拣，完成后进入包裹 | 扫码、库位、批次、数量校验 |
| 交接发运 | 扣减实际发运库存 | 包裹、交接数量、回执或人工确认 |
| 移库 | 源库位减少、目标库位增加 | 源/目标库位和数量守恒 |
| 盘点调整 | 生成调整流水 | 差异审批通过、原因完整 |
| 加工/组套 | 组件扣减、产出增加 | 加工单、BOM、耗用和产出确认 |
| 逆向 | 通过退货/退仓/冲销/调整任务回流 | 原单据保留，逆向单据新建 |

| TMS/承运商 | 发运、运单、交接、轨迹 | 运单号、承运商状态、回执和补发 |
| WCS | 设备任务、执行结果、告警 | 设备任务号、统一状态、失败原因 |
| AS/RS/输送线 | 入库、出库、搬运、缓存 | 设备能力、路由、容器、回执 |
| AGV/AMR | 搬运、取放、充电 | 任务、路径、当前位置、故障和人工接管 |
| 分拣设备 | 分播、格口、滑槽 | 容器/格口、设备任务、结格回执 |
| 现场设备 | 称重、打印、扫码、相机 | 采集值、设备状态、重试和人工补录 |

### 7.2 连接器配置字段

连接器详情抽屉至少包含：

- 连接器编号、厂商名称、系统类型、设备类型。
- 接入方式、协议名称、协议版本、地址、端口、环境。
- 鉴权方式、凭证引用、证书状态；敏感值只展示脱敏结果。
- 能力清单：收货、上架、搬运、拣货、分拣、称重、打印、告警等。
- 心跳间隔、连接超时、响应超时、重试次数、退避策略。
- 幂等规则、回调地址、签名校验、请求/响应编码。
- 状态码映射、错误码映射、业务事件映射。
- 适用设备、适用库区、启停状态、版本、生效时间。
- 最近连接时间、最近调用时间、成功率、失败数、待处理消息数。

### 7.3 指令执行闭环

一条设备动作必须能够通过以下关联查询：

**来源单据 → 工序单 → WES 作业任务 → WCS 设备任务 → 指令号/幂等键 → 厂商请求 → 厂商响应 → 设备回执 → 统一执行结果 → 库存/单据结果**。

| 阶段 | 页面呈现 | 失败处理 |
| --- | --- | --- |
| 任务生成 | 任务详情的设备执行区 | 设备能力不匹配，转人工或改派 |
| 指令下发 | 设备任务队列、指令流水 | 网络失败按策略重试，超过阈值转人工 |
| 执行中 | 设备状态、任务进度、最近心跳 | 超时告警，保持任务执行中，不直接完成 |
| 回执接收 | 原始回执、统一状态、回执时间 | 重复回执按幂等键忽略并留痕 |
| 执行失败 | 失败原因、错误码、影响任务 | 重试、换设备、转人工、取消或补偿 |
| 状态不一致 | WMS/WES/WCS 三方状态对账 | 进入异常中心，人工确认前不修改业务终态 |
| 完成回写 | 工序、单据、库存流水 | 数量不守恒时拦截过账并生成异常 |

### 7.4 消息可靠性

集成中心必须有以下能力，原型中至少以列表、状态页签和详情抽屉呈现：

- **幂等**：请求唯一号、业务流水号、指令序列号、幂等键、重复消息结果。
- **重试**：按网络失败、超时、设备拒绝、执行失败、回执丢失分类；每次重试记录时间和原因。
- **死信**：超过重试上限的消息进入死信，展示原始消息、失败原因和影响范围。
- **补发**：允许有权限的操作员补发，但必须写明原因、补发人和补发前后状态。
- **人工接管**：暂停设备任务、转人工、更换设备、手工确认、重新同步状态。
- **对账**：按单据、任务、设备任务、消息和库存流水核对数量与状态。
- **审计**：保留原始请求、原始响应、统一映射结果和操作轨迹；敏感凭证不落界面明文。

## 8. 页面骨架与交互规范

### 8.1 页面类型

沿用 `admin` 外壳的四种形态：

| 类型 | 页面用途 | 固定结构 | 禁止事项 |
| --- | --- | --- | --- |
| `list` | 单据、任务、资源、设备、消息、异常 | 状态页签 → 筛选 → 工具条 → 表格 → 分页 | 不放 KPI 卡、不加页面副标题、不自绘筛选栏 |
| `report` | 单据总览、作业看板、接入总览、设备/人效分析 | 时间范围/口径 → 指标卡 → 问题分节 → 下钻列表 | 指标不能写死；必须显示数据截止或状态 |
| 抽屉详情 | 单据、任务、设备、消息、异常 | 抬头 → 明细 → 轨迹 → 底部动作 | 不注册独立详情页，不套嵌套页签分页 |
| 抽屉表单 | 派工、重排、接管、连接器、冻结、调整 | 抬头 → 分组字段 → 动作条 | 必填字段、危险后果和撤销口径不能省略 |
| PDA 扫码 | 收货、拣货、盘点执行 | 上下文 → 当前输入 → 校验结果 → 确认/下一件 | WMS 后台不重复画扫码屏 |

### 8.2 列表页规则

- 首个状态页签为「全部」，其它页签必须对应真实字段和值。
- 状态页签只放状态，不把异常、SLA、设备在线等不同生命周期塞成一套页签。
- 列顺序按“标识 → 来源/对象 → 状态 → 数量/金额 → 时间 → 操作”。
- 每页至少一个与当前状态匹配的动作列；批量动作只进入工具条。
- 任务页必须有“来源单据号”；设备任务页必须有“业务任务号”和“指令号”；消息页必须有“业务号”和“最后错误”。
- 数字列右对齐，数量、重量、体积、金额带单位；空值使用 `—`，不把未知值伪装成 `0`。
- 货主筛选只出现在需要按货主收窄的 WMS 页面，不在端级导航做货主切换。
- 设备监控、任务池、告警和消息流水必须有时间范围、区域/设备/执行单元等收窄条件，避免无界展示。

### 8.3 抽屉详情规则

抽屉宽度按信息量分级：

- 普通单据/任务详情：约 640px。
- 设备、消息、接口和 DAG 详情：约 920px。
- 抽屉内部固定四段：抬头字段网格、明细/原始数据、操作轨迹、底部动作条。

详情中必须区分：

- 计划值与实际值。
- 推荐库位/设备与实际库位/设备。
- 任务状态与异常状态。
- 设备原始状态与统一状态。
- 原始消息与映射后业务对象。
- 可逆动作与不可逆动作。

### 8.4 作业看板规则

作业看板只回答一个问题：**当前仓内作业是否按时推进，下一处瓶颈在哪里？**

建议结构：

1. 页头：时间范围、货主、区域、数据截止时间、刷新状态。
2. 第一行指标：在办任务、阻塞任务、超时任务、待派任务、设备影响任务。
3. 主体：按工序/区域的负荷与积压，问题行置于前方，动作紧跟问题。
4. 侧栏或第二块：阻塞任务、设备故障、接口失败和待处理异常。
5. 下钻：每个问题只进入一个主列表，不在看板复制完整表格。

看板不使用装饰性大图表。数量优先用表格、条形/子弹图和热力格；颜色只用于当前问题、风险和状态，不以彩色大色块装饰。

### 8.5 设备监控规则

设备监控必须让操作员在 3 秒内回答：设备是否在线、正在做什么、是否影响业务、下一步做什么。

| 区域 | 内容 |
| --- | --- |
| 设备列表 | 设备编号、类型、区域、在线/运行/故障状态、当前任务、最近心跳、今日吞吐 |
| 任务区 | 业务任务号、设备任务号、指令号、目标、进度、执行耗时、重试次数 |
| 告警区 | 级别、错误码、发生时间、影响对象、确认状态、工单状态 |
| 连接区 | 连接器、协议版本、最近调用、成功率、待处理消息 |
| 动作区 | 暂停、重试、换设备、转人工、确认恢复、查看流水 |

危险动作必须在动作旁明确影响和可逆性：暂停是否影响后续任务、人工确认是否允许撤销、强制完成是否会触发库存/单据回写。

### 8.6 扫码与现场执行

扫码页面属于 `pda-app`，WMS 后台只保留任务和结果详情。后台与 PDA 必须共享以下上下文字段：

- 单号/任务号、货主、作业人、设备/工作站、库区/库位。
- 商品编码、条码、批次、效期、序列号、容器码。
- 计划数量、已完成数量、当前输入数量、差异数量。
- 校验结果、错误原因、异常号、操作时间。

扫码失败应就地显示“对象 + 原因 + 修正方式”，不只提示“操作失败”。重复扫码、跨货主扫码、批次不符、数量超出、设备离线和任务已被他人领取都必须有确定的回退路径。

## 11. 分批实施计划

### P0：主链和闭环补齐

目标：不扩张导航理论，先让 WMS 主链和设备闭环可展示、可追溯。

- 改造任务池与派工：任务依赖、SLA、阻塞原因、重派和转人工。
- 改造出库订单/波次/拣货：库存分配、缺货、短拣、锁定库存和容量。
- 改造设备监控/告警/驱动：设备任务号、指令号、回执、心跳、重试和人工接管。
- 新增或以抽屉承载设备任务队列、消息流水、死信补发。
- 改造库存流水、盘点差异和调整任务：唯一改账入口和来源链。

### P1：自动化和接口治理

目标：支持多类外部设备服务厂商接入，而不是为每家厂商写一套业务页面。

- 新增连接器管理、设备能力矩阵、自动化拓扑。
- 完善协议/状态码/错误码映射、版本和生效范围。
- 增加接口对账、回执补发、业务状态重同步。
- 将输送线、AS/RS、AGV/AMR、分拣设备、称重/打印设备统一映射到设备任务模型。

## 13. 待评审决策项

以下问题不阻塞本方案作为原型改动依据，但在进入 P0/P1 前需要定稿：

1. 外部设备接口页面是否全部归入“设备与容器”，还是在页面达到规模后新增“集成治理”导航段。
2. 设备任务队列和消息流水是做两页，还是任务队列主表 + 消息/指令抽屉。
3. WCS 是否需要在原型内展示设备拓扑图；若展示，先做二维节点图，暂不承诺三维孪生。
4. 设备人工接管的权限角色、审批要求和强制完成后的库存过账规则。
5. 出库缺货池是否由 WMS 管理，还是由 WES 任务池统一承接；建议主档归出库订单，调度视图归任务中心。
6. 设备厂商连接器的凭证、证书、密钥是否只做脱敏占位，还是需要独立的安全管理系统页面；本项目原型建议只做脱敏展示。
7. 设备实时状态的刷新频率、数据截止标记和“实时/延迟”判据；在没有真实接口前不写死刷新阈值。

**方案判定句**：货灵 WMS 的原型不是把 WMS、WES、WCS 三套菜单相加，而是围绕“单据产生需求、WES 编排任务、WCS 执行设备、库存记录事实、集成治理可靠性”组织一条可追溯的仓内执行链。
