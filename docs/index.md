# 文档索引（货灵供应链运营平台）

`docs/` 是本项目文档的唯一存放位置。文档按用途归入分类文件夹，本索引是总入口，所有变更记入 `log.md`。

## 使用规则

1. **新增文档**：先归入已有分类，确无合适分类再新建文件夹；同步在本索引追加一行、在 `log.md` 追加一条。
2. **修改文档**：改完必须在 `log.md` 留痕并更新本索引的「最近更新」；只改文档不记日志视为未完成。
3. **分类自带索引**：`数据字典/`、`调研/` 各自保留 `index.md`、`log.md` 与自检脚本，清单以分类索引为准；本索引只给出分类入口。分类内部的清单维护由分类索引负责，校验由对应脚本执行。
4. `humanfile/` 是人类书写区，只读，不纳入本索引；除与所检查文档同目录的自检脚本 `check.mjs` 与调研报告的截图资产目录（`调研/<命题>-<日期>.assets/`，属证据）外，工程产物与临时文件不写进 `docs/`。
5. **提交前自检**：跑 `node docs/check.mjs`（文档体系）与 `node docs/数据字典/check.mjs`（数据字典字段），两者零错误再提交。
6. **调研类文档**：竞品、参考系统与需求来源调研一律放 `docs/调研/`（入口见 [调研/index.md](调研/index.md)），先读 `.codebuddy/rules/调研颗粒度/RULE.mdc` 的「交付物」一节与 `.codebuddy/skills/research-report/SKILL.md`：一份报告 = 一个不超过 24 小时的调研窗口、一份按八节骨架填写的自包含 HTML，须给覆盖清单、字段表、截图、证据分级与结论落点；写完跑 `.codebuddy/skills/research-report/scripts/check-report.mjs <报告.html>`，再过 `node docs/check.mjs`，两份都过才算完。只写功能概览或只列菜单名的按未完成处理。
7. **存量豁免**：`docs/产品需求/` 下的存量调研文档维持原状，不迁不改。

## 日志管理

活跃日志 `log.md` 只保留当期记录与归档索引，历史按月归档，避免单文件无限膨胀。规则只在此处维护。

1. **分片**：历史记录整体移入同级 `log/YYYY-MM.md`；跨月、当期记录超过 200 条、或单文件超过 100 KB 即触发，单月超量按 `YYYY-MM-2.md` 顺序续拆。
2. **归档文件只读**，不再追加；放 `log/` 子目录，不会被 `check.mjs` 当成实体文档扫描。
3. **登记**：每次归档在 `log.md` 的归档索引表追加一行（文件、覆盖时段、条目数、归档日期），并记一条类型为「归档」的变更记录。
4. `docs/check.mjs` 自动检查跨月、记录数、文件体积、归档索引与归档文件的双向闭环；历史记录在归档前已校验，归档后不重复扫描。
5. 顶层 `docs/log.md` 与 `docs/数据字典/log.md` 各自维护自己的归档索引，互不汇总。
