# 场景模拟（货灵供应链运营平台）

本分类存放「业务场景模拟」文档：把参考文章中的业务情形，拆成可独立闭环验证的场景规格。每个场景一份独立 md，含场景描述、参与角色、触发条件、正常流程、异常流程、闭环条件与闭环验证。

> 概念基座：[什么是场景.md](什么是场景.md)（定义「场景」是什么）+ [场景描述方法.md](场景描述方法.md)（每节怎么写、常见错误与自检清单）。所有 SC 文档先读这两份再动手。

## 使用规则

1. **命名**：`SC<NN>-<场景短名>.md`，NN 从 01 起两位补零、连续不跳号；短名用中文动宾短语，单看文件名即知在模拟什么。
2. **章节**：每份场景必须含七个 H2 章节——场景描述 / 参与角色 / 触发条件 / 正常流程 / 异常流程 / 闭环条件 / 闭环验证（后续补「流程图」一节，见 [什么是场景.md](什么是场景.md) 第 3 节），缺一不可，否则 `check.mjs` 判违规。
3. **自包含**：每个场景可独立闭环验证，不看其他场景也能从头走到闭环；跨场景共用概念（如「拣货单 / 任务 / 作业三层」）在本索引「术语与模型」统一说明，场景内只引用不重定义。
4. **来源登记**：场景推演自外部文章，来源文章、链接、访问日期与「SC ↔ 文章小节」映射统一登记在 `log.md`，场景文档内不铺陈来源；结论以参考文章口径为准，不引申到具体系统实现。
5. **归属端**：每个场景必须标注归属端（主／跨），索引按端分组；「端」清单与枚举口径见 [什么是场景.md](什么是场景.md) 第 4 节。
6. **增删与记录**：新增场景先在本索引「场景索引」对应端分组下追加一行（编号续接、状态草案）再建文件，并在 `log.md` 留痕；删除场景从索引移除并写明归档说明，不物理删除以免断链。

## 命名规范

文件名即契约，改动前先读本节点。本分类所有文档的命名约定如下。

### 1. 场景文件
- 格式：`SC<NN>-<场景短名>.md`
- `<NN>`：两位补零、从 `01` 起连续不跳号（由 `check.mjs` 强制校验）。
- `<场景短名>`：中文动宾短语，单看文件名即知在模拟什么（如 `中途换人-原任务内交接`）。
- **端不进文件名**：现有场景均跨 作业APP＋货灵WMS，无法唯一归属某一端；端的维度由「索引按端分组 + 归属端列 + 文档内 归属端 行」表达，而非文件名。
- 反例：勿用 `SC-WMS-01`、`SC-PDA-02` 这类端前缀——会破坏 `check.mjs` 的 `^SC\d{2}-` 正则，除非同步改造脚本。

### 2. 概念基座文档（固定名，不编号）
- `什么是场景.md`：定义「场景」是什么。
- `场景描述方法.md`：场景每节怎么写。
- 命名用中文、语义自解释，首字母大写。

### 3. 分类管理文档（固定名）
- `index.md`：使用规则 / 命名规范 / 术语与模型 / 场景索引（按端分组）。
- `log.md`：本分类变更日志（格式见文件顶部）。
- `check.mjs`：命名/章节/索引自检脚本，勿手改，规则变再改。

### 4. 流程图
- 以内联 Mermaid 章节 `## 流程图` 写在各 SC 文档内，须覆盖 正常+异常+逆向；**不单独出图文件**。
- 若未来确需独立图档（如跨场景总图），再约定 `SC<NN>-<短名>-图.md` 或 `图/` 子目录，并同步更新 `check.mjs` 与 `流程图规范` 的存放要求。

### 5. 扩展与变更
- 新增端（货灵ERP / 货灵商城 / 运营中台管理端）的场景仍用 `SC<NN>` 连续编号，不另起编号序列；归属端只在索引与文档内标注。
- 任何命名/结构变更须先评估 `check.mjs` 与 `docs/check.mjs` 的影响（见上文「按端分文件夹」结论），并记 `log.md`。

## 术语与模型

（这是参考文章的领域模型；「场景」本身的定义见 [什么是场景.md](什么是场景.md)。）

文章核心命题：仓内拣货任务「做到一半换人」，系统要能查清已完成记录、剩余工作责任，并正确处理延迟结果与差异。围绕 WMS 任务模型的三层分离：

- **拣货单（单据）**：保留业务要求——拣哪些货、多少数量、来自哪些出库要求；换人不改要求。
- **任务（执行责任）**：把工作划成可独立分配、跟踪、结束的单元，明确执行范围、作业位置、当前负责人。
- **作业（具体操作）**：承接具体动作与过程结果——从哪个库位取、放进哪个容器、谁确认多少、发生什么差异。

交接评审四条问题（文章结尾）：① 已完成量能否追到具体人员与作业记录；② 每份剩余工作是否有唯一当前执行责任；③ 交接前发生、交接后到达的结果如何核对避免重复计算；④ 少拣量由谁决定补拣或接受短拣、决定后由谁执行。
