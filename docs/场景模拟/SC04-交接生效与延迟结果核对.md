# SC04 交接生效与延迟结果核对

## 场景描述

接续方案选定、交接生效点设为「交接确认成功」（剩余范围已核对、甲对这部分执行权限已结束、乙已接收并记录）后，甲的设备因网络问题迟一些才提交交接前已发生的结果。本场景验证：延迟结果如何核对并避免重复计算——不能只看消息到达时间就当成乙的成果或直接丢弃；同一次确认重复提交只累计一次；若延迟结果暴露交接数量不一致，先核对受影响货物与记录再调整剩余任务。

## 参与角色

- 甲（作业人员）：延迟上报交接前已发生的确认结果。
- 乙（作业人员）：已接手剩余 20。
- 系统（WMS）：按「所属操作 / 是否已计入 40 / 是否影响剩余范围」核对，去重。

## 触发条件

- 交接已确认成功（生效点已过）；
- 甲设备延迟提交交接前已发生、尚未到达系统的作业结果。

## 正常流程

1. 系统收到甲的延迟结果，先判断它属于哪次操作。
2. 核对：是否已计入甲的 40 箱、是否影响交接时确认的剩余 20 范围。
3. 若属甲 40 内且未计入 → 归集到甲 40，不重复累计（同一次确认只计一次）。
4. 若与已确认一致 → 幂等去重，不重复。

## 异常流程

- 仅按消息到达时间处理：把延迟结果算作乙的成果，或直接丢弃 → 必须以「所属操作 + 是否已计入 + 是否影响范围」为准，不以到达时间定归属。
- 延迟结果暴露交接数量不一致：不立即让乙继续重复拣 → 先核对受影响货物与记录，再调整剩余任务范围。
- 同一次确认重复提交：累计多次 → 幂等控制，只累计一次。

## 闭环条件

- 延迟结果正确归集到甲 40 或差异待处理，未误计为乙成果、未丢失；
- 剩余 20 范围无重复计算；
- 若发现不一致，已触发核对与剩余任务调整，无悬空差异。

## 闭环验证

- [ ] 甲延迟上报的 40 内结果，核对后计入甲 40，乙已确认数不变。
- [ ] 同一次确认重复提交，系统去重，已做数量不翻倍。
- [ ] 延迟结果导致交接数量不一致时，触发核对流程而非直接让乙重复拣。
- [ ] 转交未成功时，仍可查当前负责人，延迟结果不丢失。
