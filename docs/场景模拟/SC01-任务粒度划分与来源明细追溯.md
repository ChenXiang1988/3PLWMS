# SC01 任务粒度划分与来源明细追溯

## 场景描述

一张拣货单（单据）包含若干出库要求的拣货行，系统需把它拆成可独立分配、跟踪、结束的「任务」单元。本场景验证：拆分粒度如何定、何时不拆，以及任务为何必须追溯到来源明细——同一商品可能出现在不同来源行，只存商品编码将无法核对各自完成量。简单作业可保持一单一任务；是否继续拆分取决于是否存在「必须独立分配、调整和结束」的工作。

## 参与角色

- 系统（WMS）：按策略生成任务、挂接来源明细。
- 排程/计划员：确认粒度与派工范围。
- 作业人员：按任务执行与确认。

## 触发条件

- 系统生成拣货单（可来自波次计划），命中多库区 / 多来源行；
- 需决定任务拆分粒度。

## 正常流程

1. 拣货单落库，保留业务要求（拣哪些货、数量、来源出库要求）。
2. 判断粒度：
   - 跨 A、B 两库区且两边可独立作业、各有合适人手 → 按库区拆成两个任务，各自独立分配/跟踪/结束。
   - 货物在相邻库位、一次行走可完成 → 不拆，保持一单一任务，避免按每箱拆任务增加领取与确认操作。
3. 每个任务挂接所承接的来源明细行与数量，保证「任务 ↔ 来源明细」可追溯。
4. 任务进入任务池，按派工策略分配执行人。

## 异常流程

- 拆得过细：每箱一任务，领取与确认操作暴涨，交接/汇总成本高 → 回退到按库区或按单。
- 拆得过粗：一处缺货拖住整项任务 → 重新按可独立结束的单元拆分。
- 只存商品编码不存来源明细：同商品在多来源行时无法准确核对各自完成量 → 补录来源明细关联，重算完成量归属。

## 闭环条件

- 粒度确定（拆 / 不拆及其依据记录）；
- 每个任务可追溯到来源明细与计划数量；
- 任务进入可分配状态，无「既拆又重叠」或「漏拆致无法独立结束」的残留。

## 闭环验证

- [ ] 给定一张跨 A/B 库区的拣货单，系统产出任务数 = 库区数，且每任务范围不重叠。
- [ ] 相邻库位单据产出 1 个任务，确认无每箱拆分。
- [ ] 任取一任务，能反查其承接的来源明细行与数量，合计 = 该任务计划数量。
- [ ] 同商品多来源行时，两个来源行的完成量可分别核对，不互相覆盖。
