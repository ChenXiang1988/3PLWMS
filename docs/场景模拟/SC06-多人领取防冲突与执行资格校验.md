# SC06 多人领取防冲突与执行资格校验

## 场景描述

同一份剩余工作（如乙接续的 20 箱）在派工/领取时，需避免两个人同时领取成功导致重复作业；若任务允许多人协作，须明确每人分别负责的明细或范围。同时系统要区分「已分配」与「可开始执行」：乙没有对应区域作业资格、或仍在等补货时，派给乙不等于可立即作业。

## 参与角色

- 乙 / 丙（作业人员）：可能同时尝试领取同一剩余工作。
- 主管：派工、校验资格。
- 系统（WMS）：领取排他锁、执行资格校验、区分已分配/可开始。

## 触发条件

- 剩余工作任务进入任务池可被领取，或主管主动派工；
- 任务可能多人协作，或执行人需特定区域资格 / 前置补货。

## 正常流程

1. 领取/派工发起，系统对剩余工作加排他锁，仅一人领取成功。
2. 多人协作场景：为每人划分各自负责的明细或范围，分别记录。
3. 区分状态：领取成功 = 「已分配」；通过执行资格校验（区域资格有效、补货已到位/无需补货）= 「可开始执行」。
4. 仅「可开始执行」状态允许发起实际拣货。

## 异常流程

- 两人同时领取同一剩余工作均成功：重复作业 → 领取加排他锁，第二人领取返回「已被领取」。
- 乙无对应区域作业资格却置为可立即作业：越权作业 → 派工/领取时校验资格，未通过只置「已分配」不置「可开始」。
- 仍在等补货却置为可开始：前置条件不满足 → 补货到位（或无需补货）才允许进入「可开始」。

## 闭环条件

- 同一剩余工作当前执行责任唯一（领取排他）；
- 多人协作时每人范围明确、不重叠；
- 「已分配」与「可开始执行」状态分离，满足资格/前置才进入可执行。

## 闭环验证

- [ ] 乙、丙并发领取同一剩余工作，仅一人成功，另一人得「已被领取」。
- [ ] 多人协作任务，分配后每人负责明细/范围可查且不重叠。
- [ ] 乙无区域资格时，任务状态为「已分配」但不可开始，补全资格后才可开始。
- [ ] 任务等补货时置「已分配/待补货」，补货到位才转「可开始执行」。
