# 店小秘 ERP 竞品对照（面向货灵ERP）

**目标读者**：产品、原型维护人。
**核心目的**：店小秘是货灵ERP 的直接竞品之一。本文以货灵ERP 为对照主体，记下共同主干、双方能力侧重、关键页面口径，以及货灵ERP 可借鉴与不必跟随的边界。
**前提**：材料来自 2026-11-08 对店小秘网页版的一次只读浏览。调研账号未授权任何店铺，订单与库存数据为空，所以本文只记菜单结构、列表字段、状态口径与配置项，不代表真实业务量下的表现。本项目单实例单主体，不做 SaaS，货主是业务维度。

## 1. 对标口径

- 对照主体是货灵ERP，不是整个货灵供应链运营平台，也不是货灵WMS、货灵运营中台管理端、PDA 作业端。
- 两者是直接竞品，共用一条 ERP 主干：订单、履约、售后、商品、平台接入、库存、报表、账号权限、操作日志。差异分布在多个能力域，不能归因于单一因素。
- 3PL 仓储委托是货灵ERP 在主干之外的一项差异化能力，不是它的产品定位；店小秘的自营仓作业同样只是它的一个能力域。仓内具体作业划给货灵WMS 与 PDA 端，属同一产品族的端分工，不是 ERP 缺少该能力。
- 仓库、库区、库位、批次、盘点、PDA 作业属 WMS 侧。本文第 4.5 节留作补充参考，不进对标主线。

## 2. 定位与能力侧重

| | 店小秘 | 货灵ERP |
| --- | --- | --- |
| 使用者 | 跨境电商卖家，在平台上开店、备货、打单发货 | 货主/卖家，处理平台订单与商城业务，其中一部分仓储履约委托给 3PL |
| 共同主干 | 订单、履约、售后、商品、平台接入、库存、报表、账号权限、操作日志 | 同左 |
| 能力侧重 | 产品刊登、自营仓作业、物流报关与运费、经营财务、客服自动化、全托管与平台仓 | 订单分层与履约决策、异常与对账、商城双身份、两域账号与全局审计，外加 3PL 仓储委托 |
| 主线单据 | 平台订单 → 打单发货；采购单、自营仓出入库单据 | 渠道单 → 履约单 → 执行单；委托链路上另有入/出库计划单与委托单据中心 |
| 费用口径 | 经营利润、采购成本、平台结算 | 自营部分按货主维度核算；委托链路上是 3PL 服务费账单、对账差异与仓储服务 |

双方在主干上是同类产品，能力清单的长短来自侧重不同与端分工，不是产品定位对立。做能力补齐时应逐域判断，不能用一句「我们是委托 3PL」排除刊登、物流、经营财务等域的参考价值。

## 3. 功能地图对照

按货灵ERP 的 12 段导航逐段对照。店小秘一级模块共 13 个：首页、产品、订单、客服、采购、仓库、物流、数据、财务、托管、广告、服务、设置；其中托管、广告、服务三段本次未展开。

| 货灵ERP 段 | 主要页面 | 店小秘对应 | 差异 |
| --- | --- | --- | --- |
| 工作台 | 货主工作台 | 首页（平台授权引导、直播培训） | 店小秘首页以授权引导为主 |
| 订单 | 订单中心、平台订单、代发采购单 | 订单 → 订单处理、手工订单 | 货灵ERP 订单段只接单，发货动作拆到履约段 |
| 履约 | 履约单、平台备货单、自发货单、物流跟踪 | 订单处理（待审核→待处理→运单号申请→待打单→已交运→发货成功/失败）、物流追踪 | 店小秘是打单流水线状态机，货灵ERP 是渠道单/履约单/执行单三层 |
| 售后 | 平台售后单、退货申请 | 客服 → 速卖通纠纷管理/延长收货/买家取消、eBay 纠纷管理、Wish Tickets | 店小秘按平台拆成客服与纠纷，无统一售后单，也不与逆向入库打通 |
| 仓储委托 | 入库计划单、出库计划单、调拨申请、委托单据中心 | 仓库 → 收货管理、入库管理、出库管理 | 货灵ERP 的差异化能力之一；店小秘仓内作业在自身产品内完成 |
| 异常与对账 | 异常队列、对账差异 | 订单处理的异常筛选（缺货、未配对SKU、仓库无此SKU、报关信息未填写等） | 店小秘把异常做成订单筛选条件，没有独立异常单与对账差异单 |
| 库存 | 本货主库存总览/查询/台账/批次效期查询 | 仓库 → 仓库清单、批次库存、出入记录 | 店小秘是自营仓作业视角，货灵ERP 是委托方只读视角 |
| 商品 | 本货主商品查询、商品资料变更申请 | 仓库 → 商品管理、商品图片、商品配对、包材管理、条码工具；产品 → 数据采集、搬家、开发、UPC、美图 | 店小秘强在刊登链路，货灵ERP 只做主档申请与查询 |
| 商城店铺 | 我的店铺、店铺商品、店铺价格、店铺订单、企业资质认证 | 无对应 | 货灵ERP 独有 |
| 平台接入 | 平台店铺、同步任务 | 设置 → 店铺授权；仓库 → 库存推送（配对关系/推送规则/推送记录） | 店小秘授权是平台目录式开通，同步靠推送规则；货灵ERP 把同步任务做成可查、可重试的单据 |
| 账单与服务 | 费用规则查看、本货主费用账单、服务费账单、仓储服务 | 财务 → 利润核算、采购成本、平台费用、物流对账、平台结算 | 一个算卖家经营利润，一个算 3PL 服务费 |
| 报表与设置 | 货主数据报表、子账号与权限、角色权限、操作日志 | 数据 → 综合分析/运营分析/仓储物流；设置 → 子账号管理、责任人设置、操作日志 | 结构接近，权限粒度不同（见 4.7） |

店小秘另有货灵ERP 没有的能力：全托管（Temu、SHEIN、Shopee、TikTok、速卖通等）、平台仓库（FBA、FBL、FBT、Shopee、Mercado 等 10 类）、第三方海外仓、物流运费与报关、客服消息自动化。这些属跨境卖家场景，见第 6 节。

## 4. 关键页面口径

以下都是本次实际打开页面读到的字段与状态，未取帮助文档或二手评测。

### 4.1 订单处理

状态分组：全部订单、待审核、待处理、运单号申请、待打单、有货 / 缺货、已交运、发货失败、发货成功、已退款、已搁置。
异常筛选：有备注、有留言、买家指定多物流、报关信息未填写、俄罗斯收件人非全名、缺货、未配对SKU、仓库无此SKU、黑名单买家。另有按订单来源（其它 / 手工订单）与按国家两类筛选。

货灵ERP 的订单中心按来源单号聚合履约单，状态是未下发 / 待发货 / 部分发货 / 已发货 / 已签收 / 售后中 / 已取消。两者不是同一套状态机：店小秘围绕「把这一单打出来发走」，货灵ERP 围绕「这一单由谁、用哪张执行单履约」。

### 4.2 审单规则

页签：审单规则、物流规则、赠品规则、运单号自动申请规则、自定导出。
开关：启用审核流程（默认开启），未命中时「留在待审核」；另有规则试算、设置系统规则、创建规则。
列表字段：优先级、规则名称、规则详情（可展开）、执行动作、状态、操作。页面提示语写明用途是「将订单移入待审核并打上对应的标记/备注」。

这是优先级条件→动作的规则引擎。货灵ERP 的对应物是履约决策记录与规则版本留痕，偏决策可追溯，不是自动改单。若后续要做策略配置，「规则试算」这个上线前验证入口值得抄。

### 4.3 售后

店小秘把售后放在客服模块，按平台拆：速卖通（纠纷管理、延长收货、买家取消）、Wish（Tickets、Wish通知）、eBay（客服消息、评价管理、纠纷管理、议价管理），另有通用的物流消息（到达待取、已经签收、投递失败、运输过久、物流异常）与智能客服（发货提醒、自动催付、自动评价、付款消息、延迟发货等）。
货灵ERP 用统一的平台售后单与退货申请，售后处理结果会生成入库计划单。这一段的差异在于：店小秘侧重买家沟通，货灵ERP 在委托链路上还要处理货权与库存回流。

### 4.4 商品与库存

商品管理页列：商品信息、仓库位置、货架位、库存情况、销量（3/7/15/30 天）、单价（CNY）、总价（CNY）、创建/更新时间、操作。
库存情况拆成六段：安全、在途、未发、占用、可用、总量。
SKU 类型：单个SKU、组合SKU、加工SKU、多变种SKU；商品状态：在售、热销、新品、滞销、清仓、停售。
搜索维度：商品SKU、商品编码、商品名称、货架位、识别码、备注；排序维度含未发、可用库存、库存总量、单价、总价、采购在途、货架位。
汇总行显示库存总价值、库存总数、可用库存总数。

货灵ERP 的库存查询已补已占用、在途、可承诺（ATP）与数据截止，但没有「安全」与「未发」两段，也没有销量分档与商品生命周期状态。是否补，取决于货主要不要在本端看销售表现；按委托链路上「ERP 不接管 3PL 库存账」的口径，销量分档不必进 ERP。

### 4.5 仓库侧补充参考（非对标主线）

仓库设置分三个页签：仓库管理（仓库名称、仓库地址、负责人、默认状态）、分区管理（分区名称、拥有货架数、分区类型、状态）、货架管理。默认仓库下有拣货区、次品区两个分区，均启用。系统还预置「无仓库（仅使用商品SKU，不使用仓库）」，允许整店不启用仓库管理。
仓库清单页按「仓库位置 + 分区」展示商品库存明细，页签即拣货区 / 次品区 / 全部区。
库区模型是仓库 → 分区 → 货架位，这一段供货灵WMS 的库区库位设计参考，不写进货灵ERP 的需求。

### 4.6 平台接入与同步

店铺授权页按平台目录展示：全部(74)、已授权(0)、未授权(74)，可搜索平台名称。本次账号一个平台都没授权，这解释了为什么各页计数都为 0。
仓库模块下的库存推送分三项：配对关系、推送规则、推送记录，是把商品与库存推到平台店铺的通道。
货灵ERP 的平台接入段是平台店铺与同步任务两页，授权状态、同步任务状态、重试与失败原因都是可查单据。差异在于店小秘把同步藏在「推送规则 + 推送记录」里，货灵ERP 把它提升到一级导航。

### 4.7 账号与权限

子账号管理有两个页签：子账号管理、角色管理。
列表字段：子账号名称、姓名、角色、创建时间、登录需要邮箱/短信验证码、最后登录时间、操作；可按子账号名称、姓名、角色搜索，支持创建子账号与批量操作。
设置模块还有责任人设置、PDA设置、操作日志。

货灵ERP 的《账号与权限方案》是三类账号（运营方 / 货主 / 仓内）、角色 = 菜单 + 动作 + 数据范围、货主域与运营中台域两套边界，并有账号生命周期与操作日志。店小秘面向单一卖家主体，账号模型是「子账号 + 角色 + 二次验证开关」，没有跨货主数据范围这一层。这个差别来自主体模型不同（单卖家主体 vs 单实例下多货主作为业务维度），不是产品定位对立，也不宜当成能力高低。

## 5. 可借鉴点

1. **六段库存口径**：安全 / 在途 / 未发 / 占用 / 可用 / 总量。本端已补已占用、在途、可承诺，可核对「安全库存」与「未发」是否需要暴露给货主。
2. **规则试算**：审单规则页在规则列表旁提供试算入口。货灵ERP 的履约策略、任务中心策略若加配置，上线前试算比直接生效稳妥。
3. **异常筛选前置**：缺货、未配对SKU、仓库无此SKU、报关信息未填写等直接做成订单页的筛选条件，异常队列可参照按来源域组织同类快捷筛选。
4. **商品生命周期状态**：在售 / 热销 / 新品 / 滞销 / 清仓 / 停售，比单纯启停状态更能表达货主的经营口径。
5. **库区分型与货架位**：拣货区 / 次品区的分区类型，供货灵WMS 参考（见 4.5）。

## 6. 不必跟随

- **产品刊登链路**：数据采集、数据搬家、商品开发、UPC管理、外观专利、小秘美图、各平台刊登。当前版本未规划刊登能力，商品主档由 3PL 侧审核下发。
- **经营利润与平台结算**：利润核算、采购成本、平台费用、1688开票。店小秘算卖家自己的经营账；货灵ERP 在委托链路上算 3PL 服务费，两者不是同一套核算对象。
- **全托管与平台仓**：Temu/SHEIN/Shopee/TikTok 全托管、FBA/FBL/FBT 等 10 类平台仓。货灵ERP 已用「平台 × 订单类型」配置吸收履约责任与备货位置，不按平台建页面。
- **客服消息自动化**：自动催付、自动评价、消息模板、纠纷与议价。当前版本未规划买卖双方消息能力。
- **仓内作业与 PDA 作业**：收货、上架、盘点、波次、拣货。这些划给货灵WMS 与 PDA 端，是产品族内的端分工。

## 7. 方法与边界

- 全程只读浏览，没有新增、修改或删除任何业务数据，也没有提交任何表单。
- 单步串行访问，每步之间留间隔，没有并发请求或批量抓取。
- 字段与状态口径取自网页实际渲染。未展开的模块（托管、广告、服务）与未打开的二级页只记菜单名，不推断其内部字段。
- 本文不改原型、不改数据字典。若要按第 5 节落地，先走原型规范与跨端联动确认。
