调研报告

Shopee 订单接口能力调研

Shopee 已提供订单、发货与售后 API 目录；货灵应以“原始订单—标准业务订单—履约单—执行单”承接，原型先复用现有平台化页面，不新增 Shopee 专属菜单。

日期2026-11-10状态草案版本v0.1作者货灵产品与架构调研报告对象Shopee Open Platform OpenAPI 2.0、货灵 ERP 原型

1 口径与证据

本轮覆盖 Shopee 官方公开站点和货灵当前原型，只读访问，未执行 Shopee 写操作，也未改动 prototypes/。证据分三档：A 本项目代码与页面实见；B Shopee 官方 Open Platform 文档目录或官方页面；C 第三方资料。本报告不把目录名称推断成未验证的字段定义。

3 逐页记录

3.1 Shopee 订单查询 › 货灵平台原始订单 / 订单中心

入口

沿用货灵 ERP 已有平台化订单入口，Shopee 通过平台 key 进入，不新增一级菜单。现有平台页面复用 owner/pages/platform-order-list.mjs，订单聚合入口为 order-center。

结构分区

列表顶部为同步、筛选、批量操作；行展示平台订单号、原始状态、统一状态、店铺、下单时间、金额、履约方式、异常标签。右侧抽屉使用订单 360：原始订单快照、标准业务订单、商品/SKU、地址、履约关系、包裹物流、同步事件、售后关联。

列表列与筛选

分区字段/控件交互口径证据
查询平台订单号、店铺、平台原始状态、货灵统一状态、创建/更新时间默认按更新时间倒序；时间窗由平台适配器限制并展示实际同步窗口B：目录能力；字段策略为货灵设计
商品SKU、商品标题、配对状态未配对、部分配对、已配对可直接进入异常处理A：现有订单分层方案
履约履约方式、目标仓、承诺发货时间、包裹/运单可按仓发货、自发货、外部委托筛选A：现有原型与方案
异常同步失败、映射异常、取消申请、售后中异常标签置顶；支持从行进入异常队列A：异常队列与同步任务

行与批量操作

单行：查看 360、重试同步、进入履约决策、查看平台原始快照、处理取消申请。批量：同步/重试、批量分配履约方式、批量标记已读；涉及发货、取消和平台写回的批量动作必须二次确认，并按成功/失败/跳过分组返回结果。

交互与异常

首次同步显示进度与店铺；相同平台订单号命中幂等键时不新建标准订单；地址/金额已被履约单引用时不静默覆盖，改为版本差异提示；SKU 未匹配阻断履约；部分同步失败保留成功行并生成异常任务。

3.2 Shopee 拆单与发货 › 货灵履约单 / 执行单

入口

从订单 360 的“履约关系”进入 fulfillment-list；仓发货继续进入 ERP 的 out-plan-owner-list 和 WMS out-plan-list，自发货进入 selfship-list，代发分支当前页面名称是 dropship-list（代发采购单）。

结构分区

履约详情顶部显示履约单号、责任方、方式、状态和承诺时间；中部是商品行与分配数量；下部是执行单、包裹、承运商、运单、平台回传和事件时间线。拆单必须显示来源标准订单、原始平台订单和剩余可履约数量。

字段与接口映射

货灵字段Shopee能力关联页面落点证据边界
平台订单号、店铺、原始状态get_order_list / get_order_detail平台原始订单卡片目录 B；字段待授权复核
包裹、包裹状态、履约数量get_shipment_list、search_package_list、get_package_detail履约关系与包裹卡片目录 B；字段待授权复核
物流参数、渠道、承运商、运单get_shipping_parameter、get_tracking_number物流区块、发货表单目录 B；字段待授权复核
发货、面单、回传ship_order、发货文件 API、update_tracking_status发货动作与同步任务目录 B；写回前必须验证权限

行与批量操作

履约单支持查看、拆分、合并前校验、生成执行单、确认责任方、录入/获取运单、生成面单、发货、重试平台回传。仓发货只把执行结果回传 ERP；自发货与外部委托履约不进入本地 WMS/PDA。

状态 × 动作

履约状态拆分确认责任方发货撤销
待决策可可不可可
待确认按未确认行可不可需撤回
履约中剩余数量可拆不可按包裹不可
已发货不可不可仅重试回传不可
异常修复后可补资料后可重试/人工补偿按售后

交互与异常

发货前锁定本次提交幂等键；平台返回部分成功时，包裹逐个显示结果，不回滚已成功包裹；承运商或运单缺失时阻断发货；面单异步生成时显示任务状态，不允许重复生成。拆单数量、包裹数量和已发货数量三者在提交前校验。

3.3 Shopee 取消能力 › 订单详情 / 平台售后 / 异常队列

入口与结构

cancel_order 从订单或履约详情发起；handle_buyer_cancellation 从“取消申请”标签进入。货灵以平台售后/异常关联记录平台请求、处理人、原因、影响商品行、平台返回和后续履约撤销结果。

字段与动作

字段展示/输入规则
取消类型卖家取消 / 买家取消申请来源只读，处理动作分开
取消原因平台原始原因 + 货灵归一原因保留原值，不以归一值覆盖原值
影响行与数量商品/SKU、待发货数量已发货行不能被普通取消动作覆盖
处理结果接受、拒绝、失败、待重试需保留平台回执和异常任务

交互与异常

取消提交必须二次确认，展示可能产生的库存/采购/委托影响；订单已下发 WMS 时先检查执行单状态，禁止只改平台状态；平台拒绝取消时保留申请，不自动关闭；网络超时按未知结果处理，先查询再重试。

3.4 Shopee 售后逆向 › 平台售后单 / 退货申请

入口

平台售后页面复用 owner/pages/platform-aftersale-list.mjs，Shopee 通过平台 key 过滤；货主侧退货申请是独立的 return-apply-list。两者以平台售后单号、原始订单号、标准业务订单号、履约单号和包裹/运单关联。

结构分区

列表优先显示售后状态、原因、金额/数量、截止时间、责任方、逆向运单和异常标签；右侧抽屉分为售后概览、方案、凭证、争议、逆向物流、退款/对账和事件时间线。

接口能力与交互映射

Shopee API货灵动作页面反馈证据
get_return_list / get_return_detail拉取/刷新售后原始状态、更新时间、同步任务B：目录
confirm / dispute确认退货 / 发起争议二次确认、凭证校验、平台回执B：目录，条件未验证
get_available_solutions / offer / accept_offer选择方案、提出/接受方案方案差异和金额影响B：目录，字段未验证
upload_proof / query_proof上传/查询凭证文件状态、失败重试、审计B：目录
get_reverse_tracking_info同步逆向运单逆向包裹卡片、入库待核验标签B：目录

状态 × 动作

售后状态查看确认/方案争议凭证/逆向
待处理可按平台能力按截止时间可
处理中可按平台回执补充材料可
退货运输中可不可重复确认按平台窗口刷新
已完成/已关闭可不可不可仅查询
同步异常可修复后重试人工处理重试/补录

交互与异常

售后动作必须展示平台截止时间与证据要求；上传凭证成功以平台回执为准；争议和方案动作不覆盖原始售后状态；逆向物流与仓内退货入库分开，只有仓内实际收货后才推进本地退货申请的入库状态。

3.5 Shopee 同步任务与异常 › 同步任务 / 异常队列 / 对账差异

入口与列表

同步任务复用 sync-task-list，异常队列是 exception-list，对账差异是 reconciliation-list。同步任务按店铺独立；异常按来源域、单据、类型、SLA 和处理状态聚合；差异分平台单、ERP 单、履约/运单、账单/售后。

最小字段

任务类型字段动作
拉单店铺、时间窗、游标/页、拉取数、成功数、重复数、失败数、最后错误查看、重试、补拉、暂停
发货回传履约单、包裹、运单、平台回执、重试次数查询结果、重试、人工补录
售后同步售后单、状态、凭证、截止时间、回执刷新、重试、转异常

交互与异常

失败任务保留原请求摘要、响应摘要、关联单据和幂等键；重试默认只允许在可安全重试的错误上执行；未知结果先查询后重试；批量任务按店铺分组展示成功/失败/跳过，不以一条总状态掩盖部分失败。

5 横向对比

本轮是单平台接口调研，横向比较对象为“Shopee 官方能力”与“货灵现有承接能力”；不把货灵页面能力误写成 Shopee 官方字段事实。

能力维度Shopee 官方目录货灵现状差异与口径
订单查询/详情有有平台化页面Shopee 字段 schema、时间窗和权限需适配器复核
包裹/拆单有接口名称履约单支持多次发货需绑定平台包裹与履约单数量，避免一对一假设
仓发货/自发货有物流/发货能力已有出库计划单、自发货单仓发货进入 WMS；自发货不进入 PDA
外部委托履约未从官方目录确认独立能力有代发采购单，委托履约语义待拆开不把现有代发采购单直接当外部委托履约单
取消/买家取消有接口名称有订单/异常承接取消条件、截止时间、状态枚举待授权复核
退货/争议/凭证有接口名称有平台售后与退货申请售后字段、方案和地区差异待复核
同步与异常补偿目录未说明同步任务、异常、对账已有页面由货灵集成层负责，不推断为 Shopee 原生能力

6 结论与落点

本轮结论集中在“能力目录已足以定义适配边界，但字段正文和授权条件不足以直接开发联调”。原型交互方案已给出页面入口、字段、筛选、批量、抽屉、状态动作和异常逆向；原型文件暂不修改。

编号判定结论落点
C1可借鉴Shopee 订单、包裹、物流、取消和售后能力应被适配器拆成独立同步/写回任务，不把平台状态直接写成 ERP 状态。platform-order-list、order-center、sync-task-list
C2可借鉴货灵使用原始订单—标准业务订单—履约单—执行单四层链路，支持多包裹、部分发货和售后关联。order-center、fulfillment-list、履约关系卡片
C3可借鉴仓发货、自发货和外部委托履约使用同一履约详情框架，但只把仓发货下发 WMS/PDA。out-plan-owner-list、selfship-list、dropship-list
C4可借鉴取消、退货、争议和凭证必须保留平台原始请求/回执，并通过异常队列处理未知结果和部分失败。platform-aftersale-list、return-apply-list、exception-list
C5待定官方详细 schema、权限、错误码、时间窗、限流和地区差异尚未在公开正文稳定取得，接入前必须用目标店铺授权复核。运营中台平台应用配置、适配器联调清单；决策人：平台接入负责人
C6不跟随不新增 Shopee 专属订单、售后或履约菜单，也不把自发货/外部委托履约接入 PDA/WMS 仓内作业。shared/modules.json 现有平台化页面与端边界

6.1 建议

编号动作前置判据
R1把 Shopee 适配器的原始订单、物流、取消、售后字段做版本化映射取得目标店铺授权并导出真实 schema每个字段有原始路径、统一字段、版本和缺失策略
R2在现有平台化页面中补 Shopee 的平台配置与演示状态完成跨端联动清单并获用户确认只改批准落点，五端构建与交互验收通过
R3将外部委托履约从代发采购语义中拆成独立业务对象确认成本、确认、拒单、对账和退货责任规则可追踪委托确认、发货凭证、平台回传和费用对账
R4为未知结果建立先查询后重试的补偿策略适配器支持查询接口和幂等键重试不产生重复订单、重复包裹或重复售后动作
