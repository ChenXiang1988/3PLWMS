3.1 系统定位与整体架构（含技术栈）

JeeWMS 是一套基于 JEECG 生态打造的开源仓库管理系统，Gitee GVP 项目，采用 GPL-3.0 协议，由灵鹿谷科技主导、经多家企业商用后开源。定位为「智能仓储中枢」，覆盖 WMS、OMS（订单）、BMS（计费）、TMS（运输）、RF（现场作业/PDA）五大域，支持 3PL 第三方物流与厂内物流两类业态，含 Web 后台与 PDA 双端。

技术栈（依据部署文档与官方 README，C 级、部署文档佐证）：

分层选型备注

后端框架Spring Boot 2.x老版基于 JEECG（非 Boot），2022-11-11 发布 JeecgBoot 前后端分离版

3.3 业务流程与数据流转逻辑

JeeWMS 的核心是「单据驱动、过账改库存」。库存只在明确的过账动作上变化，其余环节均为待处理状态，多数账实不符源于单据停在中间态未过账（掘金全景，C 级）：

业务链起点单据中间单据终点状态库存过账时点
入库链采购/调拨到货通知收货单 → 质检 → 上架单入库完成上架确认时
出库链客户订单/发货通知波次 → 拣货单 → 复核 → 出库单发货完成出库确认时
库内链移库/补货/盘点任务移库单 / 盘点单任务关闭移库确认 / 盘点差异过账时
逆向链客户退货申请退货收货单 → 质检 → 处置单退货入库或报废处置确认时

数据流转骨架（五个核心对象）：

  1. 货主：绝大多数数据的第一层隔离维度（厂内物流常一个，3PL 下多个）。
  2. 仓库 / 库区 / 库位：三级物理建模，库位是库存最小容器，也是作业指令最小落点。
  3. 货品与批次：货品是静态主数据，批次是动态实例，追溯挂在批次上。
  4. 库存与库存状态：定位 = 货主 + 货品 + 批次 + 库位 + 状态；状态含可用/锁定/待检/冻结，状态不同可参与业务不同。
  5. 单据与单据行：头与行分离，批次/库位/状态挂在行或头层。

前三类（货主、仓/区/位、货品与批次）是「配置出来」的；后两类（库存与状态、单据与行）是「跑出来」的。库存扣减通过同事务写入流水 + 更新台账保证一致性。

3.5 权限与角色管理机制

JeeWMS 权限基于 Apache Shiro + JEECG RBAC：

  • 认证：Shiro 管理登录会话，token 存 Redis（部署文档要求 Redis 设密）。
  • 授权：角色-菜单-按钮三级，菜单与操作权限挂在角色上；受限角色（如拣货员、复核员、货主）看到的菜单与按钮与管理员不同。
  • 数据权限：通过 sys_org_code / sys_company_code 等字段做行级隔离；「域验证」菜单专门校验仓/货主/人三维数据隔离，排查「看不到单」首先查此。
  • 默认账号（公开 README，属弱口令风险）：本地 admin/llg123，测试系统 test/123456；ActiveMQ 默认 admin/admin。
  • 角色差异：官方未公开角色清单；依业务推断含系统管理员、仓库主管、拣货员、复核员、货主/客户，但逐角色菜单差异未验证（C 级）。

3.6 系统扩展性与二次开发能力

JeeWMS 的二次开发遵循「配置层 / 扩展层 / 模块层」三级边界（掘金全景，C 级）：

层次典型内容改动方式升级代价
配置层仓库库位建模、货主货品主数据、计费规则、作业策略界面配置几乎为零
扩展层自定义校验、接口适配、报表定义按扩展点实现低
模块层新增业务能力、改造领域模型新增模块或改内核中到高
  • 低代码基座：基于 JEECG/JeecgBoot，提供代码生成、Online 表单开发，二次开发门槛低、社区资料多。
  • 接口适配层：对接 SAP ECC/HANA、用友 U8、百胜 E3、UAS 时在接口层做转换，外部字段语义不下沉领域模型（推荐实践）。
  • 动态计费（BMS）：在线 SQL 拼装计费规则，按操作类型/货主/合同周期组合；灵活但存在安全风险（见 3.7）。
  • 移动端解耦：PDA 用 UNI-APP，一套代码适配多硬件，与后端仅经接口通信。
  • 模块化可拆分部署：3PL 城市配送方案可将 WMS/OMS/BMS/TMS 按模块独立部署。
  • 兄弟微服务产品：jeemes 提供 Nacos/Sentinel/Gateway/MinIO/SkyWalking 的微服务底座，可作为规模化演进方向。

3.7 性能与安全性表现

性能：

  • 库存扣减采用行锁 + 条件约束：UPDATE wms_stock SET quantity = quantity - ? WHERE id = ? AND quantity >= ? AND is_frozen = 0，靠条件充当乐观锁，数据库行锁保证不超卖、跳过冻结（CSDN 库存台账，C 级）。
  • 台账与流水写入同一事务，保障对账一致；并发扣减安全。
  • 异步任务经 ActiveMQ 削峰，避免同步阻塞。
  • 瓶颈：单体 Spring Boot，无内置水平扩展；报表统计在 MySQL 上聚合，大仓月报类查询易成瓶颈；PDA 高并发扫码需结合缓存与连接池评估。

安全性：

  • 认证/授权靠 Shiro + RBAC，机制成熟。
  • 默认弱口令：admin/llg123、test/123456、ActiveMQ admin/admin，部署文档明确要求改密，否则易被入侵。
  • BMS 在线 SQL 计费引擎：若未做沙箱与白名单，存在 SQL 注入乃至命令执行风险，是高危点。
  • GPL-3.0 合规：以 SaaS 形式分发需随分发物提供源码与许可证文本，商用边界需法务评估。
  • 前端风险：老版 EasyUI/jQuery 前端需注意 XSS 与组件漏洞；分离版（Vue）风险相对可控。

3.8 现有设计优缺点总结与改进建议

优点：

  • 开源 GPL-3.0，零许可成本，可本地化部署与二次开发。
  • 能力覆盖 WMS/OMS/BMS/TMS/RF 全链路，多家企业商用验证。
  • 基于成熟 JEECG 生态，招人、踩坑资料多，二开门槛低。
  • 支持多租户/3PL 与厂内物流，硬件对接（PDA/RFID/AGV/电子标签）现成。
  • 「台账 + 流水」对账模型与明确过账时点的单据链设计清晰、可追溯。

缺点：

  • 技术栈偏旧（JDK8、单体、EasyUI 老版），规模化与云原生能力不足。
  • 版本分裂（JEECG 老版 / JeecgBoot 版 / jeemes）增加维护与表结构不一致成本。
  • 默认弱口令与 BMS 在线 SQL 带来明确安全短板。
  • 报表在 MySQL 聚合，大仓性能与扩展性受限。
  • 文档分散、跨版本命名/表结构不一致，上手与排障成本高。
  • 多租户依赖字段隔离（sys_org_code）而非真正租户隔离。

改进建议（落到货灵平台或 JeeWMS 自身改造）：

  • 升级 JDK17 + 向 jeemes 微服务底座演进，缓解单体瓶颈。
  • 交付基线强制改默认口令、Redis/ActiveMQ 设密、BMS 规则加 SQL 沙箱与白名单。
  • 报表迁读写分离 / OLAP，避免大查询压主库。
  • 统一表命名与 DDL 规范，收敛多版本差异。
  • 明确 GPL-3.0 商用/SaaS 边界，提供容器化交付。

6 结论与落点

每条结论只允许三种判定：可借鉴、不跟随、待定。落不到具体落点的是描述，不是结论。

编号判定结论落点
C1可借鉴「库存台账 + 流水」双表对账模型（可用/冻结/总量三列 + change_type 流水）可直接映射到货灵库存设计货灵WMS / 库存 / 实体 inventory、inventory_transaction
C2可借鉴四条业务单据链 + 明确「库存过账时点」的设计，账实不符多因单据停在中间态，值得借鉴货灵WMS / 出入库计划单状态流转与逆向流程
C3可借鉴货主作第一层数据隔离维度、仓库/库区/库位三级建模、库位为作业最小落点，与货灵仓网模型一致货灵WMS / 仓库档案、库位管理
C4不跟随默认弱口令（admin/llg123、test/123456、ActiveMQ admin/admin）不可沿用，交付须强制改密与最小权限货灵WMS / 安全基线、交付形态方案
C5不跟随BMS 动态计费采用在线 SQL 拼装规则，存在注入/命令执行风险，货灵计费应走参数化规则引擎而非裸 SQL货灵WMS / 计费模块（BMS）
C6不跟随多租户依赖 sys_org_code/sys_company_code 字段隔离，非真正租户隔离；货灵为单实例单主体、多货主仅业务维度，不应照搬字段租户方案账号与权限方案 / 数据范围
C7待定报表统计在 MySQL 聚合，是否借鉴其报表维度需结合货灵读写分离/OLAP 方案确认货灵WMS / 报表统计、数据字典
C8可借鉴「配置层/扩展层/模块层」三级改动边界（规则变→配置、参数/流程→扩展、通用能力→提回主线）可作货灵二开分层依据货灵WMS / 二次开发框架
C9可借鉴接口适配层统一对接 SAP ECC/HANA、用友U8、百胜E3、UAS，外部字段语义不下沉领域模型，可作货灵 ERP 对接层范式货灵ERP / 平台接入、订单体系
C10不跟随版本分裂（JEECG 老版/JeecgBoot 版/jeemes）增加维护成本；货灵应锁定单一技术基线，不并行多套技术栈选型 / 架构设计
C11可借鉴PDA 采用 UNI-APP 一套代码多硬件、与后端仅经接口解耦，可作货灵 PDA 端形态参考货灵WMS / PDA 端
C12不跟随GPL-3.0 下 SaaS 化分发需提供源码，货灵若做多租户云交付须评估许可证边界货灵ERP / 交付形态（单独售卖软件）
