# 有限空间资源约束下的仓内作业调度模型

> 本文档是一份完整、独立、可用的模型说明。按金字塔原理组织：先给结论，再按四个支撑论点展开，每个论点下给具体结构、公式和参数。全文用中文论述，字段名和公式用代码块呈现。

---

## 结论

仓库的流通量不取决于把任务派得多快，取决于瓶颈有没有停下来等人、等货、等空间。这份模型要解决的核心问题是：在库容、人员、设备、空间拓扑都有限，且仓内已经存在积压货品的情况下，怎么让单位时间流过的标准工作量最大。

模型的定位一句话：**放多少由瓶颈决定，什么时候放由作业缓冲、库存缓冲、容器可用性和同步窗口共同决定，怎么组合由人机能力、行程收益和载具容量决定，放了之后由同步损失、积压变化、库容占用、容器消耗和实际时长回写校准。**

支撑这一结论的四个论点：

| 论点 | 内容 | 回答的问题 |
|---|---|---|
| 论点一 | 目标口径：以瓶颈通过率为唯一主控目标 | 度量什么 |
| 论点二 | 控制结构：五层闭环，瓶颈节拍加准入阀门 | 怎么控制流量 |
| 论点三 | 空间与资源建模：拓扑、楼层、货架、容器、人机能力组合 | 资源和空间怎么算 |
| 论点四 | 可靠性与数据：可信度、降级、参数分层、公式体系 | 状态不可信时怎么保护回路 |

四者关系：目标决定结构，结构决定建模粒度，建模粒度决定输入输出和可靠性设计。

## 论点一：目标口径

### 1.1 三类吞吐量，各管一段

| 口径 | 定义 | 角色 |
|---|---|---|
| 系统吞吐量 | 统计期内完成的标准工作量除以时间窗口 | 验证层，评价整体流通量 |
| 瓶颈通过率 | 当前瓶颈资源单位时间通过的标准工作量 | 控制层，唯一主控变量 |
| 任务吞吐率 | 标准工作量除以资源工时，剥离同步等待 | 反馈层，校准时长与权重 |

系统流通量不会超过瓶颈通过速率，非瓶颈跑满只会制造在制品。调度层面的“吞吐最大化”应表述为：瓶颈通过率最大化，且尽量不中断。

### 1.2 货物与容器双口径

```text
货物通过率 = 完成任务货物标准工作量 / 时间窗口
容器通过率 = 完成任务容器数 / 时间窗口
装载效率   = 货物通过率 / (容器通过率 × 单容器标准容量)
```

资源占用按容器口径算，业务评价按货物口径算，装载效率独立监控。三个都进输出，不合并成一个数。

### 1.3 库容周转是约束性指标

库容占用率、积压滞留时长分布、库容占用率变化速度，作为约束性目标：在瓶颈通过率不下降的前提下被压住。库容饱和不会让单个任务不可执行，但会压低所有资源的有效通过率。

### 1.4 单位统一

瓶颈通过率、释放配额、在制品上限、库容占用，必须用同一套标准工作量单位：托盘每小时、标准箱每小时、订单行每小时，或按仓库任务结构加权。任务个数做单位偏差太大。库容另有一个空间单位：托盘位或平方米。

### 1.5 目标函数：字典序

```text
第一优先：最大化  瓶颈通过率 R_t
第二优先：在 R_t 不下降前提下，最小化  在制品 + 同步损失 + 拥堵 + 积压滞留
第三优先：在前两项不恶化前提下，最小化  移动成本 + 改派成本
```

后一项不能以前一项为代价。移动成本再低，瓶颈通过率掉了也不选。

## 论点二：控制结构

### 2.1 五层闭环

```text
第零层  状态快照层
        任务、依赖、资源、库存库位、空间拓扑、库容、积压、容器、业务、现场、可信度
          ↓
第一层  瓶颈识别与节拍层
        识别瓶颈（水平资源、垂直节点、工作站、库容、交叉口、窄巷道）
        输出瓶颈速率、投料配额
          ↓
第二层  准入判断层
        作业缓冲 × 库存缓冲 × 在制品上限 × 同步窗口 × 垂直队列 × 容器可用 × 信任可行
        输出授权集
          ↓
第三层  人机能力组合与协作层
        移动匹配 × 拣选匹配 × 同步可行 × 空间可达 × 协作模式
        输出可行的能力组合
          ↓
第四层  行程结构化释放层
        硬隔离过滤 + 行程收益评分 + 容器容量约束
        输出行程包与执行单元
          ↓
执行 → 反馈回写 → 回到第零层
```

### 2.2 第一层：瓶颈识别与节拍

每个决策周期重算各类资源、垂直节点、工作站、库容、交叉口、窄巷道的有效通过率，取最小者为瓶颈。释放节奏绑在瓶颈消耗速率上，不绑在上游资源空闲状态上。

**库容可以成为瓶颈**。库容饱和不会让任务不可执行，但会压低所有资源的有效通过率。占用率超过阈值且积压滞留时长上升时，该区域的有效上架能力和有效拣选能力按占用率打折。

**垂直节点是独立瓶颈候选**。楼层仓里，提升机、货梯、垂直输送机是共享的、有容量上限的、有排队时间的独立资源，高峰时段成为全局瓶颈是常态。

**交叉口和窄巷道也是瓶颈候选**。窄巷道容量不是宽度，是“同时只能一辆车”，按单服务台排队模型算。交叉口多方向汇合，容量有限，容易排队。

### 2.3 第二层：准入判断

回答“现在该不该放”，不是“能不能做”。七项条件全为真才准入：

```text
准入可行 = 作业缓冲可行 × 库存缓冲可行 × 在制品可行 × 同步窗口可行
         × 垂直队列可行 × 容器可用可行 × 信任可行
```

可行集回答“能做”，授权集回答“该放”。两个集合分开输出，不一致是正常的，不一致的原因就是第二层在起作用。

**定位转变**：容量阻塞、阻塞任务不是异常，是阀门正常工作的结果。把它们当异常看，现场会倾向于绕过限制继续投料，最后把系统推进高利用率、吞吐骤降的区间。

### 2.4 第三层：人机能力组合与协作

人机混合任务不能按“任务匹配单个资源”处理。拣选由人做、移动由机器人做，一个任务同时需要人的手和机器人的腿。拆成移动匹配、拣选匹配、同步可行、空间可达、硬约束五项，全为真才可执行。

同步可行判断的不是“人到了没有”或“机器人到了没有”，而是两者预计到达同一交接点的时间差是否落在允许窗口内。

协作策略是决策变量，不是全局配置。固定配对和自由浮动各有最优场景，逐周期、逐任务包选择。

### 2.5 第四层：行程结构化释放

释放单位从“一个任务给一个资源”改成“一个行程包给一组资源”。行程包里可以有移动任务和拣选任务的交错。分组规则是硬隔离过滤加收益评分：货主隔离、批次、权限、库存真实性一票否决；容器替代、区域邻近、窗口微差进入收益评分。

同一区域的上架任务和出库任务如果能配对进一个行程包，可以在一次行程里同时完成腾出空间和填入空间，压住库容的瞬时峰值。楼层仓里这个配对必须按层做，不能跨层。

### 2.6 评分排序的位置

评分只在授权集内排序，决定先放哪一个，不决定放多少。放多少由第一层配额定。

```text
评分 = α·时效紧迫度 + β·业务优先级 + γ·已等待时长 + δ·瓶颈贡献 + η·合并收益
     − ε·拥堵风险 − ζ·移动成本 − θ·同步风险 − ι·阻塞传播风险
```

## 论点三：空间与资源建模

### 3.1 空间拓扑

空间不只是一组容量数字，是图结构：

```text
拓扑 = ( 节点集合, 边集合, 节点容量, 边容量, 通行时间, 允许资源类型 )
```

节点包括库位、工作站、暂存区、交接点、交叉口、垂直节点口、楼层入口、月台。边分两类：水平边（同层通道）和垂直边（提升机、货梯、垂直输送机）。大平面仓没有垂直边，拓扑退化为平面图。

拓扑从仓库布局数据生成，不硬编码。布局变，拓扑重建。

### 3.2 单层面积与货架排布

面积决定拓扑的尺度和分区边界。大面积仓移动成本占比高，评分里移动成本权重更高；路网稀疏，拥堵传播范围大，通道占用阈值更保守；面积超过阈值时启用分区调度，每个区跑一套完整五层回路。

货架排布决定边的连接方式。背靠背货架加巷道，巷道是天然的空间聚类单位，行程包按巷道聚类；窄巷道是串行资源，容量为一，作为独立瓶颈候选；死胡同进出同一条通道，移动成本按往返算；交叉口是咽喉节点，有节点容量和排队模型。

### 3.3 楼层仓与大平面仓的差异

楼层仓在拓扑里多一类垂直边。这改变三处结构：瓶颈候选多一类垂直节点；移动成本从平面距离变成拓扑路径时间，垂直段有等待时间；准入判断多一道垂直队列约束。

跨层任务的能力需求从“移动匹配”变成“出发层水平移动 + 垂直节点通过 + 到达层水平移动”三段。执行单元必须同时满足楼层权限和垂直节点权限。

楼层承重是硬约束，不是软约束。超重不是降效，是安全事故。

### 3.4 容器容积

空间计量从“货物直接占空间”改成“货物先装进容器、容器再占空间”，中间多出装载率这个调度变量。

**容器数估算**：

```text
容器数 = max( ⌈ 体积 / (容器有效容积 × 目标装载率) ⌉ , ⌈ 重量 / 容器载重上限 ⌉ )
```

向上取整，0.6 托的货也占一个托盘位。

**空间占用**：

```text
占用空间 = 容器数 × 单容器占用空间(容器类型)
```

**行程包容量三重约束**：总重量不超过载重上限、容器数不超过载具位数量、容器总体积不超过载具容积。三个同时成立。载具位数量往往比容积更紧。

**装载率策略**：装满再走和凑单再走各有最优场景。截单前紧迫任务凑单快走，常规补货装满再走。装载率进入行程包收益评分。

**空容器回流**：占用移动资源、载具位、暂存区，但不产生货物通过量。瓶颈通过率计算要把空容器回流的工作量算进资源占用，不能算进货物通过量的分子。容器池水位作为状态变量监控，低于阈值时提升空容器回流优先级。

**库位适配按容器类型**：同一个库位，放标准托盘是一个，放小料箱可能是四个。库位容量要按容器类型记，货架层高也影响适配。

**积压记三个数**：货物实物量、容器数、占用空间。三个数分开记，因为它们变化不同步。滞留时长也要按容器维度看，空容器滞留和满载容器滞留是两类问题。

### 3.5 资源建模

人员字段：标识、技能、资质、区域、楼层权限、垂直节点权限、可用时间窗、最大并行任务数、同步协作能力、允许交接点、最大互等容忍时长、响应移动时间。

机器人字段：标识、类型、载重、载具位数量、载具容积、速度、电量、充电窗口、区域权限、楼层权限、垂直节点权限、同步协作能力、允许交接点、最大互等容忍时长、响应移动时间。

执行单元不等于单个资源。人机混合任务里，完整的执行单元是在允许时间窗内可同步协作的能力组合：一个拣选人员、一台移动机器人、一个允许交接的交接点，三者能在时间窗内交汇。执行单元的粒度跟着任务的能力需求走，不跟着资源台账走。

## 论点四：可靠性与数据

### 4.1 现场与系统差异

模型的所有判断建立在状态快照上，快照一旦与现场不一致，输出越精确，错得越系统。软件只能处理已被感知到的差异，消除不了差异产生的根源。差异的根源在流程设计、硬件缺失、激励错位、管理缺位。

软件能做的三件事：暴露差异不假装消除差异；在差异存在时保护控制回路；把差异变成管理输入。

### 4.2 可信度

每个关键状态字段增加三个元数据：更新时间、可信度、来源。

```text
可信度_f(t) = 初始可信度_f × exp( −(t − 最后更新) / 半衰期_f )
```

来源可靠性和时间衰减共同决定。不同字段半衰期不同，库存数量短、库位长。同一字段收到矛盾信号时可信度打折并标记待核验。

差异检测分三类：主动核验在关键节点强制确认；被动检测从执行反馈推断矛盾；交叉校验比对不同来源。检测输出不是直接改状态，而是降低相关字段可信度并生成核验任务。

### 4.3 三级降级

| 可信度状态 | 触发条件 | 控制回路行为 |
|---|---|---|
| 正常 | 关键字段可信度高于阈值 | 正常自动调度 |
| 保守 | 部分字段可信度低于阈值 | 受影响区域自动释放收紧，配额按保守值给 |
| 冻结 | 关键字段不可信或影响面大 | 受影响区域停止自动释放，生成核验任务 |

降级按区域、按字段生效，不搞全局。核验任务进入任务池，和正常任务一起消耗资源、一起计算瓶颈。

### 4.4 异常分级

| 级别 | 定义 | 产品表现 |
|---|---|---|
| 一级：自动消化 | 有确定恢复路径，影响局限 | 不弹告警，只留痕 |
| 二级：状态标记 | 改变可用状态但不影响当前动作 | 地图和列表打状态标签 |
| 三级：处置任务 | 必须人工动作才能恢复 | 生成处置卡，带SLA倒计时 |
| 四级：熔断升级 | 影响面大或涉及安全 | 全局熔断横幅，停止自动释放，通知上级 |

判级依据：影响控制回路哪一层、是否影响安全、是否有自动恢复路径、影响范围多大。级别不写死，随上下文变化。

### 4.5 降级模式

每个控制服务定义明确的降级行为：瓶颈与配额服务失效时沿用上一周期配额并逐周期递减；准入服务超时只放行缓冲远低于阈值的任务；求解器超时用快速启发式结果并标注未精化；状态快照滞后冻结受影响区域自动释放。

降级期间操作限制同步调整，手动放行配额收紧、禁止批量改派。降级恢复后进入观察期，配额逐步恢复，由调度主管确认关闭。

## 公式体系

### 状态与目标

```text
状态向量  X_t = { 任务, 依赖, 资源, 库存, 空间缓冲, 库容, 积压, 瓶颈, 拓扑, 可信度 }
状态更新  X_(t+1) = 更新( X_t, 本轮决策, 执行事件 )
```

字典序目标：先最大化瓶颈通过率，再最小化在制品、同步损失、拥堵、积压滞留，最后处理移动与改派成本。

### 瓶颈与配额

```text
名义通过率   r_i = 可用容量_i × 效率系数_i / 平均标准工作量_i
库容折减     φ_z = 1 − λ × max(0, 库容占用率_z − θ_k) / (1 − θ_k)
垂直折减     ψ_k = 1 − max(0, 队列_k / 队列上限_k − θ_v) / (1 − θ_v)
有效通过率   r'_i = r_i × φ_所属区域 × ψ_相关垂直节点
瓶颈识别     R_t = min over 全部候选  r'_i
投料配额     Q_t = max( 0, R_t × Δt + κ × (缓冲目标 − 缓冲当前) )
```

### 准入判断

```text
准入可行 = 作业缓冲可行 × 库存缓冲可行 × 在制品可行 × 同步窗口可行
         × 垂直队列可行 × 容器可用可行 × 信任可行
作业缓冲   占用_s + 任务占用_s ≤ 容量_s
库存缓冲   占用_z + 任务占用_z ≤ 安全利用率 × 区域容量_z
在制品     当前在制品_z + 任务标准工作量 ≤ 在制品上限_z
同步窗口   |移动预计到达 − 拣选预计到达| ≤ 互等容忍时长
垂直队列   队列_k + 1 ≤ 队列上限_k 且 预计等待_k ≤ 垂直等待容忍
容器可用   容器池可用量 ≥ 所需容器数
信任可行   涉及关键字段可信度 ≥ 信任阈值
授权集     可行集中准入可行且累计工作量不超过 Q_t 的任务
```

### 可执行性与空间可达

```text
空间可达 = 楼层权限包含来源和目标楼层 × 垂直节点权限包含所需节点（跨层时）
         × 路径存在且所有边允许该资源通行
任务可执行 = 移动匹配 × 拣选匹配 × 同步可行 × 空间可达 × 硬约束
```

### 容器与空间

```text
容器数     = max( ⌈体积 / (容器有效容积 × 目标装载率)⌉ , ⌈重量 / 容器载重上限⌉ )
空间占用   = 容器数 × 单容器占用空间(容器类型)
库位剩余   = 该库位可容纳的当前容器类型数量 − 已占用数量
装载率     = 总体积 / (总容器数 × 容器有效容积)
装载收益   = 货物量 / (容器数 × 单容器容积) − 装载率基准
```

### 移动成本

```text
移动时间_i = Σ 路径边 ( 边长度 / 资源速度 + 边排队等待 )
```

死胡同往返计两次，窄巷道按串行排队算。

### 行程包与分组

```text
收益(B) = 移动节省 + 同步节省 + 换型节省 − 额外等待 − 空间峰值增量
可行(B) = 硬隔离成立 且 容量三重约束满足 且 收益(B) > 0
```

### 协作模式

```text
固定配对成本 = 配对切换时间 + 同步等待期望 + 资源闲置期望
自由浮动成本 = 动态重组开销 + 交接次数 × 单次交接成本 + 同步等待期望
选择成本较低的模式
```

### 评分排序

```text
评分 = α·时效紧迫度 + β·业务优先级 + γ·已等待时长 + δ·瓶颈贡献 + η·合并收益
     − ε·拥堵风险 − ζ·移动成本 − θ·同步风险 − ι·阻塞传播风险
```

### 库容与积压更新

```text
库容更新  占用_z(t+1) = 占用_z(t) + 上架占用 − 出库释放 + 逆向占用
积压更新  积压_y(t+1) = 积压_y(t) + 新增_y − 消化_y
```

### 可信度与降级

```text
可信度衰减  可信度_f(t) = 初始可信度_f × exp( −(t − 最后更新) / 半衰期_f )
降级配额    保守配额 = 配额 × 降级系数
```

### 反馈校准

```text
同步等待时长 = 实际交接完成时间 − 双方到位时间差的期望
垂直等待偏差 = 实际垂直等待 − 预计垂直等待
时长偏差     = 实际作业时长 − 模型估计时长
```

## 产品交互

### 按角色分界面

| 角色 | 使用节奏 | 主界面 |
|---|---|---|
| 调度主管 | 每班次、每时段 | 瓶颈与流量控制台 |
| 现场主管 | 实时、每十几分钟 | 准入干预台与异常地图 |
| 作业员与运维 | 实时、逐任务 | 行程包执行视图 |
| 计划与改善 | 每日、每周 | 复盘与校准视图 |
| 管理层 | 每周、每月 | 吞吐量趋势视图 |

所有视图共享同一套决策留痕。任何一个视图里看到的“挡住”或“放行”，点进去都能落到同一条决策记录上。

### 核心控制台

瓶颈区放最上方，用横向水位条表达各区域有效通过率，最短的标为当前瓶颈。配额水位用双色条显示已释放、剩余、缓冲回补和收紧量。积压用热力图加滞留时长长尾，每个积压块旁边给趋势箭头和一句人话。

### 准入干预台

被挡任务按原因分组，不按时间排。每个任务展开是决策理由链，从最终判断倒推到状态事实，最后给动作建议。手动放行带越权标记和班次配额限制，超出配额需二次确认。

### 行程包执行视图

时间线加小地图，列出先到哪个点、做什么、再到哪个交接点、和谁交接。交接点标出人机双方预计到达时间，时间差在容忍内显示绿色，接近上限显示黄色。交接动作一步一确认，同步等待时长准确回写。

### 复盘与校准

决策留痕做成可检索时间轴，支持按区域、任务类型、挡住原因、操作人检索。参数配置带影响预览，调整不直接生效，先在回放数据上跑一遍对比。吞吐量趋势按三个口径分列，标注瓶颈迁移时间点。

### 异常与差异

异常分四级，一级不弹告警只留痕，二级打状态标签，三级生成处置卡，四级全局熔断。异常条目统一用状态、影响、原因链、动作、SLA五要素表达，挂在异常地图、时间线、队列三个入口上。差异视图和异常视图分开，差异要核验，异常要处置。核验任务进入任务池，在行程包视图里和正常任务一起显示。

## 实施边界

模型已定义结构和参数类别，以下参数必须通过仿真或现场日志校准，不能把演示值当通用结论：

- 任务到达过程与作业时长分布；
- 各类资源标准工作量换算系数；
- 瓶颈识别窗口与重算频率；
- 区域在制品上限、缓冲红黄绿阈值；
- 库容占用率瓶颈折减阈值与折减曲线；
- 积压滞留时长预警阈值；
- 同步窗口容差、最大互等容忍时长；
- 评分权重与字典序次级权重；
- 行程包收益评分参数、装载率基准；
- 重调度最小间隔与重试次数；
- 可信度半衰期与信任阈值。

在制品上限、缓冲阈值、库容折减阈值对吞吐影响最大，建议先用保守值跑仿真，再逐步收紧。评分权重影响通常比现场直觉小，不值得花太多时间手调。

软件不能消除现场与系统的差异，只能让差异不再隐形。模型的目标不是保证快照等于现实，而是在快照可能不等于现实时，仍然做出可控的决策，并把差异交还给该处理它的人和流程。

## 一页式总结

**一句话**：本模型以瓶颈通过率为唯一主控目标，以五层闭环为控制结构，以空间拓扑、楼层、货架、容器和人机能力组合为建模基础，以可信度和降级为可靠性保障，在有限空间资源约束下最大化单位时间流过的标准工作量。

**四个支撑论点**：

1. **目标**：瓶颈通过率控制，系统吞吐量验证，任务吞吐率反馈；货物与容器双口径；目标函数字典序。
2. **结构**：五层闭环，第一层瓶颈节拍定投料，第二层准入控过载，第三层人机能力组合解同步，第四层行程包回收移动产能。
3. **建模**：空间是拓扑图不是容量数字，楼层加垂直边，货架排布决定聚类单位和咽喉节点，容器容积引入装载率和双重计量，人机混合拆为能力组合加同步加协作策略。
4. **可靠性**：状态维护可信度，差异检测分主动被动交叉校验，三级降级按区域生效，异常分四级，核验任务进调度池，差异转管理输入。

**四个论点间的关系**：目标决定结构，结构决定建模粒度，建模粒度决定输入输出和可靠性设计。
